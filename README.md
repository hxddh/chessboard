# 国际象棋 Chessboard

国际象棋 — Native SDK WebView + Canvas，支持 macOS 与 Windows。**GPLv3**（为后续集成 Stockfish 引擎预留）。

复用 [goban](https://github.com/hxddh/goban)（五子棋）打磨出的整套架构：Native 壳、Canvas 渲染、
侧栏/复盘/主题 UI、双平台 CI、无头浏览器回归测试。

## 7.5.0 改了什么

**发布门禁里终于有一步跑在真壳上。** 6.0 到 7.3 的引擎停摆能漏出去，是因为 CI 只跑 Chromium / WebKit，从来没有启动过打包好的应用。现在 `build-macos` 与 `build-windows` 在打包之后、上传之前，用 `CHESS_SELFTEST=1` 启动刚打好的应用：页面按原样启动 Stockfish、对初始局面要一步棋，原生壳把结果写出来再按成败退出，拿不到一步合法的棋就不上传、不发布。先红后绿：把 CSP 换回 7.3 的样子，两个平台都红，报的正是 `CompileError`；换回来以后两个平台都绿，真壳里引擎第一次应着 macOS 约 2.1 秒、Windows 约 2.3 秒。

**要引擎的六个功能有了真引擎测试。** 新增 `test-engine-flows-e2e`：人机与提示、失着提醒、分析与精析、持续分析、棋谱库、教学对练，接的都是真 Stockfish，在两套浏览器引擎上都跑，也进了发布门禁。它第一次在 WebKit 上跑就抓到一个 macOS 上的真缺陷：棋谱库里填完名字直接点「分析」，那一下点击会丢。已修。

**开局名按「族」本地化。** 开局书只译了约 195 条线，其余局面在中文、日文界面里整条显示英文。现在开局表里全部 149 个族都有中日译名，查不到整条译名时显示「西西里防御：Bowdler Attack」这样的半译名，测试守着「表里每个族都有译名」。

**五处小修。** 失着提醒从「成功」样式改成警示样式，停留 4.2 秒（原来 2.2 秒，不够看完再决定要不要悔棋）。引擎起不来时点「新局」会顺带重试一次，再失败也只在横幅里说一次。导入大 PGN 时逐局解析、每 16 毫秒让出一次界面，切分 8000 局从 9.4 秒降到 0.19 秒。棋谱库的「分析剩下的 N 局」写出预计时长，中途关掉再打开能从断点接着分析，这一条现在有测试守着。`manifest-check` 要求 README 有当前版本这一节。

计划、依据与落地记录见 [docs/v7-5-plan.md](docs/v7-5-plan.md)。界面键 914 → 917。

## 7.4.0 改了什么

**引擎终于在应用里起得来了。** 6.0 给页面加的 CSP 缺 `'wasm-unsafe-eval'`，WebView2 与 WKWebView 因此都拒绝编译 Stockfish 的 wasm。从 6.0 到 7.3.0，人机对局、提示、复盘分析、棋谱库分析都起不来，界面停在「引擎思考中…」，一句话也不说。这个问题一直没被发现，是因为所有浏览器测试都把引擎换成了空桩。现在：CSP 放行 wasm 编译（只放行这一项，不放行 `eval()`）；新增 `test-engine-e2e`，真去启动引擎，在 CI 的 Chromium / WebKit 两套引擎上都跑，也进了发布门禁，而且先红后绿，两套引擎上都实测过；引擎万一起不来，顶栏会说明原因，一条常驻横幅提供「重试 / 复制诊断信息」，不再自己反复重启。

**七条数据接缝。** 导入新局以后，棋谱库列表点 A 局打开的曾经是 C 局，「再深一遍」也改写 C 局；现在按 id，不按下标。开局书：一着非法不再让整份文件被拒；长线替换短线不再误报「上限」；两万条线的导入从约 90 秒降到约 60 毫秒；清空或替换开局书之后，屏幕上那道题不再写进复习队列；导出学习数据时带上开局书本身。库分析被打断时，不再用有空洞的结果覆盖原来的好数据。「接实战」会先问一声再清掉没下完的对局。

**用户真能拖出来的窗口，都有布局。** 7.3 的竖窗修法漏了近方窗口：540×543 上面板一开，棋盘只剩 210px。现在 820px 以下的窗口，面板开合棋盘都不变大小、也不小于 260px（新测试覆盖 271 个可达尺寸）。窄窗顶栏不再重叠。做题页的面板退回原宽度，「今天的训练」卡片按步骤名 / 说明分两行排，做题页重复的「答案」按钮去掉一个。

README 只留最近两版，更早的移进 [docs/CHANGELOG.md](docs/CHANGELOG.md)，补写了发布时漏掉的 7.1.1 与 7.2.0。计划、依据与落地记录见 [docs/v7-4-plan.md](docs/v7-4-plan.md)。界面键 910 → 914。

更早版本的说明见 [docs/CHANGELOG.md](docs/CHANGELOG.md)。

## 规则引擎

局面合法性由 vendored [chess.js](https://github.com/jhlywa/chess.js) 0.13.4（BSD-2-Clause）判定——
不自研规则。`src/web/js/chess.js` 顶部注明了从 ESM 到经典脚本的机械转换（zero:// 方案下 WebView
只验证过经典脚本加载）。

chess.js 之上,`js/fide.js` 补齐它不做的比赛规则判定：三次重复与 50 回合是**可声明**和棋（art.
9.2/9.3）而非自动结束,五次重复 / 75 回合才自动判和（art. 9.6）；超时是否算输由「能否将杀」而非
子力数量决定（art. 6.9）。复盘分析对每个局面用的是**同一套判定**而不是 chess.js 的 `game_over()` ——
后者在三次重复和 50 回合就返回 true，照它记分会把还能继续的局面一律记 0，把局势曲线拉到轴上，
并且带偏其后每一步的失误分类与准确率。重复计数比较的是**可走着法**而不是 FEN —— FEN 只要有兵走两格就写上吃
过路兵格,哪怕没有兵能吃,直接比字符串会把同一个局面算成两个（`1.e4 e5 2.Nf3 Nf6 3.Ng1 Ng8
4.Nf3 Nf6 5.Ng1 Ng8` 就会漏判）,因此只有真正存在合法吃过路兵时才保留该权利。

## 对弈引擎

[Stockfish.js](https://github.com/nmrugg/stockfish.js) 19 lite-single（GPLv3，单线程 + lite NNUE，
wasm 1.79 MB），vendored 于 `third_party/stockfish/`。zero:// 方案不能加载 worker 脚本也不能 fetch 打包
文件，因此构建时由 `scripts/gen-engine-src.mjs` 把 loader 文本与 wasm base64 生成为
`engine-src.js` 全局量，运行时 `engine.js` 用 Blob worker + `postMessage` 传 wasm 启动引擎——
全程零 URL 解析。页面 CSP 的 `script-src` 带 `'wasm-unsafe-eval'`：blob worker 继承这份策略，没有它 WebView2 与 WKWebView 都拒绝编译 wasm（6.0–7.3 引擎因此一直起不来，7.4 修复，由 `test-engine-e2e` 守着）。难度用 UCI `UCI_LimitStrength/UCI_Elo`（1320–3190）限强，「极限」为满强度；
「新手」和「休闲」不靠 UCI 选项：Stockfish 的 `UCI_Elo` 下限是 1320，比真正的初学者高得多，
而实测 Skill Level 1 仍有约 27 ACPL（与入门档无异）。所以这两档改为**浅层 MultiPV 搜索 + 候选抽样**
（会主动取差着，但绝不放弃已算出的杀棋），靠 `worstBias` 调档：新手 0.2、休闲 0.15 且候选更少。

强度不用 ACPL 背书 —— ACPL 说不清「初学者赢不赢得了」。`scripts/test-novice.mjs` 直接对下：
一个只会「不一步送子」的随机机器人，100 盘对新手得分率 **59%**、对休闲 **29%**、对入门（1320）几乎为零（5 轮 × 20 盘；一场 20 盘的样本标准差分别是 7.7 和 10.1）。
（这三个数与下面各档的平均失分都来自 [`docs/measured.json`](docs/measured.json)，由
`node scripts/test-novice.mjs --record` / `test-strength.mjs --record` 写入；单测校验本文与
`engine.js` 的注释引用的是同一份数,不是各自记着的一份。1.25 之前正是各记各的：
README 记 56%/27%（32 盘），engine.js 注释记 66%/25% 且没写盘数。7.1.1 又补了一层：这三个数从 7.0 换引擎起就是 Stockfish 18 时代的，换成 SF19 之后没有人重测，而单测只比对「本文和 engine.js 是否一致」，两边一起过期它就一起放过。现在测量本身带着实测标准差，`test-novice.mjs` 的判定区间必须等于记录里的均值 ±3σ，单测校验这一条 —— 重测过却没改区间，会当场红。）
1.18 之前新手档 `worstBias` 是 0.6（六成的着法是十个候选里最差的那个），同一个机器人打出 **81%** ——
那不叫弱，叫自己送；而它上面一格就是 1320，没有中间地带。`scripts/test-strength.mjs` 另按满强度评估
量每档的平均失分。抽样走固定种子，但参照评估是按时间搜的，所以**它逐位复现不了**——
断言因此写成带容差的「档位之间不许实质倒挂」加各档绝对上下限，而不是两个噪声均值之比。

测试：
- `node scripts/test-chess.mjs` —— 规则/课程/题库/开局/成就/纯函数模块（快,打包流程内置）
- `node scripts/bundle.mjs --check` —— **模块图解不解得开**（test-chess 内置）。1.25 之前这条规则由 `scripts/scope-check.mjs` 承担:它扫出「被读取但在任何作用域里都没有绑定」的标识符,因为那时 28 个文件都挂在 `window` 上,加载次序就是依赖图,而这份契约只写在 index.html 的 `<script>` 顺序里。1.12 把 `CHECK` 留成自由变量,`draw()` 在画棋子之前抛出,每次将军棋盘上一个子都没有,这样发了两个版本。现在源码是 ES 模块、产物是一个经典脚本,解不开的名字直接是构建失败 —— 同一条规则,由发布产物本身来执行
- `node scripts/test-board-e2e.mjs` —— 真下到将军与将死,四套主题各数一遍棋子;引擎给不出着法时这局能不能接着走;以及**棋盘画出来的是不是这盘棋** —— 逐格取一张 8×8 的墨迹掩码(与该格四角相差够远的像素),掩码只认形状,所以同一种子在深浅两格上读出来是同一串,再配一个「很亮/很暗」的比值把黑子白子分开(实测同型异格差 0–3 位、异型差 8–14 位、白子比值 50–204 对黑子 0–39)。据此量:开局三十二个子各就各位、选中之后亮起来的正是这枚子能去的格、上一手只标那两格、吃子之后落点上换成了吃子方那一枚、将军只有王那一格底色变、翻转是真的镜像(按屏幕位置读,不按格名读——只把坐标标签翻过来的坏翻转,按格名读全对)、拖到半路棋子真的离开了原格。三处注入验证过:去掉上一手着色、去掉翻转镜像、少画一个可走点,各自都红。**另有用键盘下棋的一节**(方向键移光标、回车选中与落子、Esc 取消、Home/End,以及 `#board-live` 每一步说了什么给读屏软件——键盘走出来的棋在画布上和手走的必须是同一回事),和**局面编辑器的一节**(空棋盘上说得出缺什么、按不动「开始对局」、拖着刷是一笔四个兵、三个出口各自收尾)（需 playwright + Chromium,没有就跳过）
- `node scripts/test-audio-e2e.mjs` —— **哪一件事发出哪一种声音**（在真页面上探 Web Audio:每个 `createOscillator` / `createBufferSource` 记下它拿到的频率,再按频率还原成「拿起 / 落子 / 吃子 / 将军 / 王车易位 / 升变 / 拒绝 / 胜利 / 失败 / 和棋」。此前所有浏览器套件都把 `soundOn` 关着开页面 —— 一个会响的测试很烦人,静音是最省事的办法 —— 于是整条音频路径从来没有被执行过:分胜负的那张表没有,一步棋听起来是什么样没有,连开关本身也没有。按频率而不是按调用栈认声音,是因为发布流水线在 WebKit 上也跑一遍,而没人在这台机器上验得了 WebKit 的栈格式。需 playwright,没有就跳过）
