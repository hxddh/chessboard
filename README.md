# 国际象棋 Chessboard

国际象棋 — Native SDK WebView + Canvas，支持 macOS 与 Windows。**GPLv3**（为后续集成 Stockfish 引擎预留）。

复用 [goban](https://github.com/hxddh/goban)（五子棋）打磨出的整套架构：Native 壳、Canvas 渲染、
侧栏/复盘/主题 UI、双平台 CI、无头浏览器回归测试。

## 7.1.0 改了什么

**7.0 造了一条数据管线，它的产出只流向一张点不动的统计页。这一版不采集新数据，只接线。** 计划与逐条理由在 `docs/v7-1-plan.md`，落地记录（做到的和没做到的都逐条）在该文件 §7。

- **点得开那一局棋了。** 7.0 把每一局的着法和整趟分析都存了下来，然后没有任何一个界面能打开它：库是一个计数器加一张统计页，而统计页是条死路。现在记录页多一个「全部 N 局」——日期、对手、结果、**我这局的精准度**、几处失误、开局，按结果与执子筛选，按最近导入或「我下得最差」排序；点一局，棋盘上就是那一局，**存好的分析跟着一起过来**，`?` 和 `??` 当场就在走子列表上，**引擎一次都不跑**。
- **诊断的每一行都是一扇门。** 点「栽在哪些战术上」的某一行，筛出被这个母题打中的那些局；点开局那一行、点「失误最密集的是第 N 回合」，同理。v7-plan §6.2 自己写过验收——「每一条都必须点到一个可执行的下一步；没有下一步的统计不写进这一页」——7.0 一条都没做到。
- **诊断页画出来了**：分阶段每手厘兵（最弱那根用判级红）、失误按回合的分布（是个尖还是个坡——时间恐慌和知识缺口在这里长得完全不同）、按开局的胜和负。画不出来的图**不存在**，而不是一张空画布。
- **§6.3 补上：库里的失误进错题本。** 7.0 的 `addMines` 全仓库只有两处调用，都在棋盘那条路上，`runLibraryPass` 一次也没调过——库认出了几百局棋里的每一个 `??`、连引擎该走哪一手都算好存下来了，全部停在统计里。现在每分析完一局就走**和棋盘同一套规则**收进错题本，淘汰策略加一层**按母题分层保留**：每个母题的最近 6 道先于任何人被豁免，否则一次两百道的导入（一批、一个时间戳）会沿着「最旧先退」把你正在练的每一类整类冲掉。上限 50 → 90。
- **教练看得见你在别处下的棋。** 「今天下过棋」以前只读本机战绩，于是一个刚把今早快棋导进来的人还被劝「来一盘」；题库战绩一片空白时，弱项现在从**你自己的棋**里读（诊断的母题榜，和诊断页同一个二十局门槛）；日课多一步「分析棋谱库里还没分析的 N 局」；进步页的准确率走势把库里的棋按对局日期并进同一条轴。
- **7.0 复查查出的四个缺陷，全部修掉。** ①每手厘兵没有钳制到 ±1000——6.1 在棋盘上修过的事，棋谱库抄漏了：一步报杀、下一步只报大优，两个标量差着九千多，照直相减就把「尺子能表达的最大失误」记到一个没做错的人头上。实跑：20 局里 6 局的残局各有一手报杀，残局 ACPL 从 30 变成 413，「该练哪一段」从「没有」变成「残局」，而这个人三个阶段下得一模一样。②`foldGame` 完全没读 `[SetUp]` 局的起始 FEN，于是**玩家自己的每一手都记到了对手账上**，一个从第 30 手开始的局面整个归进开局。③`mistakes.js` 里同一个钳制缺陷的第三处，一手放掉杀棋的错题显示「亏了 99.5」。④**没有任何一处给条目写过 `eco`**，所以「开局战绩」那一段从来没渲染过一次——e2e 当初是把 `eco` 手工塞进种子数据的，所以测试过了而应用什么都不产出。三份各自为政的算式收成一份 `plyLosses()`。⑤顺带修掉一个**每个版本都有**的老缺陷：`[FEN]` 局的手数不从那个局面的全手数起算，交到你手上的第 30 手被列成第 1 手——`[SetUp]` 棋谱一次只来一局时没人撞见，库一口气开出几十局就立刻显形。
- **§6.4 的验收补测了**：`scripts/test-motif.mjs` 在 28 局 1320 半着的语料上量出「能给出母题解释的失误比例」——判为 `?` 或 `??` 的 88 手里，**22.7% 的失误**给得出解释（只看 `??` 是 14/47），给出来的是牵制 9、捉双 8、串击 3。**只量了覆盖率**：正确性没有人工抽样核对过，`motif.js` 只认五个母题、只在几何事实确凿时开口、不确定就闭嘴，那是构造上的论证不是一次抽样——所以这个数的读法是「有多经常有话说」，不是「说得有多对」。这句话和数字一起记着。
- **发布门禁从两个半小时回到半小时左右**：题库门禁在 PR 和发布上跑**固定抽样 150 道**（约五分半，同一个洗牌顺序，不会自己变），全量挪到新的 nightly。抽样从此**会因为答案更差而失败**——以前抽样跑完只打印然后退 0，当门禁一文不值。代价写在 workflow 注释里没有藏。
- **`docs/v7-plan.md` §10 那两张表本身的洞也补记了**（§11.6）：§6.3 两张表里都不存在，§6.4 打了勾但验收没做，§6.2 的「按开局战绩」记在做到了而代码里是死的。三条的成因是同一个——把「算得对」和「有人把数据喂进来」当成了一件事。界面键 848 → 873。

## 7.0.0 改了什么

**一个大版本四件事一起做完：修掉复查查出的缺陷、升级底层依赖、用起新 SDK 的能力、上线棋谱库。** 计划与逐条理由在 `docs/v7-plan.md`，**做到了什么、没做到什么、哪些改动一次也没在真机上跑过**，逐条写在该文件 §10。

- **棋谱库（这一版的主线）**。`mistakes.js` 从 5.1 起就在说「任何现成题库都给不了的那一种内容，是这个玩家真正输掉的那些棋」——而这个闭环此前只对在这个窗口里下的棋成立，对任何在线上下棋的人来说那是他真实棋量的一个舍入误差。现在：一个 PGN 文件里**有多少局就收多少局**（不再让你从里面挑一局）；逐局离线分析，可暂停可续，切到后台时一条**带固定 id、会被替换而不是堆起来**的通知报进度；**二十局起给诊断**——战绩、精准度、分阶段 ACPL 与失误率、该练哪一段、失误最密集的回合、栽在哪些战术母题上、按开局的得分率。认领谁是「你」靠你填的名字，**认不出来就不认**：每个数字都是从一把椅子上读的，这里猜一下会安静地污染后面全部结论。母题取的是**引擎在你走错那一步之前的自己那一手**，不是你走的那一手——失着本身通常没有母题，惩罚它的那一手才有。
- **丢档：注释里的 `}` 会让文件再也打不开**（6.1 自己引入的）。6.1 把私有转义写成 `\}`——一个字面右花括号加「请别当成结束」的约定，读的时候必须在那个花括号上猜。没有规则能对自己的文件和外部文件同时猜对，而 6.1 的启发式把自己的猜错了：注释里出现 `}` 再出现 `{`，不是静默截断就是整份文件解析失败。**存档槽位存的就是 PGN 文本**，所以那是永久丢档。7.0 取消了这个决策点：导出把花括号写成 `\R`，序列化后的注释体里一个字面 `}` 都没有，导入就按标准扫描；旧档走一层文档级回退。
- **题库：11% 的题会把下对的人判错**。`tac` / `win` 按 SAN 精确匹配判，而其他每一类都反对这么做且写清了理由。判题侧现在接受同等好的第一手，题库也过了一遍深度 18 的门禁——**而这道门禁本身错了两遍，错的都不是棋、是测量**。第一遍按「是不是引擎第一选择」判，按名次不按差距，一厘兵之差和 262 厘兵之差被一视同仁地退役。第二遍改成量差距，两轮仍然对不上，复核报出九万多厘兵的差距（那是杀棋分：这一轮看见强制杀、上一轮没看见，同一局面同样深度）——根因是**脚本从来没在题与题之间清空置换表**，每道题继承前面所有题留下的哈希，于是 `go depth 18` 的结果取决于它前面搜过什么。补上 `ucinewgame` 后同一份样本连跑两轮逐条一致，题库随即恢复到未删减的 1023 重判（**一次删除的可信度不会高于它背后那次测量**）。第一个可复现的结果：退役 **21** 道（最小差 61 厘兵，六道是引擎有强制杀而存的答案够不到）、记下 27 道同等解、**id 一个都没改写**；独立复核 `确实更差 0 · 未记下的同等解 0`，门禁通过。题量 1023 → 1002。
- **八个随应用发布的局面是非法的，而换引擎把它们从瑕疵变成了崩溃**。追「噪声重测跑不完」追出来的：`position fen k7/8/8/8/8/2PPP3/2PNP3/K1PPP3 w` 让 Stockfish 19 抛 `RuntimeError: unreachable` —— 那是「马被自家兵团团围住」那一课的图，包围圈画在 c1–e3，**三个白兵站在第一横线上**。兵永远不可能在自己的底线；chess.js 照收，SF18 照算，于是它上线了十一个版本。SF19 **abort 整个 wasm 模块**，而 abort 之后每一次调用都撞同一个陷阱，6.1 那套引擎自愈也救不回来 —— 零基础学员点开这一课，引擎就死了。把内容喂进仓库自己早就有的守卫（`ChessEditor.validate`）一共揪出八个（兵在底线、没有白王、轮到白方走而黑王已被将着），**实测 SF19 八个全都 abort**。全部改掉，改完 Stockfish 自己确认每一道的解都是它的首选。1284 个局面（课程、手写题、挖掘题）现在全部要过那道守卫 —— 它早就存在，只是从来没有对准过自己的内容。
- **Glicko 的 `rd` 终于会随时间松动**。`rating.js` 文件头承诺的那件事从没接上线。补之前先量了一件事：**不能只靠反复跑 Glicko-2 的空评分期**——σ=0.06 之下跑满一年也只从 61 到 96.8。改用 Glicko-1 的停赛规则，标定成「一年回到 350」。效果：闲置三个月后连答五题，评级移动 **464 分 vs 不衰减的 98 分**。
- **`?!` 默认不再显示**，**白方第一手开始走钟**（此前 `clockRunning()` 系在「走完一手」上，白方整个第一手不走钟还白拿一次 Fischer 加秒）。
- **Stockfish 18 → 19 lite-single**：wasm **7.30 → 1.79 MB**，启动 280 → 109 毫秒；代价是 nps −34%。换引擎顺带揪出一条本来就错的书线（B06 末手把 −19cp 送成 +151，SF18 只报 +108 刚好躲过门槛），没有为它放宽门槛而是改了线路。**快扫预算 120 → 200 毫秒**：三轮独立重测、按轮配对读，`?` 与 `??` 的两遍重合率三轮全部改善（`?` 60→73 / 64→73 / 58→64），而 `?` 正是玩家会盯着某一手去改的那个标注。精析仍是 400 毫秒。顺带两条如实记下：这个测量脚本**自换引擎以来一次也没跑完过**（它后半段要走过全部课程与题库局面，正撞上那八个非法局面），以及 **SF19 在同样毫秒预算下比 18 更吵**（中位抖动 8→9 厘兵、九分位 33→42）。**SDK 0.8.1 → 0.10.1、Node 22 → 24**，手抄分叉落后了两轮：`manifest-check --sdk` 抓到六个结构体字段与三个系统库，CI 的链接一步又抓到三个 macOS 框架，守卫随即补到第三张面孔。
- **CI 的洞**：6.1 修掉了 static 作业手写脚本名的问题，然后把同样的手写清单留在 e2e 作业和 release 的 e2e 循环里。现在有一条断言把 `package.json` 的清单和两个 workflow 对起来。界面键 807 → 848。

## 6.1.0 改了什么

**一个补丁版本一件事：把 6.0 发布后复查查出来的每一条都修掉，并让账本上的每一个勾都有一条会失败的断言撑着。** 复查方法与逐条清单写在 `docs/v6-plan.md` §8，施工账本是 `docs/v6-1-plan.md`。

- **丢档的四条路径**（原生镜像是 6.0 的主打功能之一）。启动先写后读，`recover()` 的桥读还在飞时镜像定时器已经架起来了：localStorage 被清、文件完好——正是这个功能存在的理由——读慢于 400 毫秒就会让空档先写进文件并盖上更新的时间戳，然后「恢复」自己刚写坏的东西。现在镜像在 `recover()` 落定前只记待办。恢复之后到 reload 之间冻结一切写入（否则 `beforeunload` 的自动保存会把刚恢复的档覆盖掉）。`restoreAll()` 逐个检查写入返回值。`.bak` 从只写变成可读：主文件缺失或零长度时回退到它，重命名前 fsync，临时文件名按写次唯一。零长度文件不再等同于「没有文件」，解析不了的文件不再静默略过。
- **引擎自愈实际上一次也愈不了**。`init()` 交出 wasm 后把 base64 置空，之后任何一次 teardown 再 `init()` 都抛 `engine sources missing`，而刻意留着「给重建用」的解码结果在抛错那行之后。两次罢工也凑不齐——每次搜索前的 `isready` 排空会把罢工数清零。另外三条：teardown 不结算在飞的等待（无限分析期间一次 teardown 让搜索队列永久卡死）、残留定时器会朝新 worker 记罢工、持续分析的 `stop()` 会截断别人的搜索且结果按请求预算入缓存。六条各有一段测试，假 Worker 加手推的虚拟时钟，不需要引擎也不需要浏览器。
- **PGN 进出十条**。`0-0+` 让整个文件解析失败；空着 `--` / `Z0` 连 `splitGames` 一起炸，多局文件里好的那局也取不出；**变着里重复主线着法会把主线偷走**，静默、往返稳定、存盘后永久；无 `[Result]` 头的棋局导出丢结果；序列化会吐出超 80 列的行；注释里的 `}` 被改写成 `]`；无着变着里的注释漏到下一个主线着法；`e.p.` 与图形化 SAN 致命。另外 `[FEN]` 导入现在按头部原文校验——此前多出来的王会在校验看到之前被 chess.js 吃掉，应用载入的是一个与文件里不同的局面。
- **复盘的两处刻度**。判语档位 90 / 75 是照厘兵曲线读的，而 6.0 把输入换成了胜率精准度（整体高 10 到 17 点），每个人被高看一档；新档位取胜率曲线上同样的棋所在的位置。杀棋分数与厘兵之间的跳变不再被钳成满额漏着记进 ACPL——赢定的残局里快扫时有时无地报杀，以前会被记成两个大漏着。
- **评级改成量出来的**。6.0 的 958 道题只落在 10 个值上（300 道整整 1200，358 道整整 1400），因为公式是「类别基数加常数」——编码的是类别不是难度，「按棋力出题」实际等于「按类别出题」。现在用固定节点预算的阶梯加首选次优分差，两个都确定、都可复现。重标定后题量 958 → 1023，九个评级段里八个补到 §5 要求的 50 题（2200–2399 段 27 题，低水平自弈天生产不出那么多难局面，按实际钉住并写明未达）。
- **首屏**。`bundle.js` 1.68 MB 同步加载，其中 ECO 表 462 KB 只为棋局旁边那行开局名。抽出 `chunk.js`（`engine.js` 早就有这招，只是没人复用），ECO 按需注入，主包降到 1382 KB。
- **CI 的一个洞**：`checks.yml` 的 static 作业手写了三个脚本名而 `npm run test:static` 列了八个，`test-pgn` / `test-learning` / `test-eco` / `test-review-winpct` **从来没有在 PR CI 里跑过**，`test-classics` 写完后没接进任何地方。两个工作流都改成跑那个脚本。`test-mines` 补七条区间断言。
- **复盘噪声重测**。语料从 4 局 168 手扩到 28 局约 1300 手——6.0 公布的「`?!` 重合率 32% → 67%」是从 11 与 14 个事件算出来的。而且三档预算整个扫了一遍：`?!` 在 120 / 400 / 1200 毫秒下分别是 52% / 56% / 54%（胜率口径），**十倍搜索也救不回来**，没到 §5 写的 60% 及格线。`?` 与 `??` 站得住且随深度变好。结论：`?!` 是这个应用唯一不敢背书的标注。数字与结论一起写在 `docs/measured.json` 与 `docs/v6-plan.md` §8。

## 6.0.0 改了什么

**一个大版本一件事：把线性对局升级为可保存的分析树，并让产品在系统层面可信任。** 计划与标杆差距写在 `docs/v6-plan.md`；除 Apple Developer 签名公证与 Windows msix（都要证书）之外，计划内容按四个阶段落地，逐条状态见该文件 §7。

- **分析板**：任意一着走出别的着法即开变着（人机局进行中除外），着法表内嵌变着 / 注释 / NAG，可升主线、删分支、编辑注释，「回主线」一键；「重下」不再丢弃其后的着法。自写 PGN 解析器（RAV 嵌套、NAG、`{}`/`;` 注释、`[%cal]/[%csl]`、转义引号、`0-0`、CRLF/BOM、多局）替换 `load_pgn`，26 份语料往返断言；结果记号只写一次。右键拖箭头、右键点圈，Shift / Alt 换色，随节点进出 PGN。PV 存变着、固定预览后「从这里试走」。预走、盲棋、坐标开关、音量滑杆。

## 5.2.1 改了什么

**原生壳里两处从 5.0.0 起就坏着的东西。** 2026-09-06 的本机走查（`docs/manual-check.md` 末尾）发现：① 「导出」「导出复盘图」「学习数据导出」都不弹原生文件对话框，提示“在下载文件夹里”而下载目录里没有文件；② Esc 在原生应用里到不了页面 —— 固定的预览撤不掉、对话框关不上，而 → 和 P 正常。

- **根因一**：SDK 0.8 起，对话框 / 系统 / 剪贴板类内建命令没有隐含权限，不在应用传入的 `builtin_bridge` 策略里就一律拒绝；本仓库传的是默认空策略，host.js 把拒绝读成“这一构建没有对话框”，静默走浏览器回退。5.0.0 把 SDK 从 0.7.1 钉到 0.8.1 时引入，三个版本 CI 全绿，因为没有任何检查把页面调用的命令与 zig 侧放行的命令对到一起。现在 `main.zig` 放行页面用到的 10 个 `native-sdk.*` 命令，`manifest-check` 双向校验 host.js 与 main.zig 的清单。
- **根因二**：AppKit 壳只把声明过的快捷键当快捷键事件转给页面，Esc 未声明也未到达 WebView。现在 `app.zon` 声明 `view.escape` 快捷键，页面把窗口按键与快捷键事件都接到同一个 `escapeKey()`：清选中 → 关顶层对话框 → 关粘性提示 → 释放预览 → 退出编辑器 → 收面板。
- **回退如实**：原生构建里对话框仍不可用时，文本导出改为复制到剪贴板并如实提示，图片导出直接报告未保存，不再宣称“已下载”。
- 界面键 713 → 715。

## 规则引擎

局面合法性由 vendored [chess.js](https://github.com/jhlywa/chess.js) 0.13.4（BSD-2-Clause）判定——
不自研规则。`src/web/js/chess.js` 顶部注明了从 ESM 到经典脚本的机械转换（zero:// 方案下 WebView
只验证过经典脚本加载）。

chess.js 之上,`js/fide.js` 补齐它不做的比赛规则判定：三次重复与 50 回合是**可声明**和棋（art.
9.2/9.3）而非自动结束,五次重复 / 75 回合才自动判和（art. 9.6）；超时是否算输由「能否将杀」而非
子力数量决定（art. 6.9）。复盘分析对每个局面用的是**同一套判定**而不是 chess.js 的 `game_over()` ——
后者在三次重复和 50 回合就返回 true，照它记分会把还能继续的局面一律记 0，把局势曲线拉到轴上，
并且带偏其后每一步的失误分类与准确率。重复计数比较的是**可走着法**而不是 FEN —— FEN 只要有兵走两格就写上吃
过路兵格,哪怕没有兵能吃,直接比字符串会把同一个局面算成两个（`1.e4 e5 2.Nf3 Nf6 3.Ng1 Ng8
4.Nf3 Nf6 5.Ng1 Ng8` 就会漏判）,因此只有真正存在合法吃过路兵时才保留该权利。

## 对弈引擎

[Stockfish.js](https://github.com/nmrugg/stockfish.js) 18 lite-single（GPLv3，单线程 + lite NNUE，
约 7MB），vendored 于 `third_party/stockfish/`。zero:// 方案不能加载 worker 脚本也不能 fetch 打包
文件，因此构建时由 `scripts/gen-engine-src.mjs` 把 loader 文本与 wasm base64 生成为
`engine-src.js` 全局量，运行时 `engine.js` 用 Blob worker + `postMessage` 传 wasm 启动引擎——
全程零 URL 解析。难度用 UCI `UCI_LimitStrength/UCI_Elo`（1320–3190）限强，「极限」为满强度；
「新手」和「休闲」不靠 UCI 选项：Stockfish 的 `UCI_Elo` 下限是 1320，比真正的初学者高得多，
而实测 Skill Level 1 仍有约 27 ACPL（与入门档无异）。所以这两档改为**浅层 MultiPV 搜索 + 候选抽样**
（会主动取差着，但绝不放弃已算出的杀棋），靠 `worstBias` 调档：新手 0.2、休闲 0.15 且候选更少。

强度不用 ACPL 背书 —— ACPL 说不清「初学者赢不赢得了」。`scripts/test-novice.mjs` 直接对下：
一个只会「不一步送子」的随机机器人，100 盘对新手得分率 **59%**、对休闲 **29%**、对入门（1320）几乎为零（5 轮 × 20 盘；一场 20 盘的样本标准差分别是 7.7 和 10.1）。
（这三个数与下面各档的平均失分都来自 [`docs/measured.json`](docs/measured.json)，由
`node scripts/test-novice.mjs --record` / `test-strength.mjs --record` 写入；单测校验本文与
`engine.js` 的注释引用的是同一份数,不是各自记着的一份。1.25 之前正是各记各的：
README 记 56%/27%（32 盘），engine.js 注释记 66%/25% 且没写盘数。7.1.1 又补了一层：这三个数从 7.0 换引擎起就是 Stockfish 18 时代的，换成 SF19 之后没有人重测，而单测只比对「本文和 engine.js 是否一致」，两边一起过期它就一起放过。现在测量本身带着实测标准差，`test-novice.mjs` 的判定区间必须等于记录里的均值 ±3σ，单测校验这一条 —— 重测过却没改区间，会当场红。）
1.18 之前新手档 `worstBias` 是 0.6（六成的着法是十个候选里最差的那个），同一个机器人打出 **81%** ——
那不叫弱，叫自己送；而它上面一格就是 1320，没有中间地带。`scripts/test-strength.mjs` 另按满强度评估
量每档的平均失分。抽样走固定种子，但参照评估是按时间搜的，所以**它逐位复现不了**——
断言因此写成带容差的「档位之间不许实质倒挂」加各档绝对上下限，而不是两个噪声均值之比。
