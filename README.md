# 国际象棋 Chessboard

国际象棋 — Native SDK WebView + Canvas，支持 macOS 与 Windows。**GPLv3**（为后续集成 Stockfish 引擎预留）。

复用 [goban](https://github.com/hxddh/goban)（五子棋）打磨出的整套架构：Native 壳、Canvas 渲染、
侧栏/复盘/主题 UI、双平台 CI、无头浏览器回归测试。

## 2.1.5 改了什么

一处。它比前四个版本加起来都重，而且不是版式问题：**全新用户拿到的一直是中文界面，而首次运行的引导从来没出现过。**

干净存储、只改系统语言，实测已发布的 2.1.4：en-US、ja-JP、zh-CN、de-DE 四种系统语言，界面四次都是中文，引导一次都没出现。这两条正是 `docs/manual-check.md` A3 写着的失败样子——「引导不出现，或语言固定成中文」，而 A3 从来没有人跑过。

**根因**：`loadPuzzleState()` 为空档案返回的默认值带着 `idv: 2`，而模块初始化里那句 `if (idv === 2) Persist.setJson("puzzles", …)` 因此对全新用户也成立，写进一条空的做题记录。四千行之后，`firstRun` 靠回头读四个键来判断，而 `Persist.set` 会同时更新那份内存快照 —— 于是 `firstRun` 对每一个装过这个应用的人都是 false。它同时管着引导和 `detectLang()`。（`detectLang` 本身有八条单测，全部正确；函数没问题，只是永远不会被调用。）

**修法两半**：只在 id 真的动过时才落盘（`loadPuzzleState` 现在返回 `{state, migrated}`）；以及结构性的那一半 —— `firstRun = Persist.wasEmpty()`，问的是 `load()` 在任何迁移和写入之前记下的快照。只修第一半不够：那样 bug 只是被移走，下一个在 import 时写存储的模块会把它带回来 —— 实测也证明了，只还原第一半时冷启动守卫仍然全绿。

**更值得记的一句**：上一版扫了 36 个状态，但每个套件都先往 localStorage 塞种子，所以冷启动这条路按构造就没被测过。而且三个套件写着 `chess.onboarded` —— 一个早已不在 `KEYS` 里、应用根本不读的键。测试以为自己在跳过引导，真正让引导不出现的是这个 bug。三行都删了，并新增守卫禁止套件塞应用不拥有的键。

`test-layout-e2e` 397 → **425**，新增冷启动一节（四种系统语言 × 四项断言）；反向验证时报出的正是线上那两条症状。

顺带把 Native SDK 的版本钉住了：这一版第一次发布没能出去，Windows 的 `zig build test` 在 SDK 自己的 C++ 里报 `undefined symbol: createWindowsGpuRenderer()`——`@native-sdk/cli` 从 0.7.1（v2.1.4 用的）跳到 `latest` 解析出的 0.8.0，带进来一个 Windows 回归。发布卡在「必须真的有两个下载」那一步，那一步做对了。门禁依赖的其他东西全是钉死的（playwright 1.49.1、zig 0.16.0），只有 SDK 是唯一能在没人改动的情况下从底下换掉的，现在三个 workflow 都钉在 0.7.1。

## 2.1.4 改了什么

三处修复，两处「查过、是好的」。方法变了：不再按界面区域走，而是拿着已经修过的形状去找它的其他实例 —— 三处里有两处是这样找出来的。

**教学的按钮也装不下自己的字**，2.1.2 只修了编辑器那一处。凡是给出四个按钮的课，三种语言全都漏字：中文「接着练 2 题」的「题」挂在边框下面，英文和日文各漏两个；第 72 课只有两个按钮也漏 ——「Play the Beginner engine」，整条教学线存在的意义就是走到那一个按钮。修法和编辑器不同：编辑器那行是横着装不下（271px 挤进 239），需要 2×2；这行横着装得下，装不下的是盒子里的标签，所以让按钮高度随标签走，`align-items: stretch` 保证一行里每个按钮同高。

**存档槽五个同样的东西三种高度**：四项事实挤在第二行，英文下 249px 塞进 228，两个有存档的槽 71px 和 87px、三个空槽 55px。改成隔壁那份名单的形状（第一行是这是一局什么棋，第二行是多长、什么时候），时间戳也收短（不带参数的 `toLocaleString()` 在英文下带秒）。

**第三个装着一列句子的 380px 窄框对话框**：多局 PGN 的选局窗。真实棋谱的人名和赛事名长短不一，行高跟着变 —— 四局文件在三种语言下都是 55 和 71 两种高度。同一个形状在第一个被修掉之后又活了两个版本，所以守卫改成结构性的：任何装着 `.pick-list` 的对话框都必须用宽框。

顺带堵上内联样式的下一层：存档槽那一行是用 `row.style.cssText` 把历史行的 CSS 抄成内联的，改成共用 `.pick-row`；新增守卫禁止从 JS 写布局常量。

查过是好的：72 课的课文/标题/任务三语都不越界；36 个状态扫两种形状，两处报警都是探针的错；棋谱列表带标注重新量过（行高一致、恰好一个当前手且跟着回放走、图形化记谱下仍以完整 SAN 作读屏名），并补上了它此前完全没有的版式守卫。

## 2.1.3 改了什么

三处。前两处是 2.1.2 那轮复查里看到、当时没动的。

**脊压在棋盘的坐标行上。** 顶栏的高度是从棋盘边长里扣出来的 —— `.stage` 上那段注释写明了为什么（渐变绝不能盖在第 8 横线上）。脊是同一件事在另一头：一个 24px 的药丸、离底 6px，压在一块只剩 6px 余量的棋盘上，而没有任何东西为它让位。实测（面板收起）：520×520 下药丸 490–514、a–h 字母 498–513；1400×900 下 870–894 对 878–893 —— 第 1 横线最后 7px 加整行文件字母，每种窗口尺寸都一样，药丸的字横躺在 c–f 上。新增 `--spine-h` 面板收起时留 30px；代价是棋盘 822 → 792（−3.6%）、520 下 442 → 412（−6.8%）。留的条件是「面板收起」而非「脊显示着」—— 脊随对局状态来去，把棋盘尺寸绑在它身上会让棋盘对局中途改尺寸。

**回顾报告每方一行是散文体**：一句话装五个值，239px 面板里中文折三行、英文五行，`/` 和 `·` 结在行尾；而它正上方的「统计」装的是同一类内容，用的是每行一条、标签左值右。现在报告就是那一行：精准度 / 平均失分 / 「?! · ? · ??」，第三行标签用本应用自己的着法标记，和值「0 · 0 · 0」逐项对齐。**导出图读的是同一个 `sideRows()`** —— 只为面板拆开那个键，会让图用另一套词描述同一批数字，那正是上一版那张图把名字写反的由来。顺带第一次真的把导出图渲染出来看了三张（此前没有人看过，包括机器）。

**版式断言不再只在一种窗口宽度下成立。** 此前每条测量都只在 1400×900 取过，而 `app.zon` 允许窗口小到 520×520 —— 「面板一列 239px」这套推理全是在最宽那端成立的。新增一节在 520 下问同样的问题：不横向滚动、没有东西画到窗口外、没有标签撑出按钮、棋盘完整。结论是好的，但此前是「没人验过」。

## 2.1.2 改了什么

四轮复查，十四处。最重的一处不是版式：**导出的复盘图把两位对手的名字对调了**。

**导出的复盘图，两个人的名字调了个。** `renderReviewImage` 里两处写反：装着白方精准度、疑问手、失误、大失误的那一列，标题写的是「黑方」；关键一步也把走出那步棋的人报成了对手。而四百行外的面板里，同一份报告的同一批数字，名字是对的。这是全 app 唯一一件做出来就是要交给别人的东西。根因是「说出一方」和「说出另一方」写全了只差一个字，而全文有八处写全了 —— 六处指本方，两处有意指对手（「白方超时，黑方胜」）。收成 `sideName` / `otherSideName` 各一处。

**编辑局面那一行四个按钮，三种语言都装不下自己的字。** `.tool-btn` 高 32px 不换行、自带 24px 内边距，`flex: 1` 缩不到自己最长的词以下：英文实测那行要 271px 而只有 239px，主操作整个越出面板；中日文靠把标签折进一个没有第二行余地的药丸，文字从按钮里漏出来 ——「开始对局」两行、「キャンセル」三行，最后一个字挂在边框下面。改 2×2，分行处正是语义分界。

**题型段：样式表写着「五项以上退回三列」，代码从没实现。** `auto-fit` 配 64px 下限在 335px 面板里解析成四列，而四列时「Win material」要 79px、格子 78px —— `grid-auto-rows: 1fr` 把它折行后的高度发给全部十个按钮，一个宽了一像素的标签让整个控件高出一半，只在英文下。

**快捷键表在四个模式里显示同一份十三行**，而 keydown 处理器一直是分模式的。做题模式下它给出「Z 悔棋」「F 翻转棋盘」和两行回放 —— 在那里全都没有作用；还把 N 说成「新局」，而做题里 N 是下一题。改成按模式渲染。

**十五个成就是一份清单，行却是五种形状。** 两列不够装「一个名字 + 走到哪儿了」：名字要么折行，要么把计数器挤下去。实测中文 33 与 55，英文 33/54/55/76/90，日文 33/54/55/68/76；十一个带计数的徽章里只有「圆满」把计数器留在同一行，仅因名字够短。改成整幅面板宽的一列，十五行一个高度 —— 正是它上方「统计」已经在用的那一行；最坏的英文列反而变短了（673 → 647px）。

**对局历史对话框两处。** 行「日期 · N 回合 · 精准度 X%」要一行装下，380px 的框只给 262px，而英文里昨天下的那局要 263 —— 相对写法「yesterday 12:55 AM」比更早对局的「7/31/2026」长；一个像素，40 行里 12 行 67px。全 app 只有这一个对话框装的是一列句子，却用着只装一个问题的框的宽度。另一处：两个筛选段并排 `flex: 0 1 auto`，而 flex 的 auto 基准是内容宽度，内容是 `minmax(0, 1fr)` 网格 —— 最小内容宽度是 0，它们从来没长大过。中文下四个结果按钮分 60px、三个执子按钮分 94px，而那行有 418px、空着 264px；26px 一列时「执白」折成三行，执子段 79px 高挨着 35px 高的结果段。

**七个对话框，读屏听到的名字就是屏幕上那个标题。** 每个都把标题存了两份（`aria-label` 加可见的 `<h3>`，来自不同的键），两对已经走岔；确认框更甚 —— 标题每次现写，`aria-label` 却是固定的「确认」：点「清除全部存档」，屏幕上写着「清除存档」，读屏念的是「确认」。

**两处「为什么不行」读屏一个字都听不到**：编辑器的非法局面原因（也是「开始对局」变灰的原因）、FEN 对话框的拒绝理由，都写进普通 `<p>`；FEN 输入框只变红，从未标记 `aria-invalid`。

**另外几处**：导出成功但说不清文件去了哪（`saveFile` 对「没有对话框 API」和「用户取消了」返回同一个 `null`，于是没有桥接时报的是「已取消导出」）；故障提示没有关闭键，只能等；统计行在英文下 42px 对其余 23px；回放条的键会因为被按而缩小跳走；四个内联 `margin-top`（14 和 10，两个刻度上都没有的值）—— 内联样式是全部 token 守卫唯一看不见的地方，现在有守卫禁止它。

`test-layout-e2e` 108 → **349**，新增守卫全部反向验证过。规则、引擎、题库、课程未改动。

## 2.1.1 改了什么

以「找 bug、界面精致度、设置项的逻辑」为题复查了一轮，九处，规则/引擎/题库/课程未改动。

**设置页的顺序就是它的说法。** 三个不可撤销的删除、全页唯一的红色，此前夹在你每天都会调的两组之间 —— 挪到最后。「外观」改名「界面」（它装着语言和音效，两项都不是外观），组内从最看得见排到最看不见：主题 → 棋盘方向 → 语言 → 音效。「棋盘方向」从一个写着「翻转」的按钮改成**白方视角 / 黑方视角**两段：这一页每一行都显示它现在是什么，只有它显示按下去会怎样。

**段控件的列数由项数决定，不再由宽度决定。** `auto-fit` 配 64px 下限在 284px 面板里恒为三列，于是模式、棋力档、陪练风格三个四项控件全部排成 **3 + 1** —— 一个段孤零零落在三个下面，读起来是另一类东西；而两厘米外同样四项的主题行是普通 flex，四个一排。2.0.0 处理过这个家族一次（`grid-auto-rows: 1fr` 让两行等高），孤儿变整齐了但还在。现在 2/3/4 各自整除自己的行（四项走 2×2，因为 `Intermediate` 要 88px 而四列只给 65），五项以上退回三列。顺带把「陪练档」116px 与「棋力档」74px 对齐 —— 同一个难度概念下两行差 57%。

**隐藏了内容却留下空壳**：教学/做题下「对局」是一个 33px 的空分节（`hidden` 加在 `<details>` 上，外层 `<section>` 还站着，分隔线照画）；「本局」在 0 手时只剩「新局」一项，一个组标题配一个动作而这局还没开始。

**成就**：「下一个够得着的」卡片和两个分组标题是那个两列网格的子元素，各占一格另一半留白 —— 它们不是徽章，是徽章归档的行。九个成就名被断在词中间（规则通/关、熟能生/巧），2.0.1 的 `overflow-wrap: anywhere` 止住了越界却改成到处断词 —— 真正不够的是行不是名字：`0/111` 计数器和名字抢同一行。计数器改成放不下就掉下一行，折行 **9/17 → 0**。

**另外三处**：「三项都不可撤销」在空档案下只有两项（文案改成不点数）；13 个分组标题有 3 个是 `<span class="side-h">`，按标题导航看不见；「翻转」三个入口各带一份实现，而 `NATIVE_COMMANDS` 上的注释正写着「只有一份实现，两者绝不会走岔」—— 已经走岔了（按钮 toast，键和菜单默默改），收成 `setFlipped` 一处。

`test-layout-e2e` 146 → **218**，新增七组守卫都反向验证过。

## 2.1 改了什么

只改了一个东西：棋盘正上方那条 44px 的横栏。它不是没对齐 —— 是**里面没有任何两件东西共享一个单位**，所以对不齐：模式行（一次会话切 0–2 次）、状态药丸（每一步都变）、四个动作加 ☰（随时点），三种更新频率、三套视觉语汇、三种高度（36 / 27.4 / 32）、两条基线，并排在 44px 里。

而这 44px 是**从棋盘的边长里扣的** —— 棋盘是正方形、在这个 app 跑得到的每一种窗口里都是高度受限的，上下各只剩 6px 留白。实测把 `--chrome-h` 调到 0：棋盘边长 1400×900 下 +5.2%、640×560 下 **+8.7%**，换成面积是 **+10.7% 到 +18.2%**。而这条栏上 **66% 是空的**。

现在顶栏 = 一句话 + 这一步棋要用的两个动作 + ☰，**32px 高、一种控件高度（28px）、一条基线、左右各 8px**。模式进设置页第一节（和难度/风格/主题同一种段控件），翻转进设置页·界面，新局进对局页·本局（它此前是全 app 唯一一个渐变实心按钮 —— 这个 UI 里「该按的就是这个」的说法，花在了对弈中最不该按的那一个上）。五个动作本来就都有快捷键（H Z F N P），搬走的丢的是重复的按钮不是唯一的路；☰ 留下，面板关着时它是唯一的指针入口。

一并删掉 `.mode-nav` —— 只为一行存在的第二套段控件语汇。它带的 `margin-top: 12px` 是面板时代的，在顶栏里把整组压到中线下 6px、越出栏底 2.5px，组边框和选中下划线在**栏外面**叠成一条 3px 双色横杠；样式表里没有一条规则能发现，因为它每一条声明都只有它自己在用。

顺带修掉一个比「错位」严重的：动作组右对齐，而悔棋与提示都随局面出现消失。实测走完 1.e4 轮到引擎，**提示消失、悔棋出现在提示刚刚占据的同一 50 像素里** —— 同一位置点两次，第二下是悔棋。两格改成固定槽位（`visibility` 保住盒子，仍不可 Tab、不可点击），宽度下限 80px（三语六个标签最宽的 Thinking 实测 78px）。现在栏里没有任何元素会因局面变化而移动。

教学模式的状态药丸从课程标题改成「第 N 课」：216 条真实标题在 820px 下有 61 条被省略号截断，1400px 下还有 1 条（最长要 463px 而只有 418px）—— 而 `app.js` 里那段注释说的正是「一个会被截断的胶囊说明这句话不属于那里」。

`test-layout-e2e` 108 → **146** 条，新增的守卫都反向验证过。规则、引擎、题库、课程一律未改动。

## 规则引擎

局面合法性由 vendored [chess.js](https://github.com/jhlywa/chess.js) 0.13.4（BSD-2-Clause）判定——
不自研规则。`src/web/js/chess.js` 顶部注明了从 ESM 到经典脚本的机械转换（zero:// 方案下 WebView
只验证过经典脚本加载）。

chess.js 之上,`js/fide.js` 补齐它不做的比赛规则判定：三次重复与 50 回合是**可声明**和棋（art.
9.2/9.3）而非自动结束,五次重复 / 75 回合才自动判和（art. 9.6）；超时是否算输由「能否将杀」而非
子力数量决定（art. 6.9）。复盘分析对每个局面用的是**同一套判定**而不是 chess.js 的 `game_over()` ——
后者在三次重复和 50 回合就返回 true，照它记分会把还能继续的局面一律记 0，把局势曲线拉到轴上，
并且带偏其后每一步的失误分类与准确率。重复计数比较的是**可走着法**而不是 FEN —— FEN 只要有兵走两格就写上吃
过路兵格,哪怕没有兵能吃,直接比字符串会把同一个局面算成两个（`1.e4 e5 2.Nf3 Nf6 3.Ng1 Ng8
4.Nf3 Nf6 5.Ng1 Ng8` 就会漏判）,因此只有真正存在合法吃过路兵时才保留该权利。

## 对弈引擎

[Stockfish.js](https://github.com/nmrugg/stockfish.js) 18 lite-single（GPLv3，单线程 + lite NNUE，
约 7MB），vendored 于 `third_party/stockfish/`。zero:// 方案不能加载 worker 脚本也不能 fetch 打包
文件，因此构建时由 `scripts/gen-engine-src.mjs` 把 loader 文本与 wasm base64 生成为
`engine-src.js` 全局量，运行时 `engine.js` 用 Blob worker + `postMessage` 传 wasm 启动引擎——
全程零 URL 解析。难度用 UCI `UCI_LimitStrength/UCI_Elo`（1320–3190）限强，「极限」为满强度；
「新手」和「休闲」不靠 UCI 选项：Stockfish 的 `UCI_Elo` 下限是 1320，比真正的初学者高得多，
而实测 Skill Level 1 仍有约 27 ACPL（与入门档无异）。所以这两档改为**浅层 MultiPV 搜索 + 候选抽样**
（会主动取差着，但绝不放弃已算出的杀棋），靠 `worstBias` 调档：新手 0.2、休闲 0.15 且候选更少。

强度不用 ACPL 背书 —— ACPL 说不清「初学者赢不赢得了」。`scripts/test-novice.mjs` 直接对下：
一个只会「不一步送子」的随机机器人，32 盘对新手得分率 **56%**、对休闲 **27%**、对入门（1320）几乎为零。
（这三个数与下面各档的平均失分都来自 [`docs/measured.json`](docs/measured.json)，由
`node scripts/test-novice.mjs --record` / `test-strength.mjs --record` 写入；单测校验本文与
`engine.js` 的注释引用的是同一份数,不是各自记着的一份。1.25 之前正是各记各的：
README 记 56%/27%（32 盘），engine.js 注释记 66%/25% 且没写盘数。）
1.18 之前新手档 `worstBias` 是 0.6（六成的着法是十个候选里最差的那个），同一个机器人打出 **81%** ——
那不叫弱，叫自己送；而它上面一格就是 1320，没有中间地带。`scripts/test-strength.mjs` 另按满强度评估
量每档的平均失分。抽样走固定种子，但参照评估是按时间搜的，所以**它逐位复现不了**——
断言因此写成带容差的「档位之间不许实质倒挂」加各档绝对上下限，而不是两个噪声均值之比。

## 开发

前置条件（`package.sh` 只面向 macOS，其余脚本跨平台）：

| 需要 | 用来做什么 | 没有会怎样 |
|------|-----------|-----------|
| Node 22+ | 跑 `scripts/` 下的全部检查与代码生成 | 什么都跑不了 |
| `npm ci`（唯一依赖:esbuild） | 把 `src/web/js` 的 ES 模块打成 `js/bundle.js` | 页面加载不出来:index.html 只加载这一个脚本 |

| Playwright + Chromium / WebKit | 六个浏览器 E2E（两个引擎各跑一遍）| 各自打印「跳过」并通过；发布流水线设 `E2E_REQUIRED=1`，那里跳过即失败 |
