# 国际象棋 Chessboard

国际象棋 — Native SDK WebView + Canvas，支持 macOS 与 Windows。**GPLv3**（为后续集成 Stockfish 引擎预留）。

复用 [goban](https://github.com/hxddh/goban)（五子棋）打磨出的整套架构：Native 壳、Canvas 渲染、
侧栏/复盘/主题 UI、双平台 CI、无头浏览器回归测试。

## 8.2.1 改了什么

**修复：Windows 版双击启动时页面是空的。** 8.2.0 的 Windows 包（更早的 8.x 用的是同一个 SDK 和同样的包结构，按理也一样，没有逐个核对），从资源管理器双击 `Chessboard\bin\chessboard.exe` 启动时读不到页面：SDK 0.10.1 的 WebView2 宿主按「当前目录」去找 `frontend/dist`，而安装包把页面放在 `Chessboard\resources\frontend\dist`，双击时当前目录是 `bin\`。macOS 不受影响（macOS 的宿主在 .app 里找页面）。8.2.1 启动时先找 exe 旁边的 `..\resources\frontend\dist`，找到就用这个绝对路径；从哪个目录启动都一样（CI 上在 runner 的临时目录里启动已验证，真机双击仍是真机路线 Windows 段的第一步）。

**为什么 CI 一直没发现。** 发布流程里的打包自检是在仓库根目录启动应用的，那里恰好有一份 `frontend/dist`，所以页面照常加载、自检照常通过。8.2 新加的 automation 作业在临时目录里启动应用，页面一次都没跑起来——当时记成「原因还没查清」，这次查清了就是它。现在打包自检也在临时目录里、按绝对路径启动应用，静态测试守着这一点；Windows 的 automation 作业 30 项第一次全过（同步期间 `wait` p95 10 ms，页面最长帧间隔 46 ms）。

**另外。** automation 在 Windows 上结束应用时连 WebView2 的进程一起结束，等它们退干净再启动下一次。README 的下载说明改成 exe 的实际位置 `Chessboard\bin\chessboard.exe`。存档、功能与 8.2.0 完全相同。

记录见 [docs/v8-2-plan.md](docs/v8-2-plan.md) §9「8.2.1」。

## 8.2.0 改了什么

**练计算，练看棋；能自动验证的交给 CI。** 8.1 把 8.0 欠下的补齐了；8.2 加的是新的练法：进阶课程第三部、「看 N 步」与「盲走」、名局猜着。同时把以前只能靠人在真机上看的东西，尽量交给 CI 自动去跑。存档格式不变（SCHEMA 仍是 2），8.1 的设置、棋谱库和开局书打开即用；降级回 8.0 / 8.1 再回来会丢什么，现在每次 CI 都有测试（见下面「路线」里的「降级」）。

**进阶课程第三部：96 课 → 120 课。** 计算 12 课（候选着、强制着、盘点对方的回答、算到底、数步数……）和局面型 12 课（坏象、弱格与前哨、兵链方向、何时换子、预防……），共 73 步，全部是走子题。每一步算对哪些着、算错哪些着，都用 Stockfish 深度 20 核对过：接受的着法和最佳同级，拒绝的比最佳差 50 cp 以上。55 步的局面取自 Lichess 公开题库（不在应用自带的 4 万题里）。课文三语，按需加载。

**谜题页多两种玩法：「看 N 步」与「盲走」。** 「看 N 步」：棋盘停在题面，接下来的 N 步只写成文字，你在脑子里走完，再回答「哪个子能吃掉 e5 上的马」「哪个子一步就能将军」「有没有一步杀」；答对 N 加一，答错减一，在 2–6 之间。「盲走」：一步杀、两步杀的局面亮 3 秒后藏起棋子，输入着法（`Qh7#` 或 `d1h5`），也可以直接点棋盘。都是一组 10 题，各有自己的评级和复习队列，「我的」页多一节「计算专项」。

**名局猜着。** 「学习」目录里名局之后，同样的十局再列一遍：选一方，轮到这一方时先猜，再看大师的原着。和原着一样得满分，不一样就按引擎算出的胜率差扣分，分级和复盘一致。引擎用复盘的定节点预算，同一步每次给的分都一样。一局下来告诉你有几步和大师一样、平均扣多少分、最大的一次偏差在哪（可以跳过去看）。

**开局书：每方 400 条 → 5,000 条。** 线搬进一个新的数据库，原生存档、导出 / 导入全部数据和学习数据都带着整本书。视图菜单多了「开局书」（⌘⇧O / Ctrl+Shift+O）；「今天到期」每分钟核一次，过了午夜也会更新。回到 8.0 / 8.1 时看到的是每方最早的 400 条；再回到 8.2，在旧版里做的改动会叠回整本书。

**教练又会说「长将」和「困子」了。** 8.1 抽样核对时这两种母题错误率都是 12%，所以只说子力得失。8.2 改了判定：长将要在棋盘上证明真的能一直将下去，被钉住的子不算困子。重新抽样核对，两种各 25 条，错误率都是 0%，恢复了「让对方起长将」「漏看了困子」这类说明。代价是判长将比以前严：有些以前说「长将」的局面，现在只说子力得失。

**棋谱库重启更快。** 一万局的棋谱库停在棋谱库页时重启，「经过这个局面」可用的时间 2,739 → 526 ms，列表出现 1,451 → 230 ms，能搜索 1,477 → 244 ms（本机 headless Chromium，五次取中位数）。原因是棋盘被整页盖着时，启动过程里还要画 10 遍；现在被盖住时不画，棋子脚下的阴影也只模糊一次。

**残局训练营查了表。** 5 子的 11 个残局在 CI 上查了 Lichess 的在线 Syzygy 全表，结论都和目标一致，标记改成「查残局库核对」。60 个里有 59 个查过表，只剩 8 子的「三兵突破」超出任何残局库，仍用 Stockfish 核对。

**另外几条。** 窗口的位置和大小重启后照上游的做法恢复（8.1 在某些情况下会居中）；Windows 版嵌入了 SDK 的应用清单，按显示器做 DPI 感知，缩放 150% 时应该不再发虚——这两条还要在真机上确认。导出全部数据时，保存框弹出之前先显示「正在准备导出的文件…」。界面上原来拼起来的 26 个句子片段都改成了整句模板，三语显示的文字一字不变，为以后加语言打底。Lichess 增量同步依赖的「按时间正序」已在真站上核对过。CI 每个作业都有了超时，最长的几个浏览器组拆开，一次 PR 检查的墙钟从 8.1 时的 20.2–33.8 分钟降到 15.9 分钟。主包 900,972 → 907,245 字节（8.2 给自己定的上限是 910,972，新内容都放进按需加载的分块）。`app.js` 5,873 → 5,754 行，`main.zig` 拆成五个文件。

**还没做到的。**
- **SDK 仍是 0.10.1。** 0.10.2 到 2026-10-01 还没有发布（npm 上最新仍是 0.10.1），所以没有 SDK 升级。macOS 自动更新、签名与公证、透明标题栏的情况和 8.1 一样。
- **CI 驱动打包后的应用，只在 macOS 上过了。** 8.1 真机清单 R1–R19 里有 9 条（R5 的一部分、R6、R6a、R7、R8、R9、R11、R17、R18）改由 macOS / Windows 的 automation 作业驱动打包后的应用去走。发布彩排里 macOS 30 项全过；阈值仍是放宽的暂定值，等第二次运行再定。Windows 那个作业**没过、也不挡发布**：应用起来了，但页面在 runner 上没有跑起来，场景一份报告都没写，原因还没查清（runner 上的 WebView2 环境，还是应用本身，CI 分不出来）。
- **8.2 真机路线还没人走过**（[docs/manual-check.md](docs/manual-check.md) 的「8.2 真机路线」，两个平台各约 17 分钟）：图标；原生文件对话框本身和中文路径；60 帧的动画手感；用真账号连 Lichess / Chess.com 同步，包括 Windows 上的 HTTPS（R10）；窗口位置恢复（X1）；Windows 150% 缩放下是否清晰（X2）；Windows 顶部拖动区实验。导出 / 导入全部数据（R16）的面板也只能人看。8.2.0 带着这些未记录的条目发布。
- **阶梯最上面一级仍然不准。** 补盘的工作流已经能只下点名的那一对，但还没有派发：「强力+」→「不限档」仍是 64 盘，95% 区间 50–71%。
- **CI 墙钟还没稳定在 15 分钟以内。** 最近一次 15.9 分钟，「连续三次 ≤ 15 分钟」还没达到。布局分片偶尔不出帧（看门狗兜着）的根因也没查。
- **判一次长将最慢约 0.3 秒。** 搜索有上限，最坏 260–340 ms，评审要的是 ≤ 150 ms。再压预算，样本里有三条真长将就证明不出来；要更快只能自己写着法生成器，主包放不下。
- **整句模板的守卫有盲区。** 译文经函数参数、对象属性或后来才赋值的变量流到 `+` 拼接，守卫看不见。
- **小项。** 「看 N 步」「盲走」只从本地 1,148 道题里出题，没有接 Lichess 题库；「看 N 步」接下来的几步用的是简单规则，不是引擎着法，偶尔不像实战。第二个引擎仍默认关。降级到 8.0 时，8.1 起才有的对手档位换成「中级」，「第二个引擎」开关回到关（8.1 不丢）。

计划、依据与落地记录见 [docs/v8-2-plan.md](docs/v8-2-plan.md)。界面键 1279 → 1301。

## 规则引擎

局面合法性由 vendored [chess.js](https://github.com/jhlywa/chess.js) 0.13.4（BSD-2-Clause）判定——
不自研规则。`src/web/js/chess.js` 顶部注明了从 ESM 到经典脚本的机械转换（zero:// 方案下 WebView
只验证过经典脚本加载）。

chess.js 之上,`js/fide.js` 补齐它不做的比赛规则判定：三次重复与 50 回合是**可声明**和棋（art.
9.2/9.3）而非自动结束,五次重复 / 75 回合才自动判和（art. 9.6）；超时是否算输由「能否将杀」而非
子力数量决定（art. 6.9）。复盘分析对每个局面用的是**同一套判定**而不是 chess.js 的 `game_over()` ——
后者在三次重复和 50 回合就返回 true，照它记分会把还能继续的局面一律记 0，把局势曲线拉到轴上，
并且带偏其后每一步的失误分类与准确率。重复计数比较的是**可走着法**而不是 FEN —— FEN 只要有兵走两格就写上吃
过路兵格,哪怕没有兵能吃,直接比字符串会把同一个局面算成两个（`1.e4 e5 2.Nf3 Nf6 3.Ng1 Ng8
4.Nf3 Nf6 5.Ng1 Ng8` 就会漏判）,因此只有真正存在合法吃过路兵时才保留该权利。

## 对弈引擎

[Stockfish.js](https://github.com/nmrugg/stockfish.js) 19 lite-single（GPLv3，单线程 + lite NNUE，
wasm 1.79 MB），vendored 于 `third_party/stockfish/`。zero:// 方案不能加载 worker 脚本也不能 fetch 打包
文件，因此构建时由 `scripts/gen-engine-src.mjs` 把 loader 文本与 wasm base64 生成为
`engine-src.js` 全局量，运行时 `engine.js` 用 Blob worker + `postMessage` 传 wasm 启动引擎——
全程零 URL 解析。页面 CSP 的 `script-src` 带 `'wasm-unsafe-eval'`：blob worker 继承这份策略，没有它 WebView2 与 WKWebView 都拒绝编译 wasm（6.0–7.3 引擎因此一直起不来，7.4 修复，由 `test-engine-e2e` 守着）。难度用 UCI `UCI_LimitStrength/UCI_Elo`（1320–3190）限强，「极限」为满强度；
「新手」和「休闲」不靠 UCI 选项：Stockfish 的 `UCI_Elo` 下限是 1320，比真正的初学者高得多，
而实测 Skill Level 1 仍有约 27 ACPL（与入门档无异）。所以这两档改为**浅层 MultiPV 搜索 + 候选抽样**
（会主动取差着，但绝不放弃已算出的杀棋），靠 `worstBias` 调档：新手 0.15、休闲 0.12 且候选更少（8 个 vs 10 个；8.0 B4 之前新手 0.2、休闲 0.15 与 6 个候选）。

强度不用 ACPL 背书 —— ACPL 说不清「初学者赢不赢得了」。`scripts/test-novice.mjs` 直接对下：
一个只会「不一步送子」的随机机器人，100 盘对新手得分率 **56%**、对休闲 **41%**（8.0 B4 重调这两档之前是 59% / 29%），对 B4 补上的四档依次 30% / 12% / 8% / 4%，对入门（1320）几乎为零（5 轮 × 20 盘；一场 20 盘的样本标准差：新手 11.2、休闲 9.6）。
（这三个数与下面各档的平均失分都来自 [`docs/measured.json`](docs/measured.json)，由
`node scripts/test-novice.mjs --record` / `test-strength.mjs --record` 写入；单测校验本文与
`engine.js` 的注释引用的是同一份数,不是各自记着的一份。1.25 之前正是各记各的：
README 记 56%/27%（32 盘），engine.js 注释记 66%/25% 且没写盘数。7.1.1 又补了一层：这三个数从 7.0 换引擎起就是 Stockfish 18 时代的，换成 SF19 之后没有人重测，而单测只比对「本文和 engine.js 是否一致」，两边一起过期它就一起放过。现在测量本身带着实测标准差，`test-novice.mjs` 的判定区间必须等于记录里的均值 ±3σ，单测校验这一条 —— 重测过却没改区间，会当场红。）
1.18 之前新手档 `worstBias` 是 0.6（六成的着法是十个候选里最差的那个），同一个机器人打出 **81%** ——
那不叫弱，叫自己送；而它上面一格就是 1320，没有中间地带。`scripts/test-strength.mjs` 另按满强度评估
量每档的平均失分。抽样走固定种子，但参照评估是按时间搜的，所以**它逐位复现不了**——
断言因此写成带容差的「档位之间不许实质倒挂」加各档绝对上下限，而不是两个噪声均值之比。
