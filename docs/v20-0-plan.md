# 20.0 · 一条路：学一样，下一盘像人的棋

写于 19.0.0 发布之后（2026-11-06）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

用户对这一版的要求：
- **全面质变**，不是再打磨一轮；
- 聚焦对弈和国际象棋教学，优雅、精致、简洁、快速，不复杂化（19.0 的要求照旧）；
- **不需要兼容历史版本和旧存档**（2026-11-06 补充）。

**结论**：
- **19.0 的每一块单独看都不错，缺的是把它们连起来的那条路。**
  - 课程、谜题、对局、复盘、残局、名局、开局是七座岛，各有各的进度、各的等级分、各的「下一个」。
  - 定级 2125 的人，今天页仍叫他上「第 1 课 · 棋盘与坐标」。没学马怎么走的新手，先拿到马的闷杀。一盘新手对局往复习里塞了 18 道题。
  - 研究里有证据的，是「练习量 + 针对个人 + 测验与间隔复习 + 讲清为什么」；市面上很少有产品把「你自己对局里的错 → 间隔复习 → 下一课」这个环接上（§依据 3）。
- **下棋正确，但没有温度。**对手恒定 0.3 秒落子；532 分的对手多一个车收不了官；失着提醒在对方应着之后才出来；提示一按就是答案；复盘的「再试一次」在面板最下面。
- **讲解准确，但窄。**错的不到 1%，但只有 58% 的失误能说出原因（低分段 27%）；只会讲战术和子力。上限是单线程精简版引擎（约 15 层）和只有 19 句的模板。
- **现在的代码接不住一次大改版。**所有页面一开始就写死在 `index.html`（472 个 id），41 个模块按 id 直接改它；`app.js` 4,777 行；一块棋盘是全局单例；存档三层互相对账。
- **所以 20.0 做三件事，一件为另三件铺路**：
  1. **一条路（L）**：一个学习者模型决定下一件事，课、题、对局、复盘都往里写、从里读。
  2. **一盘像人的棋（P）**：对手按人的节奏想、会收官会认输；教练在你松手前提醒；复盘就在棋盘上，三步以内。
  3. **讲「你这一步」（F）**：一个解释器用到所有反馈里；换原生多线程引擎，讲得更深、更准。
  4. 铺路的是 **A 重建**：新的界面层、一个存储、一个引擎服务；旧存档不读，旧兼容代码整块删掉。
- 外加 **H 手感**、**S 更少**、**E 工程**。
- **不做**：大模型聊天或大模型写的讲解（本地小模型讲错的比例最高 55%）、准确率百分比、「妙手!!」泛滥、每步都插话的教练、宝石皇冠类游戏化、成百上千个机器人对手。

**已定（2026-11-06，「按建议来」）**：第 8 节每一条都取推荐项——
- 范围 A + L + P + F + H + S + E 全做；
- 导航「学 / 下 / 我」，今天页并进「学」；
- 原生多线程 Stockfish，wasm 作后备；
- Maia-3 先核许可证和速度，可行就换；
- 申请签名与公证（证书要以你的名义申请，见 §7 E2）；
- 19.0 的 bug 在新结构里修，不发 19.0.1；
- 不读旧档案，只提供一次性导入 PGN；
- 对手提醒按水平：新手默认开、1500 以上默认关。

## 依据

2026-11-06 的三份报告，都在 main @ 1fbbf83（19.0.0）上做。

1. **真实使用走查**（`scratchpad/q20/`）：
   - 真引擎（Stockfish 19 + Maia），Chromium，1440 × 900 与 1024 × 700，中文、空存档，英文抽查。
   - 三个人：零基础新手（第 1–5 课、第 18 课、第一批谜题、对皮普 532 一盘、复盘）；1500 左右的俱乐部棋手（定级、对薇拉 1512 一盘、完整复盘、谜题、残局营、名局猜着、训练·开局）；第二天回来的人（今天页、我的）。
   - 俱乐部棋手的着法由另一个 Stockfish 按前三选随机挑，并在第 14、20 回合故意走坏。
   - 局限：无头浏览器不出声；不是 WebKit，不是真机；定级题用引擎解，所以定级偏高（这本身也暴露了问题）。
2. **工程审计**（`scratchpad/a20/`）：架构、性能（跑了 measure-boot、perf、engine、engine-flows、board、review 各组 e2e）、讲解管线、原生壳（含 SDK 0.11.0 的差异检查）、测试与 CI、内容清点。
3. **外部调研**（`scratchpad/r20/report.md`）：顶级对弈与教学产品做对了什么、棋类与学习科学的证据、2024–2026 能离线落地的技术、棋盘手感的具体参数。每条结论标了来源类型（论文 / 厂商 / 论坛）。

**已经是顶级、这一版不碰的**（三份报告一致）：
- **速度**：首帧 64–220 ms；对手应着 0.27–0.54 s；60 个半回合的复盘 4.5 s；下到第 160 步每步开销几乎不变（5.8 → 6.4 ms）。
- **单步反馈**：谜题的反驳（「还不是将死 —— 黑方可走 Rf8」）、再试一次第一次错说后果（「Qb3 之后，对方可以走 fxe5」）、残局丢胜当场停、关键时刻的理由。
- **自己的错变成第二天的题**：「实战里你走了 Qa3 —— 找出更强的一手」。走查认为这是整个产品最接近顶级教练的一刻，20.0 要把它从一个点变成整条路。
- **复盘的第一句话**用对手的口吻说事实，接「这盘最该练 → 去学这一课」。
- **低档对手像人**（19.0 T5）。
- **视觉语言**与三语文案。

**局限**：三份报告都没在真机上验证；没有使用统计，「很少用到」都是估计。

## 0 · 不兼容意味着什么

- 20.0 **不读** 19.0 及更早的任何存档、设置、进度；装上就是一个新档案。
- 旧版用户想带走的，只有**对局本身**：19.0 已经能「导出全部数据」和导出 PGN；20.0 提供**一次性导入 PGN**（对局进棋谱库，并按 §L 喂给学习者模型）。课程进度、谜题复习、成就不带过来——20.0 的学习模型和它们对不上，带过来反而是噪音。
- 发布说明第一行写清楚这一点，并告诉 19.0 用户：升级前先「导出全部对局」。
- 代码里随之删掉：旧阶梯分数（`RATING_80/2/3`、`lad`）、旧页面和设置分类的映射、旧外观回落、`soundOn`、存档槽迁移、`RESTORED_AND_FILED`、三层存储的对账，以及它们的测试（约 3,000 行）。注释里的 952 处版本号历史挪进 `docs/adr/`。

## 1 · A 重建：为另外几件事铺路

**依据**：
- 每一屏一开始就静态写在 `index.html`：472 个 id、23 个对话框、启动时 4,372 个节点；41 个模块按 id 直接改它（742 处 `getElementById`）。
- `app.js` 4,777 行、197 个函数，约 30 个 `createX({…})` 工厂各收 10–30 个回调，没有一个模块能单独拿出来。
- 全局状态 3 块、111 个字段，51 个文件直接赋值；一次提交让十几个渲染函数全部重跑；没有「上一个状态」，所以动画只能在棋盘上手写。
- 棋盘是模块级单例，一屏只能有一块可交互的棋盘。
- 存档：浏览器缓存 + 原生文件（A/B 两代）+ IndexedDB（再镜像成 68 个分片），按 `writtenAt` 对账；一盘 160 步的棋自动存 160 次、共写 3.3 MB。
- 按需加载：每个分块要同时维护 4 处（CHUNKS 条目、shim、facade、一条测试）；棋谱库和开局书是启动时就要的同步依赖，19.0 S1 因此没能挪出首屏包。

**做什么**：
- **A1 界面层**：
  - 一个路由，一次只挂一个页面，页面按需创建；不再有「所有页面都在 HTML 里」。
  - 组件用原生 JS + 信号（或一个 ≤ 10 KB 的库，A1 第一周比较 Preact / Lit / Solid 后定，写进 ADR）。
  - **棋盘是一个组件**：可以有多个实例（今天页的小棋盘、复盘里的变化、课上的对照），场景图里每个子、箭头、标记都能补间动画。
- **A2 一个存储**：
  - 不可变状态、显式动作、按需订阅（selector），取代 111 个可写字段。
  - 持久化交给原生端的一个 **SQLite**（SDK 的 RelationalStore）：表 `games`、`moves`、`analysis`、`events`、`cards`、`skills`、`repertoire`、`settings`。
  - 自动存档每一步只追加一条事件，不再整份重写。
  - 学习者模型（§L）是事件的投影：任何时候都能从事件重算。从 20.0 起只往前迁移，不写回退。
- **A3 引擎服务**：
  - 一个 `EngineService` 包住所有算棋的东西：原生 Stockfish（§F3）、Maia、残局库；wasm 版 Stockfish 作为后备。
  - 界面只发请求（「这个局面的三条线」「这一步人会怎么走」「复盘这一局」），不知道背后是谁。
- **A4 拆 `app.js`**：按功能分目录（play、review、learn、library、me、settings），纯逻辑核心原样保留（`chess.js`、FIDE 规则、PGN、复盘数学、`motif`、`explain`、`srs`、`rating`、`persona`）；`app.js` 只剩约 200 行的启动。
- **A5 先做一次技术验证**：SDK 0.11 在 zero:// 上能不能用 ES modules、`import()`、`fetch` 二进制。能，就去掉整套 iife 分块机制，Maia 权重和 wasm 也不必再转成文本 JS（总包 24 MB → 约 8 MB）；不能，就由一份清单生成分块 shim，不再手写四处。

**验收**：
- 首帧不慢于 19.0（≤ 220 ms 冷启动），下到第 160 步每步开销 ≤ 6.5 ms（perf e2e 原样保留为门禁）。
- 一屏可以同时有两块可交互的棋盘（e2e）。
- 一盘 160 步的棋，自动存档写入总量 ≤ 100 KB（19.0 是 3.3 MB）。
- 杀进程重开，最后一步和复盘结果都在（覆盖走查的 B1）。
- `app.js` ≤ 300 行；没有模块级可写全局。

## 2 · L 一条路：学习者模型

**依据**：
- 走查：定级结果不影响课程，定级 2125 的人「继续 · 第 1 课」，英文档案一样；谜题不知道你学过什么；新手一盘对局收进 18 道错题，第二天到期 19 道；四种等级分（谜题、这一类、对局、定级）。
- 内容：96 课核心课只有 204 个任务，平均每课 2.1 个，11 课只有 1 个，只有 7 课挂了「接着练」。学一个概念通常要 5–15 个不同局面。
- 顺序：「各子值多少」在走法之前；战术在将军、将死、易位之前。
- 调研：有证据的是**练习量 + 针对个人 + 测验与间隔复习 + 穿插练习**（各约半个标准差）；反馈要讲任务和思路，不讲人；Woodpecker 式战术重复主要对 1600 以下有效（观察性数据）。

**做什么**：
- **L1 技能图**：
  - 约 60–80 个技能节点，从「车怎么走」到「车兵残局的桥」。每个节点挂：一句讲解、3–5 个由易到难的局面、可选的一盘针对性对局、一组残局或开局练习。
  - 顺序重排：走法 → 吃子 → 将军 → 将死 → 基本杀法 → 战术母题 → 开局原则 → 基本残局 → 中局计划。前几课是走子小游戏；第 10 课左右就让新手下第一盘「刚好能赢」的棋。
  - 练习局面从现有的 4 万道 Lichess 题（CC0）、980 道自挖题、168 道手写题里**按母题和难度挑**，补齐每个概念 3–5 个；600 分以下另挖一批。
- **L2 学习者模型**：
  - 每个技能有**掌握度**和**复习日期**（调度器从 SM-2 换成 FSRS，开源、有公开参数）。
  - 证据有三种来源：课和题的作答、**你自己对局里的表现**（复盘发现你漏了捉双，就是一条「捉双」的负证据）、残局和开局练习。
  - 定级直接点亮已经会的技能：定级 1500 的人不会再看到第 1 课。
- **L3 一个队列**：
  - 「接下来做什么」只由模型决定：到期复习 + 一个新技能 + 一盘对局或残局，穿插着来。
  - 每天一份 10–15 分钟的「今日一课」由模型拼好；做完一件自动接下一件。
  - **作业有上限**：一盘对局最多收 3 处进复习（挑胜负未定时你自己的错），每天新进复习不超过 15 道。
- **L4 一个等级分**：对外只显示「你的水平」一个数和一条成长曲线；谜题、对局各自的 Elo 留在模型里，不上屏。
- **L5 阶段目标**：800 → 1000 → 1200 → 1500，每段写清楚要会的技能；到了解锁一位新对手、一组残局。每周一句有证据的话（「上周你漏看捉双 5 次，本周 1 次」），不搞连续天数的愧疚。

**验收**：
- 定级 ≥ 1200 的人，今天页和学习队列里不出现他已点亮技能的课（e2e，三语）。
- 新手在学会马的走法之前，不会拿到需要马的谜题（单测：每道题的母题与技能前置）。
- 一盘对局进复习 ≤ 3 道；任意一天新进复习 ≤ 15 道。
- 每个技能 ≥ 3 个练习局面，难度单调不降（单测，内容校验沿用现在对着引擎核过的做法）。
- 屏上只有一个等级分（布局 e2e 查数字）。
- 课和题的作答、对局复盘的发现都写进事件表，模型能从事件重算出一样的掌握度（单测）。

## 3 · P 一盘像人的棋

**依据**：
- 走查：对手应着恒定 0.27–0.54 s，没有「在想」的状态；皮普 532 多一车加几个兵，30 步收不了官，一盘 140 个半回合；失着提醒一盘 24 次，而且 15.Qa3?? 的提醒在对方已经应了 fxe5 之后才出来，按 Z 退回的是下一对着法；提示第一下就是答案箭头；局中没有一句人话。
- 复盘：「再试一次」在完整报告下面，1440 × 900 要滚动才看到按钮；棋盘落在 7.g4，关键时刻卡片 1/3 却是 13.Ne5（B3）；第 2、3 个关键时刻是输定之后的「小失误」；同一个 Qa3 在三层里出现三次；刷新后复盘丢失（B1）。
- 调研：用户对弱机器人最大的抱怨是「下得很强，然后随机送子」；Allie（ICLR 2025）的思路是连思考时间和认输都学人。Maia-3（2026 年 3–5 月）覆盖 600–2600 分，猜中真人着法 57.1%（Maia-1 是 51.6%），有一个面向 CPU 的 500 万参数版本，**许可证是 AGPL-3.0，需要先核实**（§8 第 4 条）。

**做什么**：
- **P1 像人的对手**：
  - 思考时间按局面和性格来：开局快、复杂局面慢（0.5–6 s，按对手设定可调），落子前棋盘上有一个安静的「在想」状态。
  - 低档也会收官：当胜率 ≥ 90% 时，人类模型的抽样温度收紧到「能赢就赢」（新手也会把多一个车的棋赢下来），但不会算出 20 步杀。
  - 会认输、会提和：输定时按性格认输或接受和棋。
  - 开局寒暄、关键时刻一句反应（「这步我没想到」），每盘不超过 3 句。
  - 如果 Maia-3 许可证可行：一张网络覆盖 600–2600，替换现在的五个分段网络，阶梯重新对下标定。
- **P2 教练在你松手前提醒**（可在新对局里关）：
  - 你拖起或点选一个子、要落到会丢子或被杀的格子时，**在落子前**问一句「对方在威胁什么？」，可以「再想想」或「就走这步」。
  - 按水平节流：同一盘最多提醒 N 次（新手 5 次，1500 以上 0 次，可调）。
- **P3 分层提示**：第一下「对方在威胁什么」→ 第二下「先看将军和吃子」→ 第三下「这里的想法」（母题名）→ 第四下才是要动的子和格子。
- **P4 下棋屏重做**：
  - 棋盘优先，棋盘下面**一条情境条**：对局、复盘、做题各自只放当时要的按钮；着法表是可选抽屉。
  - 评估条只在复盘出现。
  - 教学反馈全部进情境条，toast 只用于回执（「已导出」）。
- **P5 复盘就在棋盘上**：
  - 结束后直接进入：转折点 → 在棋盘上重下（「再想想 / 看答案」在情境条上）→ 还有一处 → 完。最多 3 处，只挑胜负未定时你自己的着法。
  - 完整报告按需打开，同一步只出现一次。
  - 复盘结果存进 `analysis` 表，重开还在。
  - 复盘的发现写进学习者模型（§L2）：漏了捉双，就是一条「捉双」的证据；下一件事里会出现它。

**验收**：
- 对手思考时间：同一档对手在开局 10 步的中位用时 < 中局复杂局面的中位用时；没有一档的思考时间是常数（引擎 e2e 记录分布）。
- 收官：每档对手在胜率 ≥ 90% 的 50 个局面里，60 步内赢下的比例 ≥ 90%（新的 `test-convert.mjs`，进 PR 检查而不只在发布时跑）。
- 失着提醒在对方应着之前出现（e2e：提醒出现时对方还没走）。
- 提示第一下不出现箭头（e2e）。
- 复盘 ≤ 3 处、进复习 ≤ 3 道；复盘落点就是第一张卡；重开后复盘还在（覆盖 B1、B3）。
- 下棋屏可点的控件 ≤ 12 个（布局 e2e 量，19.0 的新对局对话框是 ≤ 20）。

## 4 · F 讲「你这一步」

**依据**：
- 讲解覆盖（14.0 的教练审计口径）：58% 的失误给出原因，32% 说出母题；低分段对局 27% 和 37%；100 句里 25 句只是「更好的是 X」；错的 1 句。
- 讲不了局面：NNUE 给不出可解释的分项，`explain.js` 没有几何证明就不说话，约 42% 的失误因此没有原因。
- 只讲你的错，不讲你漏了什么：「对方在威胁什么」只覆盖挂着的子（`motif.js` `threatOf`）。
- 走查：课上走错只复述题目（第 18 课 Nd6）；残局停下只复述要领，不说「你让出了对王」；名局猜着只有分数，12 着后 98.7 分没有区分度；再试一次第二次错，理由还是原着的那一句（B6）；训练·开局走错后的提示一直留着（B5）。
- 引擎：单线程精简版 NNUE，约 450 节点/毫秒、15 层左右；最轻一级的「?!」两次分析结论一致只有 39–67%。zero:// 没有跨源隔离，wasm 多线程做不了。
- 调研：大模型讲棋的子论断错误率 10.8%（最好的云端模型）到 55.5%（能在本地跑的 8B 模型）；接上引擎也只能降到约 9%。安全的路是**引擎和规则核实过的事实拼成句子**。

**做什么**：
- **F1 一个「你这一步」解释器**，替代各处各写的反馈：
  - 每一步都回答三件事：这一步做到了什么、漏了什么（**落子前对方的威胁**，**落子后哪个子没人保护、哪个子负担过重**）、对方怎么应——并把应着画在棋盘上。
  - 用在所有地方：对局提醒、复盘、再试一次（每次错都讲当前这一着）、课上走错、残局（「你让出了对王」「车离开了第七横线」）、名局猜着（大师这一步的意图）、开局练习（「这步离开了你的开局书，常见的是…」）。
  - 句子仍是模板，事实全部由规则或引擎在棋盘上证明；模板从 19 句扩到覆盖下面 F2 的事实。
- **F2 事实 v2**：
  - 战术：威胁、无保护、超载、引离、拦截（`motif.js` 已有大部分检测，补「落子前的威胁」和「落子后松掉的子」）。
  - 局面（新增，必须在棋盘上可证）：孤兵、叠兵、落后兵、通路兵、王的掩护、开放线、前哨、好坏象；只在引擎评估同时明显变化时才说。
  - 人：「1500 的人这里常走 X」（Maia），用来说「这是一个自然的错」。
- **F3 原生引擎**：
  - 由 Zig 壳启动一个原生 Stockfish 进程（完整 NNUE、线程数 = 核数、大哈希），经现有的异步桥流式收发 UCI；wasm 版留作后备。
  - 3–4 子残局库随应用带（几 MB）；5 子（约 1 GB）做成可选下载。SDK 没有给 WebView 应用起长驻子进程的接口，原生引擎的进程管理在 `main.zig` 里自己写：`std.process.spawn` 接管道、读线程、经现有异步桥（N1）把输出送回网页，残局营的车兵残局用它给出精确判断。
- **F4 名局**：猜着的分数改成「这盘你有 N 步想得和大师一样」，每步给大师的意图和「1500 的人会走什么」的对比。

**验收**：
- 讲解覆盖（沿用教练审计的 28 局语料）：失误给出原因 58% → **≥ 80%**；低分段 27% → **≥ 60%**；只说「更好的是 X」的 ≤ 10%；错的仍 ≤ 1%（对照 100 万节点的深搜抽查）。
- 原生引擎下，常规预算的分析深度 ≥ 20 层；「?!」两次分析一致率 ≥ 85%。
- 课上走错、残局停下、名局、开局，各至少一条 e2e 断言反馈里说到了「你这一步」的事实（不是复述题目）。
- 原生引擎缺失或崩溃时，自动退回 wasm，用户只看到一句「分析会慢一些」（e2e 杀进程）。

## 10 · 落地记录

（边做边记，发布前补齐）

**E4 构建机写死版本号**：所有工作流的 `-latest` 换成今天它实际解析到的镜像（`ubuntu-26.04`、`macos-26`、`windows-2025`），`scripts/test/ci.mjs` 见到任何 `-latest` 就失败（换之前 27 处）。只在发布时才跑的 `build-windows.yml` 在分支上单独跑过一次，确认 windows-2025 能打包。

**P1 Maia-3 核查（§8 第 4 条）：可行，换 Maia-3-5M。**
- 许可证：代码 AGPL-3.0；权重没有单独的许可证，模型卡指回仓库（79M 的卡写明 AGPLv3），没有非商用之类的限制。GPLv3 §13 明确允许与 AGPLv3 作品组合分发；离线应用不触发 AGPL 的网络条款。要做的：随包带 AGPL 文本，转换后的权重标明修改过，并提供源形式（原始 `.pt` + 转换脚本）。推理代码按论文的结构自己写，仍是 GPLv3。
- 结构：PyTorch transformer（8 层、64 个格子 token），不是 lc0 格式；**一张网络覆盖所有等级分**（双方等级分是连续输入，训练覆盖 600–2600 及两端）；输出着法分布、胜和负，另有一个思考时间的检查点。
- 速度（单线程实测）：PyTorch 8.7 ms、onnxruntime 7.7 ms、onnxruntime-web WASM SIMD 27 ms 每次评估——都在现在 Maia-1 的 50–200 ms 之内。fp16 约 10 MB，比现在五张网合计 11.5 MB 还小。
- 质量（论文表 1）：猜中真人着法 Maia-3-5M 55.4%、Maia-2 52.0%、Maia-1 51.6%。
- 做法：构建时转换权重；自己写 JS/WASM 前向（不带 11 MB 的 onnxruntime-web），对着 PyTorch 做一致性测试；1100 以下五档直接传低等级分，不再靠温度和下限；阶梯重新对下标定。约 1–1.5 周。
- **接入（2026-11-06）**：`scripts/gen-maia3.py`（开发时，要 PyTorch）把钉死版本的 `maia3-5m.pt` 转成 `third_party/maia3/maia3-5m.f16`（10.46 MB，fp16，线性层转置）+ 22 KB 的 JSON 头，AGPL 文本与 NOTICE 随附；前向在 `src/app/services/maia3/`（自己写的 JS，矩阵乘法是 2.7 KB 的 wasm SIMD 内核 `kernels.c`，另有纯 JS 后备）；`maia3Backend({ analyst })` 接进 `EngineService`：`humanMoves(fen, rating, history)` 是网络的分布，`bestMove` 对有等级分的 profile 按温度 / top-p 抽样，分析仍归 Stockfish。一致性（`scripts/app/maia3-parity.mjs`，60 个局面、600–2600、两种颜色、真实历史、升变 / 易位 / 吃过路兵）：首选着法 60/60 相同，最大 KL 2.6e-6，WDL 差 ≤ 7e-4。Chromium worker 里每次评估中位 38 ms、p90 40 ms，冷启动约 80 ms，wasm 堆 21.9 MB（Node：wasm 41 ms，纯 JS 418 ms）。还没做：默认对手换成 Maia-3、阶梯重新标定、1100 以下的档位直接传低等级分。

**A5 / E1 SDK 核查（读 0.10.1 与 0.11.0 的源码，Linux 上对 0.11 试编译）**：
- zero:// 的能力（macOS `appkit_host.m` 7694–7748、Windows `webview2_host.cpp` 5406–5426；两版逐字节相同）：同源，所以 `<script type="module">`、静态 `import`、`import()`、`fetch` 文本与二进制、`WebAssembly.instantiateStreaming` 都可以；`.wasm` 是 `application/wasm`，`.js/.mjs` 是 `text/javascript`；响应只带 Content-Type，**没有 COOP/COEP，所以没有 SharedArrayBuffer**，wasm 多线程做不了（原生引擎是唯一的多线程路）。`design-constraints.md` 里「zero:// 不能 fetch」在源码里找不到依据。
- 陷阱：`spa_fallback = true` 会把缺失的二进制文件答成 200 的 `index.html`，读到的是坏数据——改用真二进制文件时要关掉它。
- 待真机探针确认：Windows 上 zero:// 的 Worker 是否被拦截（过滤器没设 RequestSourceKinds）；macOS 11 的 Safari 14 对 module worker 的支持。退路：页面 `fetch` 字节后交给 blob worker。
