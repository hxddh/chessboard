# 7.4 · 先让引擎在应用里真的跑起来，再补 7.2–7.3 的接缝

写在 7.3.0 发布之后。这份文档的依据有三种：代码走读（7.2 / 7.3 改动过的
模块逐个读），文档核对（README、docs/、release notes 与代码逐条对照），以及
**把应用在无头 Chromium 里当作一个新用户真的用一遍**——首启、「我会下棋」、
对 Stockfish 走四步、「我是新手」进第 1 课、做题页、记录页，1400×900 与
390×844 各一遍，外加一组贴近正方形的窗口尺寸。

规矩和前几版一样：每条写**依据**（核过的代码、跑出来的数、截下来的图），
每条有**验收**，发布前补**落地记录**。

复查当天的基线见 §6。

## 0 · 结论先行

1. **P0：页面的 CSP 挡住了 Stockfish 的 WebAssembly。** 在 Chromium（Windows 的
   WebView2）和 WebKit（macOS 的 WKWebView）里，引擎都一次也启动不了。人机对局停在
   「引擎思考中…」，而且一直停在那里：等了 45 秒，界面上没有出现任何一句
   错误提示。复盘、分析、棋谱库逐局分析、挖错题，凡是要引擎的功能都跟着
   失效。**应当马上单独发一个 7.3.1。**（后来的决定：不单独发，全部随 7.4.0 一起发布，见 §7。）
2. 这个问题能从 6.0 活到 7.3，原因和 7.2 的「接实战」完全一样：**8 个浏览器
   e2e 都把 `js/engine-src.js` 换成了一行注释**，引擎相关的测试又全在 node
   里跑。所以没有一条测试在真实页面、真实 CSP 下启动过引擎。真机走查的最后
   一次记录停在 5.2.0，那时还没有 CSP。
3. 除此之外，7.4 该做三件事：修 7.1–7.2 留下的**七条数据接缝**（其中一条会
   让「打开」和「再深一遍」作用到另一局上）；把 7.3 的竖窗修法**补完**（在
   一段真实可达的窗口尺寸上，棋盘仍然只有 210px）；把**文档追上代码**
   （README 缺 7.1.1–7.3.0 三节，两份被引用的文档根本不存在）。

## 1 · P0（7.3.1）：引擎在页面里起不来

### 依据

`src/web/index.html:10`：

```
script-src 'self'; … worker-src blob:;
```

引擎是一个 blob worker（`engine.js` 的 `init()`：`new Worker(blobUrl)`）。在
Chromium 里，blob worker 继承创建它的文档的 CSP；而 `script-src` 里既没有
`'wasm-unsafe-eval'` 也没有 `'unsafe-eval'`，`WebAssembly.instantiate` 因此
被拒。

同一个页面、同一步 1. e4，实测三次：

| index.html 的 CSP | 结果（等 12 秒） |
|---|---|
| 原样 | `Aborted(CompileError: WebAssembly.instantiate(): Refused to compile … 'unsafe-eval' is not an allowed source …)`；状态药丸一直是「引擎思考中…」，45 秒后仍然如此，页面上没有任何报错 |
| 去掉 CSP | 引擎应 1… c5 |
| `script-src 'self' 'wasm-unsafe-eval'` | 引擎应 1… c6 |

复现脚本就是 `test-*-e2e.mjs` 的那个静态服务器，只是**不替换**
`engine-src.js`（先跑 `node scripts/gen-engine-src.mjs` 生成它）。

**WebKit（macOS 的 WKWebView）同样中招。** 复查时本地没有 WebKit，这一条是
由下面那条 e2e 在 CI 的 webkit 矩阵上回答的：原样页面报「Refused to create a
WebAssembly object」，不应；去掉 CSP，0.84 秒就应（数字见 §6）。

### 为什么没人发现

- `grep engine-src scripts/test-*-e2e.mjs`：八个文件，八处都是 `res.end("// stub")`。
- `test-engine` / `test-analysis` / `test-strength` 在 node 里直接起 wasm，那里
  没有 CSP。
- CSP 是 6.0 Q1.2 加的，当时的验收写的是「`index.html` 含 CSP 且 e2e 无 CSP
  违规」。**e2e 当然没有 CSP 违规：它根本没加载引擎。**这条验收和 7.2 那条
  「精确到表达式的源码正则」是同一个形状。
- `manual-check.md` 里唯一的真机记录是 5.2.0（2026-09-06），J–O 六节一次都
  没走过。

### 做什么

1. `script-src 'self' 'wasm-unsafe-eval'`。只加这一项，**不要**加
   `'unsafe-eval'`。
2. **引擎启动失败必须说出来。** 现在 `init()` 被拒以后只做了 `teardown()`，
   对局就停在「引擎思考中…」。改成：启动失败时状态药丸回到可走状态，弹一条
   常驻提示（「引擎没能启动 · 复制诊断信息」，复用 5.1 那条未捕获异常横幅），
   并且让提示/分析按钮说明原因，而不是一直转。
3. **一条真正启动引擎的浏览器测试**：`test-engine-e2e.mjs`。服务**真的**
   `engine-src.js`，走 1. e4，断言 15 秒内棋谱出现第二手，同时断言页面上没有
   `pageerror`。把它加进 `checks.yml` 的 chromium / webkit 矩阵和
   `release.yml` 的发布门禁。
4. `manual-check.md` 最前面加一行 **A0：新装的应用，人机走一步，引擎要应**。
   这是整个应用最核心的一件事，却不在清单上。

### 验收

- 先红后绿：新 e2e 在改 CSP 之前红（把错误原文记进落地记录），改后绿，
  chromium 与 webkit 都要跑。
- 把 `engine-src.js` 换成坏的 wasm 再跑一次：页面在 30 秒内给出可读的失败
  提示，状态药丸不再停在「思考中」。

## 2 · 七条数据接缝（7.4）

逐条核过代码。标了「已跑」的，是用真实模块在 node 里复现过的。

### D1 · 棋谱库列表：点 A 局打开的是 C 局（高，已跑）

`library-ui.js:629/643` 的按钮带的是 `data-lib = String(i)`，也就是这一局在
`store.session.library` 里的下标。`reconcile` 用 `g.id` 作 key，而签名
（`:684`）里没有 `i`。`library.js:164` 的 `addGames` 每次导入都会按新到旧
重排，下标跟着变，可旧行的签名没变，所以被原样复用。

复现（真实的 `reconcile` 与 `addGames`）：库里有 A、B 两局，先渲染一次列表，
再导入一局更新的 C，然后重新渲染。A 行的 `data-lib=0`，指向的已经是 C。于是
**点 A 打开的是 C；点 A 的「再深一遍」，改写的是 C 的分析和 C 的错题。**
「打开」这一半从 7.1 起就有，「再深一遍」是 7.2 加上的同一条缝。

做：按钮改带 `g.id`，点击时按 id 查；或者把 `i` 放进签名。**选前者。**
下标是这一类问题的根：`renderLibList` 的注释已经为「过滤后的下标」付过一次
学费了。

验收：library e2e，列表渲染后导入新局，再点旧行，棋盘上是那一局。

### D2 · 开局书：一着非法，整份文件被拒（中，已跑）

`repertoire-ui.js:90` 对整份文本只调一次 `parsePgn`，碰到一着非法就整份抛
错。棋谱库的导入器（`library-ui.js:167`）是先 `splitGames` 再逐局解析的。

做：复用 `splitGames`，逐局解析，坏的局计数并在提示里说出来。

### D3 · 开局书：长线替换短线时，谎报「上限 400 条，退出了 N 条」（中低，已跑）

`addLines([], ["e4 e5", "e4 e5 Nf3"])` 返回 `added: 2, dropped: [1]`。书里其实
只有一条线，界面却弹「触顶」。

做：「被更长的线替换」和「因为上限被挤出去」分开计数，只有后者才弹 `rep.dropped`。

### D4 · 开局书导入是 O(n²)，而且在主线程上跑（中低，已跑）

`repertoire.js:143–149` 每进一条线都对整个 `out` 做前缀比较，400 条的上限
要到最后才截。20000 个叶子的 PGN 实测要 90.8 秒，界面一直冻着。

做：先按前缀建一棵 trie，一次遍历就能得出叶子。能在进循环之前截到上限的，
就先截。

### D5 · 更新或清空开局书之后，屏幕上的那道题还会写进复习队列（中，仅读代码）

`repertoire-ui.js:100/117` 只清了 `solved` 和 `missed`，没有碰
`store.session.puzzle`；`app.js:2792` 的 `markMissed` 也不检查这道题还在不在
书里。结果是 `owedNow()` 永远多算一道端不出来的题。47481f7 修的就是这一类
问题，这里是它漏掉的那扇门。

### D6 · 学习数据导出时带上了开局书的复习项，却没带开局书本身（中低，仅读代码）

`learning.js:29` 的 `LEARNING_KEYS` 里没有 `repertoire`，但 `puzzles.missed`
里有 `rep-*`。在另一台机器上导入后，就多出一批永远做不了的复习项。

做：`repertoire` 放进 `LEARNING_KEYS`；导入时按书过滤 `rep-*`。

### D7 · 「再深一遍」和后台分析会被棋盘上的任何一步打出空洞（中，仅读代码）

`app.js:1352` 的 `invalidateEngine` 每次改棋局都会调 `ChessEngine.cancel()`，
在途的那次库分析搜索因此返回 `null`；`library-ui.js:227` 把 `null` 当成
「没有评估」继续往下走，最后照样按 `budget=400` 存档。这一局从此不再出现
「再深一遍」，那一处的 `??` 也得不到修正。如果引擎挂掉，情况更糟：一整局
全是 `null` 的记录，会盖掉原来 200ms 的好数据。§1 的 P0 正好就是「引擎挂掉」。

做：库分析拿到 `null` 时，这一手重试一次；仍然是 `null` 就整局放弃、不写回
存档。**绝不用更差的结果覆盖更好的结果。**

### 另外两条（低）

- **「接实战」不先问一声就清掉棋盘上没下完的对局**（`app.js:3434`）。
  `requestNewGame` 在有着法时是会先确认的。这个按钮到 7.2 才第一次真正按得动，
  所以这是一条新近才暴露出来的行为。
- 库列表行的签名里没有语言，切换语言以后行文字不刷新（7.1 就有，没在浏览器
  里跑过）。

## 3 · 7.3 竖窗修法的补完（7.4）

### 依据

实测棋盘边长（Chromium，面板开 / 关）：

| 窗口 | 面板开 | 面板关 |
|---|---|---|
| 520×520 | 442 | 442 |
| **540×543** | **210** | 465 |
| **559×562** | **229** | 484 |
| 560×900 | 408 | 514 |
| **600×610** | **251** | 532 |

- 宽 520–559、长宽比落在 (0.99, 1) 之间的窗口，三条媒体查询**一条都不命中**，
  于是掉回桌面布局。7.3 声称已经消掉的那道断崖还在，只是换了个位置。而这些
  窗口**真实可达**：`app.zon` 允许的最小窗口就是 520×520。
- 宽 ≥560 的竖窗走的是旧抽屉，面板一开棋盘就缩小（560×900：514 → 408）。
  7.3 立下的「开合面板，棋盘大小不变」只在 <560 的一侧成立。
- v7-3-plan §1 自己定的「任何视口、任何面板状态，棋盘 ≥260px」，
  540×543 与 600×610 两处都没达到。

### 反过来看

**390 / 360 这两档宽度，已发布的桌面应用根本到不了**：`app.zon` 的
`min_width = 520`。7.3 把 P0 的实测和测试都放在了用户够不着的尺寸上，而用户
够得着的那一段（520–600、接近正方形）反倒没有测。`manual-check.md` O1 让人把
窗口拖到「宽 ≈ 400」，在真机上同样做不到。

### 做什么

1. 三条媒体查询合成**一张按棋盘边长决策的表**：由 JS 按「棋盘在当前布局下
   能有多大」来选布局，不再用三条互相留缝的长宽比区间。`SHEET_QUERY` 那个
   常量保留，作为 CSS 与 JS 共用的单一来源。
2. layout e2e 的竖窗组从 360/390/430 换成**真实可达的**
   520×520 … 600×620 网格（步长 10），面板开关各一遍，断言棋盘 ≥260，且开合
   前后大小相等。
3. `manual-check` O1 改成「宽 ≈ 540、高 ≈ 900」。
4. v7-3-plan §1 第 4 条（棋盘下方约 400px 空白，拿来放一行走子、时钟和评估条）
   当时既没做也没写进落地记录。截图 390×844：棋盘以下全空，只有一个 toast。
   这一版做掉，或者在文档里明确写「不做」。
5. 390×844 的顶栏里，「行」徽章压在「黑」字上（截图为证）。

## 5 · 产品层面：走一遍之后的判断

这些判断来自实际点一遍，不是来自读代码。

- **首启弹窗是对的。**「我是新手 / 我会下棋 / 先看看棋盘」三条路清楚。选
  「我会下棋」之后引擎（修好 CSP 以后）1–3 秒应一手，开局名（C23 · 主教开局）
  当场出现，送后的那一步当场有「可能是严重失误 —— 可按 Z 悔棋」提示。这条
  主路径体验很好，**前提是引擎起得来**。
- **「今天的训练」卡片读不顺。** 两列文字「上一课 新的 / 课程的下一课」
  「来一盘 / 今天还没下过棋」挤在一起，第一眼看不出哪个是步骤名、哪个是
  说明，而它出现在对局、教学、做题三页的最上方。它应该用 7.3 §4A 定下的
  那三种行之一。
- **§4E 的宽面板放到做题页，得不偿失。** 1400×900 的做题页，面板放宽到
  564px 以后，内容只有一个题面和十个题型按钮，下半截整片是空的，棋盘却因此
  缩小了。这个宽度对记录页是对的，对做题页不是。建议做题页退回原宽度，
  除非这一栏能放上真正需要宽度的东西（例如这道题的来源局缩略）。
- **顶栏和面板里各有一个「答案」按钮**（做题页），重复。
- 查过、没问题：走子列表的棋子是图形，`textContent` 里没有字母，但
  `writeSan` 把完整 SAN 挂在 `aria-label` 上，屏幕阅读器读得到「Bc4」。

文件对话框），都要在这份文档的 §1 里写明：**哪一条测试负责把它真的跑一次**。
这一条填不上，就等于这个功能没有测试。

    'wasm-unsafe-eval' is not an allowed source of script`，不应；去掉 CSP 0.84 秒应。

## 7 · 落地记录（7.4.0）

**发布方式改了。** §6 原计划先单独发一个 7.3.1，再做 7.4。后来决定全部并进
7.4.0 一起发，没有 7.3.1 这个版本。代码注释里写的也是 7.4。

### §1 引擎（P0）

- `index.html` 的 CSP：`script-src 'self' 'wasm-unsafe-eval'`，注释写明了为什么。
- `scripts/test-engine-e2e.mjs` 用三张页面检查：
  - **原样**：断言人机走 1. e4 后引擎应一手，页面没有报错。
  - **去掉 CSP**：诊断对照，只打印不断言。
  - **坏 wasm**：断言顶栏不再显示「思考中」，出现常驻提示，worker 数有上限，
