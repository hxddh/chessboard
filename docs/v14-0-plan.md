# 14.0 · 评估：下一个大版本做什么

写于 13.0.0 发布之后（2026-10-17，第二稿）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

第一稿从「13.0 的 Maia 还能用在哪」出发，答案自然都是 Maia。第二稿不预设方向，先看用户实际用起来哪里不顺，再决定做什么。第一稿量过的数据都留在附录。

---

## 依据

### 1. 一次「新用户」走查（2026-10-17）

一个独立的子任务把应用当新用户走了一遍：全新存储、1440×900、中文为主，加一遍英文。它没读过任何计划文档，留下 100 张截图（不进仓库）。

走的路线：首次启动 → 今天 → 上一课 → 做题（用提示、故意错一次）→ 和电脑下十步后认输 → 看结果卡与复盘 → 棋谱库导入、打开、分析 → 开局浏览器 → 我的开局书 → 我的 → 设置。

**做得好的**：设置页、新对局对话框、英文界面（五个主视图没有漏翻的中文）、开局书背错时的那句话（「这一步本身不坏……书上走的是 d5」）。

**最影响体验的十处**（按影响排）：

| # | 在哪 | 看到了什么 |
|---|---|---|
| 1 | 谜题 | 唯一的帮助是「答案」：一下给出整步，扣 51 分、记为错，题却标「解出」。「下一题」按列表顺序：错了一道 1908 的，下一道是 1000 的。定级中的分数跳得太大：一步杀 +57，错一次 −150 |
| 2 | 复盘 | 白方大优（+6.6）时认输，教练说「这盘你没有哪一步让胜率明显下滑」；关键时刻全是**对手**的失误，还给对手的失误配「再试一次」。引擎线的排版是「1+6.6 … g8O-O-O」 |
| 3 | 棋谱库 | 导入后要手填自己的名字，不提示 PGN 里出现最多的名字；只能选文件，不能粘贴；卡片上的状态字超出边框 |
| 4 | 开局浏览器 | 从棋谱库打开时停在那局的最后一个局面，显示「没有对局」；「大师」其实是 Lichess ≥ 2200 的对局，和棋率没有标注 |
| 5 | 开局书 | 生成后直接跳进谜题界面里背，旁边还挂着谜题等级分卡片；重开应用后背到一半的进度没了 |
| 6 | 连续性 | 定级题、背开局做到一半，重开就没了；第一次的「你下过棋吗」问题关掉窗口就不再问；首次启动落在下棋页而不是今天页 |
| 7 | 启动 | 上次停在和 Maia 档的对局里时，冷启动有 375 ms、504 ms 两段长任务，而且立刻加载 2.2 MB 的 maia-1300.js——哪怕你只是想看今天页 |
| 8 | 课程 | 字多，全尺寸棋盘；学完一课只有一个提示条；「下一课」跳过时不留痕，今天页随后说「继续第 7 课」 |
| 9 | 我的 | 大块空白；日历没有图例；已得成就的图标是一个实心圆（浅色、深色主题都是）；做了 3 题就写「本周正确率 33%」 |
| 10 | 确认框 | 棋盘是空的、或对局已经结束存好了，还问「将替换当前对局？」 |

**确定的 bug**（都有复现步骤；其中 3 条我对着代码或截图核过）：

1. 评估条的数字被左侧栏挡住，「+6.6」只剩「.6」。截图核过。
2. 「分析一局」粘贴一局无头信息的 PGN，会被当成和上一个电脑对手下的棋：对阵条写着尼可 1397，结果写「你赢了」。不进战绩。
3. 棋谱库卡片上「已分析 0 局 · 待分析 2 局」超出卡片右边。
4. 未认领的对局，列表上显示成「结果 · 黑方 · 白方」，顺序反了。`library-ui.js` 的 `libraryLabel` 核过。
5. 已得成就的图标看不见。
6. 「已解 x/N」里的 N 在几次启动之间变化（1386 → 1391 → 15523）。
7. 课程的提示条「先看一遍演示」重开后出现在谜题页。
8. 从棋谱库打开开局浏览器，停在终局局面。
9. 导入的对局，白方名字被结果条压住；对阵条旁边浮着「0」「1」。
10. 今天页的「题」进度和「已解」不一致：做了六道定级题，今天页写 1/5，已解还是 0。

**量到的时间**：
- 冷启动首次绘制 752 ms，热启动到今天页 334–392 ms。
- 视图切换 14–115 ms，换一道题 110 ms。
- **最慢的是复盘分析**：20 步的棋 9.3 秒，39 步 10.8 秒。期间面板有进度，但棋盘不能用。

### 2. 复盘讲解覆盖得不够（`docs/measured.json` `coachCoverage`、`motifCoverage`）

- 引擎标出的 ? / ??，能说出战术原因（捉双、牵制、串击……）的只有 **23–40%**。
- 其余只有一句「更好的是 X」，或者「胜率从 a 掉到 b」。
- `motif.js` 只认五种母题，不确定就不说。这是故意的，说错比不说更糟；但结果是大多数失误没有解释。

### 3. 第一稿量过的（附录 A）

- Maia 用于「大家都会错」题、开局书、开局浏览器、稳健档：都可行，数据在附录 A。
- 但走查里没有一条问题是「题不够对症」或「对手不够像人」；用户碰到的是**流程和讲解**。

## 0 · 结论先行

| # | 方向 | 一句话 | 依据 | 代价 |
|---|---|---|---|---|
| **A** | **每天用起来顺**（推荐，主线） | 修完走查里的 10 个 bug，把十处摩擦里的 1、3、4、5、6、7、10 做掉 | 走查截图 | 中 |
| **B** | **复盘讲你自己**（推荐，跟着 A） | 复盘以「你」为中心；讲解覆盖从 23–40% 提到 ≥ 60%；分析不再锁住棋盘 | 走查第 2 条；`coachCoverage` | 中 |
| C | 按你的水平练（第一稿） | 「大家都会错」题、开局书对手应着、浏览器「同分段的人」、稳健换 Maia | 附录 A 的实测 | 中 |
| D | 课程更像游戏 | 学完有星级与小庆祝、目标格高亮、跳过要留痕 | 走查第 8 条 | 中到大 |
| E | 工程 | 首屏余量（课程正文 96 KB 移出首屏）、Node 26、app.js ≤ 5,200 | 附录 A | 小 |

**推荐 A + B + E**。理由：
- 这三项都直接来自用户走一遍就会碰到的问题，不是「我们还能做什么」。
- C 是好的增量，但建立在 A、B 之上。题出得再对症，提示还是只有「答案」；讲解还是只有「更好的是 X」，效果有限。
- D 和 A 第 8 条重叠；先修「跳过不留痕」这类流程问题，星级、动画放下一版。

## 1 · A 每天用起来顺

**做什么**：

- **修 bug**：上面 10 个，每个加一条回归测试，静态或 e2e。
- **谜题提示分级**：
  - 「提示」先给「动哪个子」，再给「走到哪」，最后才给「答案」。
  - 用到第一级不算错、扣分减半；看答案算错，不标「解出」。
  - 「下一题」按你的谜题等级分挑最近的未做题，不按列表顺序。
  - 定级中（RD 大）的单题涨跌封顶 ±40。
- **棋谱库导入**：
  - 导入后列出 PGN 里出现最多的三个名字，一点就认领。
  - 支持粘贴 PGN 文本。
  - 卡片上的字不溢出。
- **开局浏览器**：
  - 从任何地方打开都停在当前局面；当前局面没有数据时，退回最后一个有数据的局面，并说明。
  - 「大师」改名「高分棋手（Lichess ≥ 2200）」。
  - 胜 / 和 / 负三段都标清。
- **开局书**：背书有自己的界面——左边棋盘，右边这条线和进度，不挂谜题等级分。背到一半的进度存下来。
- **连续性**：
  - 定级题、背书、课程做到一半的，重开回到原处。
  - 首次的问题没回答就下次再问。
  - 首次启动落在今天页。
- **启动**：引擎和 Maia 权重只在第一次需要走棋时加载，或者空闲时预载，不在启动时同步加载。
- **确认框**：只有「有没下完、没存的对局」才问。

**验收**：
- 10 个 bug 各有一条测试，修之前失败、修之后通过。
- 走查的同一套脚本重跑：十处摩擦里做了的那几处截图对比。
- 启动：上次停在 Maia 对局时，冷启动没有 > 200 ms 的长任务，启动时不请求 `maia-*.js`。perf e2e 记前后。
- 谜题：用第一级提示后不扣满分，看答案不标「解出」；「下一题」与你的分数相差 ≤ 150。

## 2 · B 复盘讲你自己

**做什么**：

- **以你为中心**：
  - 关键时刻先列你的失误，对手的失误放在后面，不配「再试一次」。
  - 结果卡与总结句识别「优势局面认输」（认输时胜率 ≥ 70%）、「赢棋被逆转」「和棋局面超时」这几类，各说一句。
- **讲解覆盖**：
  - `motif.js` 从五个母题扩到这几种：底线、闪击、过载、被困的子、无保护的子（白送）、一步杀 / 两步杀威胁。
  - 每种都要「几何事实确凿」才开口，规则沿用。
  - 目标：? / ?? 能说出原因的从 23–40% 提到 ≥ 60%，误报率由人工抽查 50 条核对。
- **分析不锁棋盘**：分析在后台跑，棋盘可以照常走、看；已分析到的着法先显示标记。20 步的棋 ≤ 6 秒出结果，现在 9.3 秒。
- **引擎线排版**：分值和着法分开；易位写成 O-O 而不是 g8O-O-O 这类拼接。

**验收**：
- `coachCoverage` / `motifCoverage` 重量，写进 `docs/measured.json`，≥ 60%。
- 抽查 50 条，错误解释 ≤ 2 条，记进 `docs/coach-audit-14.0.md`。
- e2e：优势认输的那局，总结句说的是认输。
- 关键时刻的第一张卡是你的失误。

## 3 · E 工程

- **首屏余量**：课程正文 `lessons.js`（96 KB）拆成「课名、单元、目标」（首屏）和「步骤与局面」（开课时按需加载），和第三部 `chunk-lessons-adv.js` 同一种做法。目标腾出 ≥ 20 KB，预期约 80 KB。
- **Node 26**：10-28 进 LTS 后，CI 换到 26。
- **app.js**：上限 5,387，只降不升；目标 ≤ 5,200。

**验收**：CI 绿；首屏包 ≤ 942,990 字节；perf e2e 首帧不升。

## 4 · 13.0 真机反馈

真机验收的结果一回来，先修，按 13.0.x 单独发：Maia 档在 Mac / Windows 上的应着节奏、「人会怎么走」的数字，以及 11.0 / 12.0 积压的外壳、触感、Mica。

## 8 · 需要你拍板的

1. **方向**：按推荐做 **A + B + E**？还是换成 C（按水平练）、D（课程游戏化），或者自己挑组合？
2. **谜题提示扣分**：推荐第一级提示扣一半、看答案算错。也可以提示完全不扣分，只是不计入等级分。
3. **复盘分析的目标时间**：推荐 20 步 ≤ 6 秒，现在 9.3 秒。要更快就得降低默认精度。
4. **证书**：现在有 Apple 开发者证书或 Windows 签名证书了吗？有的话签名、公证、自动更新可以并进这一版，工程量小。
