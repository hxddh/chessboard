# 7.5 · 引擎第一次真的在用户手里跑：把缝补上，把门装在真壳上

写在 7.4.0 发布之后、动手之前。规矩和前几版一样：每条写**依据**（核过的代码、
跑出来的数），每条有**验收**，发布前补**落地记录**，做到的和没做到的都逐条写。

---

## 0 · 结论先行

7.4 修好的不是一个功能，是**所有要引擎的功能**：人机、提示、失着提醒、分析 /
精析 / 持续分析、棋谱库逐局分析、挖错题、教学对练。从 6.0 到 7.3，这些在用户
机器上一次都没有真正跑起来过，而当时的浏览器测试都把引擎换成了空桩。

所以 7.5 要回答的第一个问题是：**这些功能接上真引擎以后，到底对不对？**
这一版的复查先用真引擎把它们逐个走了一遍（§5）。结论是：它们都能用，没有
找到阻断性缺陷。

但 7.4 暴露的结构性问题还在：

1. **发布门禁里没有一步跑在真壳上。** CI 用 Chromium / WebKit 代替 WebView2 /
   WKWebView，从来没有启动过打包好的应用。6.0 到 7.3 的引擎停摆正是从这条缝
   漏出去的。真机走查的最后一次记录还停在 5.2.0。**这是 7.5 的 P0（§1）。**
2. **引擎相关的行为测试，只有 `test-engine-e2e` 一条接的是真引擎**，其余都跑在
   空桩上。空桩证明不了「接上真引擎以后还对」（§2）。
3. **中文和日文界面里，大多数开局名是英文。** 这次导入的 8 局真实棋谱里，
   有 7 局显示英文开局名（§3）。

## 1 · P0：发布门禁里要有一步跑在真壳上

### 依据

- `build-macos.yml` 在 `macos-14` 上真的编出了 `.app`；`build-windows.yml` 在
  `windows-latest` 上编出了 `.exe`。但两条流水线编完就打包上传，**一次都没有
  启动过它**。
- 7.4 的 CSP 问题，是靠「Chromium ≈ WebView2、WebKit ≈ WKWebView」这个近似
  抓到的。这个近似这次成立了，但它仍然只是近似。WebView 特有的问题，例如
  自定义协议 `zero://`、原生桥、文件对话框、窗口生命周期，它都看不见。
- `manual-check.md` 里，J 到 O 六节从来没有人走过；7.4 新加的 A0 也还没走。

### 做什么

1. **先做一次调研（半天）**：GitHub 托管的 macOS / Windows runner 能不能打开
   这个应用的 WebView 窗口。macOS runner 有已登录的图形会话；Windows runner
   上 WebView2 运行时是否可用、有没有交互桌面，要实测才知道。**调研的结论要
   写进落地记录，做不到也要写。**
2. 调研可行的话，加一个**自检入口**：环境变量 `CHESS_SELFTEST=1` 时，`main.zig`
   用 `index.html?selftest=1` 打开页面。页面在这个模式下启动引擎、对初始局面
   要一手棋，再通过原生桥把 `{ok, move, ms, err}` 写到约定的路径上，然后退出。
3. 两条平台构建流水线在打包之前运行 `CHESS_SELFTEST=1 ./Chessboard`，限时
   90 秒，结果文件里 `ok !== true` 就判失败。发布门禁要等这两步都通过，才打
   tag、发布。
4. 调研不可行的话，退而求其次：发布说明模板里加一条「A0 真机结果」必填项，
   `release.yml` 的发布说明里没有这一行就不发布。

### 验收

- 在自检分支上故意把 CSP 改回 7.3 的样子，两条平台流水线都应该红，而且错误
  信息里带着 `CompileError`。
- 改回来以后两条都绿，同时记下 `ms`（真壳里引擎第一次应着要多久）。

## 2 · 把「真引擎走查」固化成测试

### 依据

这次走查（§5）是用一个临时脚本做的，所有数字都来自真引擎。除了
`test-engine-e2e`，其余 8 个浏览器测试都把 `engine-src.js` 换成了空桩。
所以：

- 引擎给出的数据形状一旦变了（例如 `analyze()` 的返回值），空桩测试照样是绿的；
- 「引擎太慢，某处超时」这类问题，空桩测不出来；
- 7.4 修的是「引擎起不来」，而「起来了、但结果没接对」目前没有测试守着。

### 做什么

新增 `scripts/test-engine-flows-e2e.mjs`，用真引擎，每个场景只断言关键结果：

| 场景 | 断言 |
|---|---|
| 人机（新手档） | 20 秒内应着；「提示」给出一手合法的棋 |
| 失着提醒 | 走出 e4 e6 Qh5 Nc6 Qxf7+ 之后，出现 `mm.blunder` 提示 |
| 分析 / 精析 | 至少 10 半着的对局有 `?` 或 `??` 标注；精准度一行不为空 |
| 持续分析 | 打开后 5 秒内出现主变 |
| 棋谱库 | 导入 3 局并分析，每局 `an.scalars` 里没有 `null`，打开一局时引擎不重跑 |
| 教学对练 | 卢塞纳走 Rc1–d1+ 之后，引擎应一手 |

跑一遍大约 4 到 6 分钟，接进 `checks.yml` 的双引擎矩阵，也接进发布门禁。

### 验收

每个场景都要先红后绿：在本地把对应接线弄断（例如让 `analyze` 返回 `{}`），
对应的那一条就红。

## 3 · 开局名：按「族」本地化

### 依据

- `localName()`（`eco-lookup.js`）只翻译开局书里的约 195 条线。开局表里的
  3810 个局面，除了这些以外都直接显示 lichess 的英文名。
- 这次把 8 局真实名局导进棋谱库，有 7 局显示英文，例如
  `C54 Italian Game: Giuoco Piano, Greco's Attack`、
  `C33 King's Gambit Accepted: Bishop's Gambit, Bryan Countergambit`。
  人机对局里也出现过 `B20 · Sicilian Defense: Bowdler Attack`。
- 名字按冒号前的「族」来数，一共只有 **149 个族**，其中前 **49 个**就占了全部
  条目的 90%（西西里 391、西班牙 235、法兰西 212、后翼弃兵拒绝 198……）。

### 做什么

- 给这 149 个族名配上中文和日文译名（新增 `openings-family-{zh,ja}.js`）。
- `localName()` 查不到整条译名的时候，先把族名替换成本地语言，冒号后面的
  变例名保留英文，例如「意大利开局：Giuoco Piano, Greco's Attack」。
- 静态测试加一条：表里出现的每个族名，在两种语言里都要有译名。以后 lichess
  表更新、多出新族的时候，这条测试会红。

### 验收

同样这 8 局，中文界面下没有一条开局名是整条英文；族名覆盖率 100%，由测试
守着。

## 4 · 7.4 留下的和这次顺手看到的

- **失着提醒用的是「成功」样式。** `coachAfterEngineReply()` 调用
  `toast(tf("mm.blunder", …))` 时没有传类型，所以落在默认的 `t-ok`（绿色、
  成功）。其他警告用的是 `fix` 或 `fault`。`ok` 这一档只显示 2.2 秒
  （`TOAST_MS.ok`），可这条提示要人去按 Z 悔棋，2.2 秒不够看完再决定。改成
  `fix`（4.2 秒），并在 layout e2e 里断言这条提示的样式类。
- **新局不会重试引擎**（7.4 §7）：引擎起不来以后，点「新局」应当顺带重试一次，
  失败了也只提示一次。
- **`pgn-parser` 在主线程上解析大文件**（7.4 §7）：6720 个叶子要 715ms，两万个
  叶子大约 2 秒，这期间界面冻住。可以挪进 worker，或者按局切片、分批 `await`。
- **README 必须有当前版本那一节**（7.4 §4 里说要做、实际没做）：在
  `manifest-check` 里加这条断言。
- **棋谱库满载时要跑多久。** 8 局在 200ms 快扫下用了 102 秒；按这个速度，
  500 局的上限大约要一个半到两个小时。README 或诊断页应当如实说出预计时长，
  并且确认中途关掉应用再打开，能从断点接着分析。这一条写过（6.0），但从来
  没有在真引擎下验证过。

## 8 · 落地记录（7.5.0）

### §1 真壳自检（P0）

**调研结论：可行。** GitHub 托管的 `macos-14` 和 `windows-latest` 都能打开这个
应用的 WebView 窗口，页面能加载、能起 worker、能编译 wasm，原生桥能来回。
第一次实测（bc94a27）：

| 平台 | WebView | 第一步 | 引擎应着 | 整步用时 |
|---|---|---|---|---|
| macOS | WKWebView | Nf3 | 2053 ms | 9 秒 |
| Windows | WebView2（Edg/153） | d4 | 2349 ms | 14 秒 |

做法和计划有一处不同：没有用 `index.html?selftest=1`，而是让页面在启动时问原生壳
一句 `chess.selftestMode`。这样不用改 `main.zig` 的入口 URL，页面加载的就是用户
加载的那一份。

- `main.zig`：新增 `chess.selftestMode`、`chess.selftestReport` 两个桥命令，只在
  `CHESS_SELFTEST` 恰好为 `1` 时生效。报告写到 `CHESS_SELFTEST_OUT`，按 `ok` 以
  0 或 1 退出。桥命令从 8 个变成 10 个，另加两条 zig 测试。
- `app.js runSelftest()`：用原样的引擎对初始局面要一步棋（60 秒超时），用 chess.js
  核对合法，报告里带 `{ok, version, wasm, ua, move, ms, err}`。
- `scripts/selftest-app.mjs`：启动可执行文件，限时 90 秒，读回报告。第一版在应用
  答完之后还空等满 90 秒（未清的定时器让 node 不退出），f81c5ed 修掉了。
- `build-macos.yml` 在打包之后、上传之前跑它；`build-windows.yml` 在压 zip 之前跑。
  发布门禁本来就要等这两条流水线，所以自检不过，就不会有产物，也就发不出去。
- `test-engine-e2e` 用替身桥验证页面这一半：原样页面报 ok，坏 wasm 页面报
  `ok:false` 并带原因。

**先红后绿**（验收）：

| | 7.3 的 CSP（3daac4a，临时提交） | 撤回之后 |
|---|---|---|
| macOS | 红，8 秒退出：`CompileError: Refused to create a WebAssembly object because 'unsafe-eval' or 'wasm-unsafe-eval' is not an allowed source of script …` | 绿（f90c55b）：e4，1921 ms，7 秒退出 |
| Windows | 红，20 秒退出：`CompileError: WebAssembly.instantiate(): … violates the following Content Security policy directive …` | 绿（f90c55b），自检这一步 31 秒 |

**顺带撞到的**：`test-persist-e2e` 断言「打开」只走「文件对话框 → 读文件」这一条桥
路径，页面启动时多出的 `chess.selftestMode` 让它红了。它不是另一条读文件的路，测试
里把它和已有的 `appdataRead/Write` 一起排除（25bda01）。

**没做到的**：A0 仍然没有人在真机上走过。CI 自检做的是同一件事，跑的也是真的
WKWebView 与 WebView2，但机器是 GitHub 的，不是用户的。

### §2 真引擎流程测试

`scripts/test-engine-flows-e2e.mjs`，六个场景各开一个新的浏览器上下文，本地
Chromium 约 84 秒。接进了 `npm run test:e2e`、`checks.yml` 的双引擎矩阵和
`release.yml` 的门禁，README 的浏览器测试计数改成十个。

先红后绿：临时把 `engine.analyze` 换成返回 `{}`，场景 1（提示）、2（失着提醒）、
3（分析、精析）、5（棋谱库）共 6 项断言失败。

**它在 WebKit 上抓到一个真缺陷**（macOS 用户会碰到）：在棋谱库里填完名字、直接点
「分析剩下的 N 局」，这一下点击会丢，按钮不变、没有提示、引擎一次也没被调用。
原因：焦点离开名字输入框时浏览器再发一次 `change`，名字没变，应用照样重新认领、
重绘面板；面板正文在按下与松开之间被重建，按钮挪了位置，WebKit 不再把这次松开算成
一次点击。Chromium 上不出现。修法：名字没变的 `change` 直接返回（c6d4827）。
先红后绿都在 CI 的 WebKit 上：修之前（3899cce）点击后 120 秒一局没分析；修之后同一
场景 7.1 秒分析完三局。场景里加了断言「点一下就开始」，失败时打印点击是否到达按钮。

**没做到的**：场景 4（持续分析）和 6（教学对练）没有单独做过先红后绿；场景 5 里
「打开一局时引擎不重跑」那一条，红跑时恰好通过，也不算验证过。

### §3 开局族名

- `openings-family-{zh,ja}.js` 覆盖 eco.js 的全部 149 个族。`localName()` 查不到整条
  译名时，换族名、保留变例名；两边都查不到才显示英文原名。英文界面不变。
- 族名尽量沿用开局书已有的写法（例如 1.Nf3 叫「列蒂开局」）。开局书本身就有一个
  开局两种写法的情况（卡罗-卡恩 / 卡罗-康，王翼印度 / 国王印度，四马开局 / 四马
  防御，彼得罗夫防御 / 俄罗斯防御，后兵开局 / 后兵对局），测试里登记了 5 组、9 条
  例外，只减不增。要做到一个开局只有一个名字，得先统一开局书。
- 测试：两种语言都覆盖全部族、没有孤儿条目、族名里没有半角标点；中文下 3810 条里
  没有一条整条英文；content e2e 走 1.e4 c5 2.Bc4，侧栏显示「B20 · 西西里防御：Bowdler
  Attack」。
- 两张表放进主包，没有放进 eco 分块：棋谱库按 PGN 里的开局名显示时不加载 eco 表。
  主包增加约 17.7 KB。

### §4 小修

- **失着提醒**：改成 `fix` 档。守它的是 test-chess 里的一条静态断言（每处
  `mm.blunder` 调用都以 `"fix")` 结尾），去掉 `"fix"` 实测会红。**计划写的是在
  layout e2e 里断言样式类，没做**：要让引擎的应着稳定地送出 300 厘兵以上，场景
  不好造。
- **新局重试引擎**：`requestNewGame()` 在引擎坏着时改走 `retryEngine()`。
  test-engine-e2e 的坏 wasm 场景加了断言：点「新局」后 worker 只多起一个
  （2 → 3），横幅还在，toast 0 条。不改代码时是 2 → 2，红。
- **大 PGN**：新增 `parseGamesAsync()`，逐局解析，约 16 毫秒让出一次；棋谱库和开局书
  的导入都换成它，并防止导入重叠。另外修掉 `splitGamesWith` 的二次方（原来对边界
  之前的全部文本跑正则，现在只看前 64 个字符）：8000 局 9.4 秒 → 0.19 秒。
  test-pgn 断言两次让出之间最长不到 50 毫秒（实测 37），切分近似线性。
  **没做到的**：单个巨大的对局仍是一次同步解析，要彻底解决得挪进 Worker。
- **README 版本门禁**：`manifest-check` 断言 README 有 `## <app.zon 版本> 改了什么`。
- **棋谱库时长**：按钮写成「分析剩下的 N 局（约 X 分钟）」，满 100 分钟改用小时。
  系数 `LIB_PACE` 按 §5 那次实测倒推：102 秒 ÷（8 局共 522 个局面 × 200 毫秒）≈ 0.98。
  「§5 那 8 局就是语料的前 8 局」是推断。500 局 × 80 手满载显示约 2.2 小时。
  中途重载后续跑，test-library-e2e 第 16 节第一次守住：6 局分析完 2 局时重载，已分析
  的原样保留，剩下 4 局接着排队，再点「分析」只问没分析过的局面。这一节用的是空桩
  引擎，**真引擎下的断点续跑仍然没有实测过**。
