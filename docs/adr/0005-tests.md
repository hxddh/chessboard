# 0005 · 测试：守行为和正确性，不守写法

**状态**：已定（2026-11-06）。

## 背景

- 19.0 的测试脚本约 4.7 万行，和 5 万行应用逻辑差不多一样多；静态测试 103 s、1,288 条断言；PR 的 CI 12–14 分钟，每次推送 39 个任务。
- 一部分检查守的是**正确性**，抓到过真问题：规则、对着引擎核过的内容、阶梯强度 ±3σ、性能曲线、首帧无长任务、存档崩溃安全、`sdk-diff`、三语齐全、对比度与截断。
- 另一部分守的是**写法**，会把现在的设计锁死：`app.js` 行数上限、各版本的打包字节线、精确的设计变量个数、「只减不增」的例外登记、33 条 README 数字断言、约 177 条按源码文字匹配的正则、布局空白比例。
- 有两项只在发布时跑（`test-strength`、19 分钟的 `test-endgames-play`），19.0.0 第一次发布就挂在前一项上。

## 决定

- **留下并迁移**：上面列的正确性检查全部保留，按新结构重写调用方式；性能门禁（首帧时间、每步开销曲线）在整个重建过程中一直开着。
- **新增**：
  - 视觉基线：每个页面在 1440 × 900、1024 × 700、600 × 900 下截图，和上一次的基线比对，差异超阈值要人看过才更新。
  - `db` 服务的契约测试（SQLite 版与测试用的内存版跑同一套）。
  - 引擎服务的契约测试（原生、wasm、假后端跑同一套）。
  - 收官测试（v20-0-plan §3 验收）。
- **删掉**：守写法的那一批（上面背景里列的），以及只为兼容旧档案存在的测试。
- **没有只在发布时才跑的检查**：改到对手、阶梯、残局的 PR 自动跑对应的强度与残局检查（按改动的文件挑）；发布流程里的每一项都在某个 PR 检查里出现过，有静态检查守这一条。
- **目标**：PR 的 CI 中位 ≤ 10 分钟。

## 后果

- 重建期间，新旧两套测试并存：一个功能搬到新结构，它的旧测试随之删、新测试随之加，同一个 PR 里完成。
- 测试不再读源码文字来判断「写对了没有」，只看行为和输出。
