# 0002 · 界面层：路由 + 组件 + 信号，棋盘是组件

**状态**：已定（2026-11-06）。

## 背景

- 19.0 的每一屏都静态写在 `index.html` 里：472 个 id、23 个对话框、启动时 4,372 个 DOM 节点；41 个模块按 id 直接改它（742 处 `getElementById`）。
- `app.js` 4,777 行，约 30 个 `createX({…})` 工厂各收 10–30 个回调，模块拿不出来单独用。
- 棋盘是模块级单例（`board.js` 的 `_canvas`）：一屏只能有一块可交互的棋盘；只有棋盘有手写的补间动画，箭头和标记不动。
- 20.0 要的东西——下棋屏重做、技能图、今日一课、棋盘上的复盘、一屏多块棋盘、子和箭头的补间（v20-0-plan §1、§3、§5、§6）——每一样都撞在这些上面。

## 决定

- **路由**：顶层三处「学 / 下 / 我」加设置；一次只挂一个页面，页面在第一次进入时 `import()`（ADR 0001）。地址是内部的 `#/learn`、`#/play/…`，方便测试直达。
- **组件**：原生 JS 函数，`(props) => 根节点`，内部用**信号**（signal / computed / effect，自写，约 150 行，有单测）更新自己那一小块 DOM。不引入框架：
  - 应用的 UI 规模（三个页面 + 设置 + 几个对话框）用不上虚拟 DOM；
  - 没有第三方运行时依赖，体积和行为都在自己手里；
  - 信号的粒度正好对上「一个数字变了只改那一个节点」。
- **棋盘组件** `createBoard(el, opts)`：
  - 每次调用一个实例；可以同时有多个（今天页的小棋盘、复盘的变化、课上的对照）。
  - 场景图：子、被吃的子、高亮、箭头、标记都是场景里的对象，位置变化做补间（时长与缓动按 v20-0-plan §5 H：默认 250 ms、三次方缓入缓出、低于 70 ms 不动画、「减少动态效果」下全关）。
  - 输入：点选、拖动（3 px 阈值、半透明影子）、键盘、预走、右键箭头与标记。
  - 渲染仍是 canvas（19.0 的绘制代码、棋子图形和三套棋子直接搬进来）。
- **文案**：每个页面自己的词典分块，按语言 `import()`；DOM 上不再有 `data-i18n` 属性，组件直接拿翻译好的字符串。键名仍是语义化的，仍有「每个键都被读到」的检查。
- **样式**：保留 19.0 的设计变量（颜色、字号、间距、圆角、阴影、动效），按组件拆成文件；去掉只为静态页面存在的选择器。

## 后果

- `index.html` 只剩外壳；`app.js` 只剩约 200 行的启动；`shell.js`、按 id 取节点的 41 个模块按页面重写。
- 纯逻辑核心原样保留并加类型注释：`chess.js`、FIDE 规则、PGN、复盘数学、`motif`、`explain`、`srs`、`rating`、`persona`。
- 每个页面可以单独挂在一个测试页上（e2e 直达 `#/play`，不必先走完首页）。

## 不做的选择

- **Preact / Lit / Solid**：都很小，但都比 150 行的信号多一层要理解和升级的东西；UI 规模不需要。若信号实现在 A1 第一周的原型里不够用，改用 Solid（同样是信号模型）并写新的 ADR。
- **继续静态 HTML，只是拆模块**：解决不了「一屏一块棋盘」和「页面按需创建」。
