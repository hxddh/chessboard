# 12.0 · 质感与品质：从「设计过」到「做工好」

写于 11.0.0 发布之后（2026-10-14）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

11.0 回答了「像不像一个被设计过的产品」：一屏一个主角，一个动作一个位置。用户对下一个大版本的要求是：**各方面提升质感和品质**。这份计划先把「质感」拆成能量、能验的几样，再回答：哪些这一版做，哪些要你拍板。


**已定（2026-10-14）**：按建议做——声音走方案 A（录音采样，我找许可证与 GPLv3 相容的素材并列出出处）；Windows 标题栏跟主题，Windows 11 加 Mica；11.0 的 Mac 外壳放在第一步请你验收；**不拆版本**，A / N / S / C / L / F / R 一次在 12.0 做完；暂无签名证书，签名与公证不在这一版。
---

## 依据

1. **11.0.0 的 37 张截图**（main @ c2f0a70，两倍像素，Chromium，四套主题 × 1440 / 1024 / 760 / 600 宽 × 三种语言），逐屏看。
2. **代码量化**：
   - 声音全部是 WebAudio 现场合成（`audio.js` + `sound-bank.js`），没有一段录音。
   - Windows 外壳没有任何 DWM 调用：标题栏不跟主题明暗，没有 Mica。
   - Mac 外壳（11.0 W）还没有真机验收；侧栏材质没做。
   - 没有触控板触觉反馈。
3. **性能基线**：Chromium 无头冷启动，DOMContentLoaded ≈ 0.2 s，棋子图解码完 ≈ 0.3 s（5 次中位）。bundle.js 950 KB，前端 184 个模块。启动不是短板。
4. **CI**：macOS 自动化的 R6:frames（帧间隔 > 700 ms）在 10.x、11.0 发布时各红过一次，重跑才过。这是品质问题，不是运气问题。

**局限**：没有 Mac / Windows 真机；声音、触感、窗口材质、字体渲染只能由你确认。

## 0 · 结论先行：「质感」差在这七处

| # | 方面 | 现在 | 做工好的样子 |
|---|---|---|---|
| 1 | **听感** | 落子、吃子、将军全是合成音：干净但「电子」，每一下都一样 | 真实木子落在木盘上的录音，轻重有别，同一种声音每次略有不同 |
| 2 | **两个平台的外壳** | Mac 刚有嵌入式外壳（未验收），侧栏无材质；Windows 是系统白/灰标题栏，深色主题下一条亮边 | Mac：材质、触感、全屏都对；Windows：标题栏跟主题，Win11 上有 Mica |
| 3 | **小尺寸的棋子与棋盘** | 今天页「接下来」「继续」里的小棋盘用的是大棋盘的同一套棋子和同一支笔：缩到 14 px 一格时描边只剩 0.4 px，白子在浅色格上几乎看不见 | 小尺寸单独的光学处理：描边随格子变粗，始终约 1 px |
| 4 | **图表** | 胜率曲线是一大块深色填充，坐标轴稀疏；谜题等级分曲线是一条平线；「我的」页统计全是数字列表；图表不能悬停读数 | 细线 + 很淡的面积，失误点标在曲线上，悬停读出那一手和胜率；空数据有像样的空状态 |
| 5 | **页面构图** | 「今天」右侧进度卡上半截空着；「棋谱」「我的」两栏卡片高度不齐，右下大片空白；训练页右栏下半屏空着 | 每页有自己的栅格，卡片对齐、留白有意图；右栏空处放与当前题/课相关的东西 |
| 6 | **数字与反馈** | 等级分「1500（定级中）」字号大、全角括号挤；等级分变化、进度圈是瞬间跳变；成就解锁是一行字 | 数字有专门的排版（定级中是小标签）；分数滚动到新值、进度圈画到位；成就有一个克制的徽章动画 |
| 7 | **可靠** | R6:frames 偶发红；发布要重跑 | 找到帧间隔偶发超 700 ms 的原因并修掉；发布一次过 |

## 1 · A 听感（需要你拍板：§8-1）

**依据**：差距 1。

**做什么（方案 A，推荐）**：换成录音采样。每种声音 3–4 个变体，随机取用并微调音高：落子（白/黑各一组）、吃子、将军、易位、升变、终局、非法着、提示音。只用许可证与 GPLv3 相容的素材（CC0 或 CC BY），在 About 与 `docs/` 里写明出处。合成音保留为「经典」音色。体积预算 ≤ 300 KB（Opus/AAC，按需分块加载）。

**方案 B**：不用录音，精修合成：加一层短混响（木盘共鸣）、按落子速度调音量、加变体。工作量小、无许可证风险，但上限明显低于录音。

**验收**：声音清单逐项有测试（存在、时长、峰值不过载、两次播放不完全相同）；你在真机上听。

## 2 · N 两个平台的原生外壳

**依据**：差距 2。

**做什么**：
- **Windows**：标题栏跟主题明暗（`DwmSetWindowAttribute` 的 immersive dark mode）；Windows 11 上窗口背景用 Mica（Win10 自动跳过）。和 Mac 外壳一样，是应用自己的原生代码，登记为 SDK 差异。
- **Mac**：先完成 11.0 外壳的真机验收与修正；再做侧栏材质（`NSVisualEffectView`，需要 WebView 背景透明，真机上试，透不过就放弃）；触控板拖子落下时一次轻触感（`NSHapticFeedbackManager`），设置里可关。

**验收**：CI 编译与自动化；Windows 截图（CI 上 windows-latest 可以截窗口）；Mac 部分要你验收。

---

## 3 · S 小尺寸的棋子与棋盘

**依据**：差距 3（今天页、继续卡、棋谱列表、谜题主题卡）。

**做什么**：小棋盘（`mini-board.js`）把格子的尺寸交给 `pieceSrc`；格子小于约 37 px 时，cburnett 的描边按「约一个 CSS 像素」加粗（最多 2.6），大棋盘不受影响。

**验收**：截图对比；e2e 断言小尺寸走的是单独的渲染（描边宽度随尺寸变）。

---

## 4 · C 图表

**依据**：差距 4。

**做什么**：
- 胜率曲线：细线 + 很淡的面积；50% 线；? / ?? 标在曲线上；悬停或键盘移动时读出「第 n 手 · 着法 · 白方胜率」并联动棋盘。
- 谜题等级分、对局等级分曲线：有点数时画出来，少于 3 个点时显示「再做 n 题就有曲线」而不是一条平线。
- 「我的」页：统计改成小图（胜负和条、按阶段的失误分布），列表留给细节。
- 一套图表 token（线宽、面积透明度、网格色），四套主题下对比度合格。

**验收**：图表单元测试（坐标、空数据）；对比度守卫；截图。

---

## 5 · L 页面构图

**依据**：差距 5。

**做什么**：
- 今天：进度卡内容垂直居中，圈与连续天数成组；「最近对局」空时与「等级分」等高。
- 棋谱、我的：两栏改为按内容高度排的栅格（短卡并排、长卡占整行），不再一栏长一栏短。
- 训练（课程 / 谜题 / 残局）：右栏下半屏放与当前内容相关的东西——课程：本单元目录与进度；谜题：这道题的主题与你在这个主题上的成绩；残局：这个残局的要点。

**验收**：layout e2e 量「卡片底边对齐误差」和「右栏空白比例」（≤ 30%）；截图。

---

## 6 · F 数字与反馈

**依据**：差距 6。

**做什么**：
- 等级分统一排版：数字用等宽数字，「定级中」是数字旁的小标签，不加全角括号。
- 等级分变化、进度圈、精准度：从旧值滚动 / 画到新值（≤ 600 ms，减少动态效果时瞬间）。
- 成就解锁：结果条上的徽章轻轻弹出一次；「我的」页成就是带图标的网格，不再是锁头列表。
- 题面去掉重复说法（「一步杀 · 白先，一步内将死」→「一步杀 · 白先」）。

**验收**：e2e 断言动画时长读 token、减少动态效果时为 0；文案字数守卫（11.0 U1 的量法）不升。

---

## 7 · R 可靠

**依据**：差距 7、CI 记录。

**做什么**：在 macOS 自动化里给 R6 的每一帧记时间戳和当时在做什么（引擎、解码、布局），找出偶发超 700 ms 的那一步并修掉；不放宽阈值。顺带把 app.js 再拆小（上限 5,722 行只降不升）。

**验收**：macOS 自动化连续 10 次 R6 全过（CI 上手动跑 10 次）。
