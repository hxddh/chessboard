# 7.1 · 把棋谱库接到应用的其余部分上

写在 7.0 发布之后、动手之前。和 v6 / v7 的计划一样，这一份的规矩不变：

- 每条都要说清楚**依据是什么**，依据是核过的代码或跑出来的数，不是推断；
- 每条都要有**验收**，验收要能被一段测试或一个数字回答；
- 发布前补一节**落地记录**，做到的和没做到的都逐条写。

---

## 0 · 这一版要解决的问题

7.0 造了一条数据管线：一次导入几百局，逐局离线分析，每局存下 `sans`（全局
着法）、`fen`（起始局面）、`an.tags / losses / scalars / bests`、`motifs`
（引擎在你走错之前那一手的母题）。

然后这条管线的产出，只流向一张点不动的统计页。逐项核过：

| 产出 | 7.0 里唯一的消费者 |
|---|---|
| `sans` / `fen` | **没有**。全树只有两处读 `entry.sans`：载入时的过滤、`analyseLibraryGame` 自己重放。没有任何一处拿它摆棋盘。 |
| `an.tags` / `losses` / `motifs` | `foldGame` → 诊断页的统计行 |
| `an.bests`（引擎的反驳着法） | 只在 `analyseLibraryGame` 内部用一次，存下来之后没人读 |
| 诊断结论 | `renderDiagnosis`，一页纯文本 `stat-row` |

而 `Mistakes.addMines` 全仓库只有两处调用（`app.js` 的分析趟和复盘页的手工
入库按钮），**都在棋盘那条路上；`runLibraryPass` 一次也没调过**。库认出了
几百局棋里的每一个 `??`，连引擎该走哪一手都算好存下来了，全部停在统计里。

v7-plan §6.2 自己写过验收：「**每一条都必须点到一个可执行的下一步；没有下一步
的统计不写进这一页**」。7.0 一条都没做到。

**所以 7.1 不采集新数据，只接线。**

---

## 1 · P0：闭环

### 1.1 A1 — 从库和诊断点进那一局棋

库里点一局 → 载入棋盘，并把**存好的 `an` 当分析结果喂给现成的复盘渲染**，
不重新跑引擎。`store.session.analysis` 的形状是
`{ sig, scalars, tags, pvs, bests, linesAt, budget, acc }`，库里的 `an` 有其中
五项；`sig` 载入后现算（`game.pgn()`），`pvs` / `linesAt` 缺席——这两项的全部
读取点都写成 `a && a.pvs ? … : null`，缺席就是没有引擎变化可展开，不是崩。

诊断页每一行可点，筛到对应的那些局：母题行筛出被这个母题打中的局、开局行筛出
这个 ECO 的局、峰值回合行筛出在那附近崩的局。

**验收**：e2e 里点诊断的母题行 → 库列表被筛过 → 点一局 → 棋盘上是那局棋、
走子列表带着 `?` / `??` 标注、而且**引擎一次都没有被调用**（e2e 的引擎是桩，
调用会被记下来）。

### 1.2 A2 — §6.3 错题自炼扩容到真实规模

v7-plan §9 原话：「§6.3 跟着 §6.1 走，否则第一次批量导入就会冲掉老错题」，
以及「工期只够一半就把 §6.3/§6.4 留到 7.1」。7.0 做了 §6.1 没做 §6.3——风险
没有爆，只是因为库根本没接进错题本。

两件事：

1. `runLibraryPass` 分析完一局就把这一局的失误入错题本（走和棋盘那条路同一个
   `candidatesFrom` / `reviseMines` / `addMines`，不另写规则）。
2. 淘汰策略从「已解出优先、然后最旧」改成**按母题分层保留**：每个母题至少留下
   最近 N 道，超出的部分才按老规矩退。否则一次导入几百局，一个月积累的错题会
   被同一批新题整批冲掉——而且冲掉的往往正是已经练出效果的那些母题。
   `MAX_MINES = 50` 按「每天下几局」定的，来源变成「你全部的棋」之后要重估。

**验收**：单测——先有一本 50 道、母题分布不均的错题本，灌进 200 道新题，断言
每个母题都还留着它最近的 N 道；以及「一次批量导入之后，老母题一个都没有整类
消失」。这条是这一版唯一会改动用户已有学习记录的改动，所以测试要钉死。

### 1.3 A3 — 日课 / 推荐 / 进步读棋谱库

`dailySignals()` 今天的七个信号全部来自 `puzzleState` / `mines` / `lessons` /
`stats`；`playedToday` 读的是 `loadStats()`，所以导进来的棋连「今天下过棋」都
不算。

- 日课取题的权重读诊断的 `weakestPhase` 和母题榜；
- 进步页的准确率走势把库里的棋按日期并进来。

**验收**：e2e——库里有 25 局已分析的棋、本地战绩为空时，日课里出现一条指向
诊断/错题的步骤；进步页的准确率走势有数据可画。

## 2 · P1：质感

### 2.1 B1 — 诊断页画图

现在整页是 `stat-row` 纯文本。三张图，用 `drawAccTrend` / `drawRatingTrend`
同一套画法（dpr 缩放、颜色取自 CSS 变量、`judgeColours()` 的判级色阶）：

1. 分阶段 ACPL 柱——最弱的那根用判级色标出来；
2. 失误按回合的分布——峰值回合是这张图上的一个尖，不是一句话；
3. 按开局的战绩——胜/和/负堆叠条。

**验收**：e2e 断言三张 canvas 在有数据时可见、无数据时不存在（这一页一贯的
P3 规矩：没有数据就不画那个元素）。

### 2.2 B2 — 棋谱库列表

几百局棋今天只有一个计数和一个「看诊断」按钮。列表照 `hist-modal` 的样子做
（它已经有筛选段、`reconcile` 的按 id 复用、空态文案）：日期 / 对手 / 结果 /
我这局的精准度 / 失误数，筛选按结果、按执子、按「还没分析的」，排序按日期或
按我的精准度。A1 需要它当入口。

**验收**：e2e——导入 4 局的文件后列表 4 行；筛「只看输的」行数对；点一行进
A1 的路径。

## 3 · P2：欠的账

### 3.1 C1 — §6.4 的验收从来没做

v7-plan §6.4 的验收原话：「在 28 局语料上，能给出解释的失误比例要量出来并
写明；抽样人工核对解释的正确率，低于某个门槛就默认关掉这个功能并如实记录」。
`docs/measured.json` 现有八个键，没有这一个。7.1 补测：在语料上跑一趟，量出
**能给出母题解释的失误占比**，写进 `measured.json`，并在文档里写明这个数。

### 3.2 C2 — 发布门禁 2.5 小时

`test:engine` 现在七个脚本串跑，其中 `test-mined` 是 7.0 接进来的，又加了
`ucinewgame`（每题一次干净置换表，这是它可复现的前提）。PR 上跑抽样，全量
留给 release 与 nightly。

**验收**：抽样档能在 CI 上十分钟内跑完，并且抽样是确定性的（固定种子）。

### 3.3 C3 — §10 的记账漏洞

`docs/v7-plan.md` §10 的两张表里，**§6.3 都不存在**——既没在「做到了」，也
没在「没做到的」。6.0 的教训原话是「计划里打了勾而代码里没有的东西，会在下
一版被当成已有继续往上盖」；这次是连勾都没打，更查不出来。§6.4 打了勾但它
的验收没做（见 C1）。两条都在 v7-plan 里补记。

### 3.4 C4 — 同一个钳制缺陷的第三处

7.0 复查修掉了两处没钳制到 ±`EVAL_WINDOW` 的每手厘兵（棋谱库的 `an.losses`、
`foldGame` 不读 FEN）。核 `mistakes.js` 时发现第三处：`candidatesFrom` 算
一道错题的 `loss` 也是自己减的

```js
const loss = sA != null && sB != null ? Math.round(side === "w" ? sA - sB : sB - sA) : null;
```

于是一手放掉杀棋的错题会显示「亏了 99.5」。判级本身没错（`??` 走的是胜率
口径，胜率函数在杀棋分附近本来就饱和），错的只有这个展示出来的数字。改为调
`Review.lossOf`。
