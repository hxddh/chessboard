# 11.0 · 顶级产品：精致、优雅、易用

写于 10.1.0 发布当天（2026-10-10）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

10.0 把训练接成了闭环，10.1 把字体、表面、控件磨了一遍。用户对下一个大版本的要求是一句话：**要精致，要优雅，要易用，达到顶级产品级别**。这份计划回答三个问题：离「顶级」还差什么；哪些能在这一版里做完；哪些要用户拍板。

**已定（2026-10-10）**：窗口外壳走方案 A（应用自己的原生拖动条，用户在 Mac 上验收，拖不动就回退）；默认棋子走 (b)（保留 cburnett，精修渲染）；对手头像由我画几何扁平风格的 SVG 肖像；**不拆版本**，W / P / V / M / U / S 一次在 11.0 做完。

---

## 依据

1. **10.1.0 的 37 张截图**（两倍像素，Chromium，四套主题 × 1440 / 1024 / 760 / 600 宽 × 三种语言），逐屏看。
2. **对照**：Chess.com（对局页、Game Review）、Lichess（对局与分析）、Apple 自带应用（Music、Notes、System Settings 的外壳、侧栏、分段、列表）。外部网站和 GitHub 被代理挡住，对照来自已有认识与 9.0 / 10.0 的评审记录。
3. **代码量化**：样式表 39 处过渡、7 个关键帧；棋盘是画布，走子滑动 200 ms；index.html 里 187 行带 aria、396 行带 i18n 标记；前端 186 个模块。
4. **SDK**：npm 上 `@native-sdk/cli` 最新仍是 0.10.1（8-24），没有网页拖动区。仓库的 `build.zig` 自己编译 SDK 的原生源文件，可以加一个应用自己的 ObjC 文件。

**局限**：没有 Mac 真机。苹方、SF、窗口外壳、触控板的实际手感都只能由用户确认。没有真人可用性测试。

## 0 · 结论先行：离「顶级」差的是这五样

| # | 差距 | 现在 | 顶级产品的样子 |
|---|---|---|---|
| 1 | **窗口不像 Mac 应用** | 系统灰标题栏压在深棕界面上；侧栏没有材质；标题栏明暗不跟主题 | 红绿灯嵌在内容里，侧栏通到顶，标题栏跟着主题 |
| 2 | **下棋页——最常用的一屏——是空的** | 开局前右栏一张说明卡和两个图标，下面 70% 空白；结束后「新局」出现两次（右栏 + 结果条）；复盘时图例一直挂在底部 | 每个状态一个主动作；对局中是着法、吃子、子力差、思考状态；结束后结果与复盘合成一张卡 |
| 3 | **没有「人」和「物」的质感** | 21 位对手是同一种线性小图标；默认棋子 cburnett 粗黑描边；「木」棋盘是两块平涂色 | 对手有面孔；棋子精致；木就是木纹 |
| 4 | **动效几乎没有** | 7 个关键帧（对话框、面板、思考点……）；吃子、将军、终局都是瞬间换图 | 走子有缓动，吃子淡出，将军有一下提示，终局有一个克制的庆祝，页面切换有方向 |
| 5 | **字太多** | 说明句挂在界面上不走（「走一步棋就会出现棋谱；完局后点『分析』……」「分析后曲线可点击跳转 · ?! 小失误……」）；对手卡写满一句话 | 界面靠布局和图形说话，说明只在第一次出现，或悬停才出现 |

10.1 修的是「每个零件是否精致」；11.0 要修的是**整体是否像一个被设计过的产品**——一屏一个主角，一个动作一个位置，东西有手感。

## 1 · W 原生外壳（需要你拍板：§8-1）

**依据**：差距 1。SDK 0.10.1 的拖动区只给它自己的画布控件用，WKWebView 盖住标题栏后，网页里没法声明可拖动区域。

**做什么（方案 A，推荐）**：仓库加一个应用自己的 `src/native/mac_chrome.m`，由 `build.zig` 只在 macOS 上编译：
- 窗口改 `hidden_inset`，标题栏透明，内容通到顶。
- 在 WebView 上方盖一条 28 pt 高的原生拖动条（`mouseDownCanMoveWindow`，双击按系统偏好缩放或最小化），让开红绿灯所在的区域。网页这一条不放可点的东西，侧栏和顶栏照它留白。
- 窗口的 `NSAppearance` 跟主题走：木、夜用深色，日、纸用浅色。
- 侧栏背后加 `NSVisualEffectView`（sidebar 材质），网页侧栏背景改半透明。这一项看效果再定，透不过 WebView 就放弃。

**风险**：无法在这里试拖动。macOS CI 的自动化只能验证窗口样式与拖动条存在，「拖得动、双击缩放、全屏时让开」要你在 Mac 上验。拖不动就整项回退成标准标题栏，不发半成品。

**方案 B**：继续等 SDK，这一版只做「标题栏明暗跟主题」（同样要一点 ObjC）。

**验收**：CI 上窗口样式断言；你在 Mac 上的确认清单（拖动、双击、全屏、多窗口、窗口还原）。

## 2 · P 下棋页重做（这一版的主角）

**依据**：差距 2、5。下棋是打开最多的一屏，现在它的右栏是一个通用的面板。

**做什么**：右栏按对局状态换成三种，每种一个主动作：

| 状态 | 右栏 | 主动作 |
|---|---|---|
| 开局前 | 对手卡（头像、名字、等级分、一句风格）、执子与棋钟两个小分段、「开始」 | 开始 |
| 对局中 | 着法表（占满剩余高度）、双方吃子与子力差、引擎思考时的状态行、悔棋 / 提示 / 认输收进一排图标 | — |
| 结束后 | 结果卡（谁赢、怎么赢、等级分变化、成就），下面是「复盘这一局」和「再来一盘」 | 复盘这一局 |

- 删掉重复的「新局」（结果条与右栏只留一处）；底部常驻的图例改为第一次复盘时出现一次，之后悬停才出现。
- 玩家栏：头像 + 名字 + 等级分 + 棋钟，吃子显示在名字下方（Lichess、Chess.com 都这样放）。
- 评估条加宽到 8 px 并贴住棋盘，数字收进条内。

**验收**：三种状态各一张截图对比；开局前右栏的空白不超过 30%；任一状态没有两个同义按钮（守卫）。

## 3 · V 质感：对手、棋子、棋盘

### V1 · 对手有面孔

**做什么**：21 位对手各一幅 SVG 头像，统一风格。几何化的扁平肖像，配主题强调色的底，由我绘制，不用照片、不用生成图。头像用在新对局对话框、玩家栏、结果卡、今天页。

**验收**：21 幅都在；四套主题下对比度合格；两倍像素截图审一遍。

### V2 · 默认棋子（需要你拍板：§8-2）

**依据**：cburnett 是 Lichess 的默认，可读性好，但粗黑描边在大棋盘上显得重。

**做什么**：三条路——
- (a) 换一套更精致的开源棋子做默认。前提是许可证与 GPLv3 兼容（GPL、CC BY-SA 4.0 可以；CC BY-NC 不行）。候选要逐个核实许可证，这里访问不了 GitHub，要在能访问的地方查。
- (b) 不换，给 cburnett 调细描边、加一层很淡的立体阴影。改的是渲染，不是图形本身。
- (c) 自己画一套。工作量最大，风险最高，不推荐在 11.0 做。

推荐 (b)，并把 (a) 的候选列出来给你挑。

### V3 · 棋盘有材质

**做什么**：「木」「大理石」两套加程序生成的纹理（在画布上叠一层低对比噪声和木纹，不加图片）。棋盘外缘加一圈很淡的投影；坐标字改为盘内角落的小字。

**验收**：截图对比；画布帧耗时不升（性能测试照过）。

## 4 · M 动效：克制但有

**做什么**（全部尊重「减少动态效果」）：
- 走子：200 ms，用 `--ease` 缓动，落子末尾轻微减速。
- 吃子：被吃的子 120 ms 淡出缩小。
- 将军：王所在格闪一次红晕，300 ms。
- 终局：结果卡从下方浮入；胜局在王上放一个小的光晕。不放彩纸。
- 页面切换：今天、下棋、训练、棋谱、我的之间 160 ms 交叉淡入；对话框与面板沿用现有的。
- 按钮按下 0.97 缩放（已有），选中态切换 120 ms。

**验收**：动效清单逐条有测试（时长读 token）；开启「减少动态效果」时全部为 0。

---

## 5 · U 易用：少字、少步、少选择

### U1 · 文案减量

**做什么**：统计每屏可见说明文字字数（e2e 量），目标减 40%。常驻的提示改为「首次出现一次」或悬停；对手说明压到 8 个字以内的风格词。

### U2 · 核心任务步数

| 任务 | 现在 | 目标 |
|---|---|---|
| 打开就和合适的对手下一盘 | 今天 → 下一盘 → 对话框 → 开始（3 次点击） | 2 次（今天的主按钮直接开局，用上次的对手） |
| 下完一局看复盘 | 结果条「分析」→ 面板 → 完整报告（2–3 次） | 1 次（结果卡「复盘这一局」直达关键时刻） |
| 做一道适合我的题 | 训练 → 谜题 → 为你出一题（3 次） | 2 次 |
| 找到一节课 | ⌘K 或 训练 → 课程 → 全部 120 课 | 照旧 |

**验收**：e2e 里为每个任务数点击次数，写成守卫。

### U3 · 训练页减负

**做什么**：谜题面板的控件（重做、下一题、等级分卡、为你出一题、复习、六张分类卡、冲刺、连胜、看 N 步、盲走、按主题、题目列表）分两层。上层只留「为你出一题」、今日复习、当前题；其余收进「更多练法」。

## 6 · S 系统收尾

- **图标**：全部线性图标统一 1.5 px 线宽、24 网格，补齐缺的。
- **空状态**：每个空状态一个小线稿插画（棋子轮廓），替代现在的单个图标。
- **App 图标**：按 macOS 的圆角方形规范重绘，带光影层次。
- **截图基线**：37 张截图进 CI 作为产物，每个 PR 自动生成与 main 的并排对比，供人看（不做像素断言）。

## 7 · 顺序与发布

W（先做，因为它改外壳，影响所有页面的顶边）→ P（下棋页）→ V1 / V3 → M → U → S → 截图对比 → 11.0.0。V2 看你的选择插进 V 里。

11.0 是大版本，工作量明显大于 10.0。如果要分两步：**11.0 = W + P + V + M**（看起来与摸起来），**11.1 = U + S**（用起来与收尾）。

## 8 · 需要你拍板的

1. **窗口外壳**：方案 A（自己写原生拖动条，需要你在 Mac 上验收，拖不动就回退）还是方案 B（继续等 SDK，只做标题栏明暗）？
2. **默认棋子**：(b) 保留 cburnett 并精修渲染（推荐），(a) 换一套开源棋子（我列候选，你挑，许可证须 GPL 兼容），还是 (c) 自己画？
3. **对手头像**：由我画几何扁平风格的 SVG 肖像，可以吗？还是只用名字首字母的圆形徽章（更保守）？
4. **范围**：11.0 一次做完 W/P/V/M/U/S，还是拆成 11.0（看与摸）+ 11.1（用与收尾）？
5. **Mac 真机**：每个阶段结束我会请你在 Mac 上截几张图，你方便吗？这是唯一能确认苹方、SF、材质、外壳真实观感的办法。
