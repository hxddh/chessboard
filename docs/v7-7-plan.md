# 7.7 · 精致：棋盘四周的一切

写在 7.6.0 发布之后、动手之前。规矩照旧：每条写**依据**，每条有**验收**，发布前补
**落地记录**，做到的和没做到的都逐条写。

这一版要回答的问题是：**界面、元素和交互为什么不够精致优雅，和顶级产品差在哪里。**

依据来自两处：

- **截图走查**。7.6.0（main 75a3560）在 Chromium 里截了 25 个状态：1440×900、
  1024×700、600×900 三种窗口，四套主题，中文和英文；开局、中局、选子、拖子、真引擎
  分析、认输确认、终局，教学、做题、记录页。下面写成「截图 NN」。
- **对照**。对照的是 Lichess（棋盘、分析、做题反馈）、Chess.com（对阵条、复盘报告、
  终局、按钮层级）、En Croissant / ChessBase（桌面端的信息密度），以及 Chessable 这类
  训练产品的「该你走了」提示。对照的是这些产品公开可见的行为与布局，不搬它们的素材；
  要引入的任何素材（棋子、音效、图标），都先核许可，只收与 GPLv3 兼容的。

局限：截图用的是无头 Linux 的字体，不是 PingFang / 微软雅黑，字形与真机不同；WebKit
这次没有截图。字形上的判断都留到真机再定，下面只谈与字体无关的问题。

---

## 0 · 结论先行

棋盘本身不差。棋子是 cburnett（Lichess 的默认棋子），格子配色和 Lichess 同源，
对比度有测试守着（正文与面板底 12.2:1，次要文字 6.96:1）。**差距在棋盘四周：**

1. **布局不稳**。切换侧栏的页签，棋盘会左右跳：1440×900 下，「对局」页棋盘左缘在
   x=150，「记录」页在 x=8，「教学 / 做题」页在 x=102。侧栏宽度跟着内容走，从 283px
   变到 567px。顶级产品里，棋盘是整个界面的锚，不会因为看了一眼别的页签就挪位置。
2. **对局信息挤在一条 32px 的顶栏里**。谁执白、谁在走、还剩几分钟、多了几个子、刚走的
   那一步、谁赢了，全在顶栏里，字号 11–16px（截图 30）。Lichess 和 Chess.com 都把这些
   放在贴着棋盘上下边的两条对阵条里，时钟是一块醒目的色块。
3. **侧栏没有主次**。对局页有 11 个按钮，外观一模一样（分析 / 精析 / 持续分析 / PGN /
   导出 / 存档槽 / 编辑局面 / 更多 / 提和 / 新局 / 认输）。分区标题是 11px 的灰字。
   看不出哪个是当下该按的。
4. **关键时刻只有一条 toast**。终局只有左上角一枚「白方认输 · 黑方胜」小药丸，外加
   一条盖在棋盘第一横线上的 toast（截图 32）。分析做完也一样（截图 22）。Chess.com
   在这时候弹出结果卡，给出下一步；Lichess 做题时，对错有专门的反馈卡。
5. **一批看得见的瑕疵**（§1）：没有内边距的按钮、整块等宽字体、鼠标点完棋盘上还挂着
   键盘光标、导航按钮到末步就消失、侧栏页签下面透出滚动的内容、表情符号当图标。
6. **声音是振荡器合成的**（`audio.js` 用 `createOscillator`）。顶级产品用的都是木头
   落子的采样声，而且走子、吃子、将军、易位、升变、时间不多了，各有各的声音。

所以 7.7 不加功能，**只做质感**：先修掉看得见的瑕疵（§1），再把棋盘固定住，对阵条
贴到棋盘边上（§2），然后给侧栏定主次（§3），给关键时刻一个像样的交代（§4），最后是
复盘报告、棋盘细节、图标、声音和动效（§5–§9）。

## 1 · P0：看得见的瑕疵（便宜，先做）

每条都在截图里看得见，每条都能写成浏览器断言。

### 1a 「记录」页有三个按钮没有样式（截图 07）

「导入棋谱文件」「导入执白开局书」「导入执黑开局书」三个按钮的文字顶着边框，高度
只有文字高。这三个都是 `.act-btn`（`index.html:760`、`:789`），但 `.act-btn` 的尺寸
规则只在按钮栅格里生效，放在栅格外面就只剩边框。

**做什么**：`.act-btn` 在任何容器里都有同样的高度和内边距。
**验收**：页面上每个可见的 `.act-btn`，计算出的左右内边距 ≥ 8px，高度等于 `--row-h`；
四套主题、三种语言都查。

### 1b 「今天的训练」整块是等宽字体（截图 13）

`<ol class="daily-plan num">`（`index.html:438`）。`.num` 是给时钟和评分用的等宽数字
类，挂在整个列表上，于是「Learn a new lesson / the next lesson」整块都是等宽字体。
中文界面里汉字回落到别的字体，不太显眼；英文界面一眼就能看出来。

**做什么**：去掉列表上的 `num`，只给列表里的数字挂。
**验收**：`#daily-plan` 里非数字文字的计算字体不在 `--font-num` 的字体族里。

### 1c 鼠标点完棋盘，键盘光标还挂在格子上（截图 20、22、30）

用鼠标走完 e2-e4 之后，e4 上一直有一个白色双线框。那是键盘光标（设计约束 §2 的
「双线描边」），本该只在用键盘操作时出现。

**做什么**：照 `:focus-visible` 的规矩，鼠标或触摸操作之后隐藏光标，按下方向键再
出现。
**验收**：鼠标走一步之后截图，光标格没有描边；接着按一下方向键，描边出现。

### 1d toast 盖住棋盘（截图 22、32）

「分析完成 · 没有明显失着」「本局结束 —— 点『分析』看这盘的回顾」这两条 toast，都压在
棋盘第一横线的 e1、f1 上。

**做什么**：toast 不进棋盘的矩形。放在棋盘上方，或者侧栏顶部。
**验收**：所有 toast 出现时，它的矩形与 `#board` 的矩形不相交；四种窗口尺寸都查。

### 1e 侧栏页签下透出滚动的内容（截图 23）

侧栏往下滚，棋谱第 10 行的上半截从页签下面透出来。页签是 sticky 的，但底色没盖住。

**做什么**：页签条给不透明底色；内容滚到页签下面时，加一道 `--line` 分隔线。
**验收**：滚动 400px 后截图，页签矩形范围内只有页签本身的像素。

### 1f 棋谱导航到最后一步，「前进」按钮就不见了（截图 20、30）

在最后一步时，导航只剩「«」「‹」两个按钮，另外两个被藏掉，这一行的布局跟着变。
棋谱末尾还有一个「…」，读起来像是内容被截断了。

**做什么**：四个按钮始终都在，走不了的那个置灰；删掉「…」，或者换成明确的「轮到
黑方」占位。
**验收**：任何一步，导航行都有 4 个可见按钮；到了末步，后两个是 `disabled`。

### 1g 切换页签，棋盘会跳（截图 02 / 07 / 08）

1440×900 下，棋盘外框左缘：对局页 x=150，记录页 x=8，教学 / 做题页 x=102。侧栏宽度
是按内容算出来的。

**做什么**：侧栏宽度只由窗口尺寸决定（设计约束 §4 的 284px 下限不变），与当前页签、
当前模式无关。
**验收**：同一个窗口尺寸下，三个页签、四种模式，`#board` 的矩形逐像素相同；
1440×900、1024×700、1280×800 三种尺寸都查。

### 1h 侧栏顶上空着 58px（所有截图）

顶栏只属于棋盘那一栏，侧栏在它旁边空出一条 58px 的暗带，页签从 y=58 才开始。

**做什么**：侧栏从 y=0 开始，页签贴顶；或者顶栏横跨整个窗口，侧栏在它下面。二选一，
实现时两种都截图再定。
**验收**：侧栏页签的上缘 ≤ 12px，或者与顶栏下缘对齐。

### 1i 「今天的训练」像一个被禁用的输入框（截图 02）

它是一个没有文字对比的宽按钮，下面两行步骤是纯文字，看不出能点。

**做什么**：做成一张卡片：标题、进度（1/3）、每一步前面有状态点，可点的步骤有悬停
状态和箭头。
**验收**：截图对比；可点的步骤有 `cursor: pointer`，并且有 `:hover` 样式。

## 2 · 对阵条：把「谁、剩多少时间、多几个子」贴到棋盘边上

**依据**（截图 30、32）：人机对局时，顶栏一行依次是：♔ 白 · 玩家 · 2:59 · 3… exd4 ·
3:02 · ♟+1 · Stockfish · 中级 · 黑 ♚。时钟是 16px 等宽字，物质差是一枚 10px 的
小标签，最后一步夹在两个时钟中间。「白方走子」是左上角另一枚药丸。

**对照**：Lichess 和 Chess.com 都在棋盘上下边各放一条对阵条，上面是对手，下面是自己，
跟着翻转。每条从左到右是：头像、名字和等级、吃掉的子（按兵种聚在一起）加「+N」、
右端的时钟块。轮到谁，谁的时钟块就亮起来；时间不多了变红，最后 10 秒显示到 0.1 秒。

**做什么**：

- 两条对阵条贴着棋盘上下边，高 40px，内容如上。人机模式下，对手一侧显示陪练风格的
  图标和档位（7.5 的 persona）；双人模式显示两位玩家的名字，导入的棋谱用 PGN 里的名字
  （7.6 已经在读）。
- 顶栏只留「悔棋 / 提示 / 菜单」。「白方走子」那枚药丸去掉，由亮起的对阵条表达轮到
  谁；读屏用的状态文字照旧保留（a11y）。
- 终局时，对阵条上标出结果（1 / 0 / ½）。

**代价**：棋盘会变小。1440×900 下，外框现在是 856px。两条 40px 的对阵条，大约让
外框缩到 800px。设计约束 §1 说棋盘尺寸变化**不做**动画，这里是布局常量变了，不是
动画，不冲突。

**验收**：

- 对阵条存在，并且跟着翻转；轮到谁，谁那条有 `is-active`。
- 吃子之后，物质差算得对（用现有的 `material.js`，不另写一份）。
- 1440×900 下，棋盘边长不小于 7.6 的 88%；1024×700 下也一样。
- 竖窗（600×900）下，两条对阵条和棋盘一起放在底部抽屉上方，不进抽屉。

## 3 · 侧栏：主次、密度、空状态

**依据**（截图 20、22、30）：对局页 11 个按钮一个样子；分区标题 11px 灰字；棋谱区
只有 7 行高，是对局中最该看的东西，却和「存档槽」「编辑局面」一样大。

**对照**：Lichess 对局时右栏只有对阵条、棋谱和一排控制按钮，别的都收进菜单。
Chess.com 每个上下文只有一个实心大按钮（Play、Start Review、New Game），其余都是次级。

**做什么**：

- **三级按钮**。主按钮是实心强调色，每个上下文最多一个：对局中没有主按钮；终局后是
  「分析这盘」；教学是「下一步」；做题是「下一题」。次级是现在的描边按钮。第三级是
  纯图标或纯文字，PGN、导出、存档槽、编辑局面都放在这一级，配 tooltip。
- **对局中，棋谱是主角**。棋谱区占满侧栏剩余的高度；兵种图标和着法文字按基线对齐（现在
  的图标偏小、偏上，截图 20）；编号列有底色；当前着法高亮；`?!` `?` `??` 按颜色标在着法
  后面。
- **不常用的收进「更多」**。提和、认输在对局中保留；复盘的三个按钮只在对局结束或
  手动打开复盘时出现。
- **空状态**。记录页现在是三段说明文字（截图 07），改成：一个图标、一句话、一个按钮。
- **字号**。设计约束 §3 规定字号 7 档，**不新增档位**。这里只调各处用的是哪一档：
  分区标题从最小档上调一档，正文不变。

**验收**：

- 每个上下文，页面上可见的主按钮 ≤ 1 个（写成断言）。
- 对局中（1440×900），棋谱区的高度 ≥ 侧栏可用高度的 45%。
- 截图对比：对局中、终局、教学、做题、记录页的空状态，各截一张，贴进 PR。

## 4 · 关键时刻：终局、做题对错、一课学完

**依据**：终局只有一枚药丸加一条 toast（截图 32）。认输确认框的主按钮是金色的，
可认输是一个不可撤销的破坏性操作（截图 31）。

**对照**：Chess.com 终局时弹出结果卡，写着结果、原因、双方精准度的入口，按钮是
复盘 / 再来一盘 / 换对手。Lichess 做题时，对了是绿色对勾加「最佳着！」，错了是红叉，
解完显示等级分变化和连对数。

**做什么**：

- **终局卡**。放在棋盘区域里、不遮挡棋子的位置，比如棋盘上方的对阵条展开，或者侧栏
  顶部。它是非模态的，写：结果（大字）、原因（将杀 / 超时 / 认输 / 和棋规则），主按钮
  「分析这盘」，次级按钮「再来一盘」「换个对手」。胜、负、和的音效已经有了（`audio.js`），这里接上。
- **做题反馈卡**。对了是对勾、「最佳着」、连对数；错了是叉、「再想想」、提示入口；
  解完显示评级变化（做题评级已有，见 `rating.js`）。
- **一课学完**。课程进度用一排圆点表示，学完的那一点亮起来，而不是只弹一条 toast。
- **破坏性操作用危险色**。认输确认框的确认按钮用 `--danger`，不用强调色。
- toast 只留给后台事件（存盘失败、导入完成），不再承担「这盘结束了」这种主叙事。

**验收**：

- 终局（将杀、超时、认输、和棋四种），终局卡都出现，内容对，与棋盘矩形不相交。
- 做题做对、做错各截一张图。
- 认输确认按钮的背景色取自 `--danger`。

## 5 · 复盘报告：从一串数字变成一眼能看懂的东西

**依据**（截图 22–24）：分析完，侧栏里是一段文字：「精准度 99% / 平均失分 3 /
?·?? 0·0 / 只分析了 11 着……」，白方一段，黑方一段。精准度在报告上方又出现了一次
（「精准度 · 白 99% · 黑 98%」）。评估条是侧栏里一根横条。1440×900 下分析完的三张
截图里，都没看到局势曲线（`#eval-curve`），实现时先确认它在哪种布局下才显示。

**对照**：Chess.com 的 Game Review，顶上是双方的大号精准度，下面一张表按分类列出
双方的着数，每类一个彩色图标；然后是关键时刻。Lichess 把局势曲线放在棋盘下方，
横贯整个宽度，点哪儿跳哪儿；评估是一根竖条，贴在棋盘左边。

**做什么**：

- **报告卡**。双方精准度做成两个大数字，并排；下面一张小表：`?!` `?` `??` 各几次，
  按颜色区分；「只分析了 N 着」这类说明收成一行脚注。精准度只出现一次。
- **竖评估条**。复盘和分析时，贴在棋盘左缘（跟着翻转），代替侧栏里的横条。
- **局势曲线**。分析完成后总是可见，放在棋谱下方或棋盘下方，二选一，截图后定。
  `?` 和 `??` 在曲线上标成彩色圆点，点击跳转（现有的行为）。
- **棋盘上的标注徽标**。当前这一步如果有 `?!` `?` `??`，在目标格的右上角画一个小
  圆徽标。Lichess 和 Chess.com 都这样做。它走 canvas，颜色取主题 token，不写死颜色
  （设计约束 §2）。
- **不编分类**。Chess.com 有「妙着 / 好棋 / 最佳」，这个应用的模型只有 `?!` `?` `??`
  三档，以及 7.6 修过的「存疑标注」开关。**不新增没有依据的分类**。这是 7.6 立的规矩：
  不做误导人的数字。

**验收**：

- 分析完成后，精准度的数字在页面上只出现一次。
- 竖评估条的高度等于棋盘高度，翻转后白方一端跟着换边。
- 有 `??` 的一步，目标格上画了徽标（读 canvas 像素，或者读画图命令记录）。

## 6 · 棋盘细节

**依据**：

- 上一步的高亮在深色格上发浑。`--sq-last` 是 `rgba(64,153,23,soft)`，叠在木纹深格
  `#b58863` 上是一块橄榄色（截图 20：d8、c7；截图 30：e5、d4）。选中格又是另一种黄
  （`--sq-sel`）。一块盘上有两种黄绿色。
- 棋子带一圈模糊的投影（截图 02，每个子底下都有）。
- 坐标写在外框上，外框 17px 宽。

**对照**：Lichess 的上一步和选中格是同一个色相、不同的透明度，深浅格上看起来是
同一种颜色；棋子没有投影；坐标写在盘面边角的格子里，与格子反色。

**做什么**：

- **重新调高亮的配色**，四套棋盘各调一次。标准是：同一种标记叠在浅格和深格上，
  色相差要小（量 ΔE，写进 `measured.json`）；上一步、选中、将军、提示四种标记之间
  要分得开。
- **棋子投影**：出三张对比图（现状、减半、去掉），截图后定。只改默认值，不加开关。
- **坐标**：加一个「坐标在盘内」的选项，打开后外框收窄。默认值截图后定。
- **更多棋子**：候选两到三套，逐一核许可，只收与 GPLv3 兼容的（cburnett 当初就是
  这么收的，见 `pieces.js` 头注）。核不过的不收，并且在落地记录里写明是哪一套、卡在
  哪一条许可上。
- **将军**：王所在的格子，用径向渐变的红色光晕，代替现在的平涂。

**验收**：

- 每套棋盘，每种标记，在浅格和深格上的 ΔE 写进 `measured.json`，并给出上限。
- 棋子精灵只缓存一个尺寸的约束不变（`the sprite cache still holds one size`）。
- 每处格子平涂仍然走 `cellRect()`；径向渐变也算平涂，同样要走（登记册只减不增）。

## 7 · 图标

**依据**：成就用的是表情符号 🎓 🧩 🏆，锁定的成就是 🔒（`achievements.js`、
`app.js:6173`）。表情符号在 macOS 和 Windows 上长得完全不一样，Windows 上还是扁平的
另一种画风。菜单是字符「☰」，导航是字符「« ‹」。

**做什么**：换成一套 SVG 线性图标（候选 Lucide，ISC 许可；或 Tabler，MIT 许可，两者都
与 GPLv3 兼容），内联大约 25 个，颜色取 `currentColor`。表情符号、「☰」和「« ‹ › »」
这类字符按钮全部替换。

**验收**：`src/web` 下的界面文字里，不再有表情符号（写成 test-chess 断言，给一个登记册，
只减不增）；图标的来源和许可写进关于页，和棋子的许可写在一起。

## 8 · 声音

**依据**：`audio.js` 用 Web Audio 振荡器合成了五种音效。

**对照**：Lichess 和 Chess.com 用的都是采样声：落子、吃子、将军、易位、升变、开局、
终局、时间不多了，各不相同。

**做什么**：

- 做一套采样音效，总大小 ≤ 100 KB。格式选 WebView2 和 WKWebView 都能播的（MP3 或
  AAC），经 zero:// 加载。每个文件的来源和许可逐条记录，只收 CC0 或 CC BY 这类与
  GPLv3 兼容的。
- 现在的合成音效保留，作为「经典」选项。
- 时间不多（< 20 秒）时，提示音只响一次。

**验收**：

- 真壳自检加一项：采样音频能解码（`decodeAudioData` 成功）。
- 每种事件的声音都不同：比对音频文件的哈希，不能两两相同。

## 9 · 动效与按压反馈

**依据**：动效已经有了好底子：一条缓动曲线，三档时长，「减少动态效果」分档，这些都
写在设计约束 §1 里，并且有测试守着。缺的是按压反馈：按钮按下去没有状态，页签切换时
内容是硬切。

**做什么**：

- 所有按钮加 `:active` 状态（颜色加深，或者下移 1px），加统一的 `:focus-visible` 描边环。
- 页签切换时，内容交叉淡入淡出，时长用 `--dur-base`。
- 吃子时，被吃的子淡出，不是直接消失。

**约束**：不新增缓动曲线，不新增时长档位（test-chess 守着）；「减少动态效果」打开时，
位移类动效全部停掉。

**验收**：test-chess 现有的动效断言全部照过；`:active` 和 `:focus-visible` 覆盖所有
`button`（静态扫 CSS）。

## 11 · 这一版不做的

- **3D 棋盘、真人头像、在线对弈**：不是质感问题，是新产品。
- **撒花、全屏庆祝动画**：与「减少动态效果」的分档理念冲突，也不是这个应用的调性。
- **「妙着」「好棋」这类分类**：模型没有依据，见 §5。
- **打包界面字体**：中日文字体一套 10MB 以上。系统字体（PingFang / SF，微软雅黑 /
  Segoe）在两个目标平台上都够好。
- **预走棋（premove）**：这是玩法，不是质感。放到以后再评估。
- **签名、公证、自动更新**：仍然缺证书。

## 12 · 怎么让「精致」可以验收

「精致」很容易变成一句说了不算数的话。7.7 这样处理：

1. **能量的都写成断言**：棋盘矩形在页签之间逐像素不变；toast 与棋盘不相交；每个按钮的
   内边距、高度；非数字文字不用等宽字体；每个上下文最多一个主按钮；界面里没有表情
   符号；高亮色的 ΔE。
2. **量不了的交给截图**。加一个 `scripts/shots.mjs`，把这次走查的 25 个状态固定下来，
   Chromium 和 WebKit 各截一套，CI 上作为 artifact 上传（不做像素比对），每个 PR 里贴
   前后对比。
3. **真机**。A0 与 J–O 从 5.2.0 起没人走过，7.7 的改动全在视觉上，必须有人在真的 Mac
   和 Windows 上看一眼。

### §8 声音

- 外部素材走不通：lila 的音效集是 AGPLv3 或 CC BY-NC-SA，标准木质音效在 COPYING.md 的
  「非自由例外」里；freesound、OpenGameArt、Kenney、Wikimedia 被代理拒绝（403）。
- 改为运行时渲染：`sound-bank.js` 用衰减正弦叠加（接触噪声 + 棋子高频模态 + 棋盘低频模态），
  第一次用时生成，没有音频文件，也就没有 zero:// 取文件的问题。走子起音 0.34ms、衰减到
  −40dB 82ms、频谱质心 2885Hz；吃子 188ms、1187Hz，更低更长。
- 14 个音效在 44.1k / 48k 下哈希两两不同（断言）；时间不多只响一次，回到 30 秒以上才重新
  武装；吃子同时将军只放将军。
- 真壳自检加 `sound`：14 个音效经 OfflineAudioContext 渲染，每段峰值 > 0.05。
- **与计划不同**：计划写的是 MP3 / AAC 文件和 `decodeAudioData` 自检；没有编码文件，所以
  自检改成离线渲染。音色没有人真的听过，只有上面这些数。

### §9 动效

这一块的提交里没有它，留到下一版。
