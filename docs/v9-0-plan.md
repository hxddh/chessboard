# 9.0 · 一块棋盘，一条路：把功能收成产品

写于 8.4.0 发布次日（2026-10-09）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

这一版的要求是你给的：**要有质变，更优雅，更易用，产品精致**。所以这份计划和前几版不同——前几版是「再加一样东西、再补一条账」，这一版是「把已经有的东西收拾成一个产品」。功能几乎不加，界面大改。

## 依据

四份评估，2026-10-09 做，原始报告在会话记录里，结论摘在下面各节：

1. **视觉审查**：8.4.0 的 28 张截图（`npm run shots`，1440 / 1024 / 760 / 600，四套主题，中英），对照 `docs/design-constraints.md` 与 `styles.css` 的 token。
2. **信息架构与任务流**：逐个视图、对话框、菜单、快捷键数入口；9 个核心任务从启动数点击；中文字典里给用户看的技术词。
3. **同类产品**：Chess.com（新首页、Game Review 改版、Puzzles）、Lichess（新移动端、谜题主题）、Duolingo Chess、Aimchess、Chessable、Apple HIG、Linear。chess.com 与 lichess.org 正文被代理挡住，结论来自搜索摘要。
4. **工程盘点**：样式、组件、护栏、存档键、降级测试——改版要动多少、哪里会碎。

**这次的局限**：截图是 Linux 上的 Chromium，字体与 macOS / Windows 不同（字体问题因此只能定性）；截图里「引擎初始化失败」是截图脚本用的引擎桩造成的，不是产品问题，已剔除；没有真人可用性测试。

## 0 · 结论先行

### 问题不在功能，在「收」

8.x 一路加下来，功能本身都站得住：棋盘渲染、主题 token、着法列表、动效纪律都是好的，审查里明确要保留。问题是**加法没有配上减法**：

| 现象 | 数字 |
|---|---|
| 设置散在 4 处 | 侧栏「设置」12 项、「偏好」对话框 34 个按钮（内容高 1,377 px、视口 866）、新对局对话框、页内局部设置 |
| 同一件事多个入口 | 新局 7 个入口；「今天的训练」2 处；开局书 4 处；残局营、看 N 步、开局浏览器各 2 处 |
| 选择过载 | 谜题侧栏一屏 20 个按钮（7 玩法 + 10 题型 + 复习混在题型里）+ 另一套 28 个主题，且「一步杀」等在两套里各有一份；新对局对话框 27 个控件，展开 53 个 |
| 一样东西三个名字 | 「满强度 / 不限档 / 引擎·满强度」；「做题评级 / 等级分 / 对局评级」；对手卡写 1420、开场白写 UCI_Elo 1500 |
| 实现细节给用户看 | 「Stockfish 限制在 UCI_Elo 1700」「置换表」「MultiPV 6」「（120ms/步）」「结论已查 Syzygy 残局库核对」「7.6 以前的合成音」「1500?」 |
| 组件各长各的 | 按钮 9 种样子、卡片 6 种、区块标题 5 种、分段控件 4 种实现 |
| 关键时刻粗糙 | 终局卡盖住棋盘中央，将杀现场看不见，同时还弹成就 toast |
| 空白没有设计 | 首页 3 张小卡占到 y≈216，下面 680 px 空着；对局面板一半是空的 |
| 窄窗不能用 | 760 宽时面板盖住棋盘 f–h 三列；600 宽抽屉把内容切掉 |

### 版本号：9.0

- **理由**：顶层结构、设置的位置、首页、训练的组织方式都变，老用户会第一眼看出不一样——这是大版本。
- **代价**：原来写给 9.0 的五件技术事（换引擎形态、SQLite、SDK 1.0、Chess960、第四种语言）一件都不在这一版，挪到「10.0 / 以后」。§8 第 1 条请你定。
- **存档**：格式不变（SCHEMA 仍是 2）。只有两个界面字段（`sideTab`、`view`）的含义会变，旧值读进来照样能用，降级测试照常跑四个旧版本。

### 9.0 的三个主题

| | 主题 | 一句话 |
|---|---|---|
| **S** | 结构 | 顶层 5 个去处 + 唯一的「设置」；学习与谜题合成「训练」；每件事只有一个家 |
| **V** | 视觉 | 一套收紧的设计语言：4 种按钮、2 层表面、2 级标题、打包 Latin 字体；棋盘是唯一的主角，任何浮层不盖 64 格 |
| **M** | 时刻 | 三个标志性瞬间：今天的首页、终局一刻、复盘拖动；外加窄窗重做 |

不做新内容。D（依赖）只有 Node 26 一项（10-28 进 LTS）。

### S1 今天（首页）【M】

- **依据**：首页三张卡信息量都很低（「棋盘上还没有对局」），而「今天的训练」在对局面板里又出现一次；Chess.com 新首页、Aimchess 都是「一个主动作 + 继续 X」，不做功能目录。
- **做什么**：
  - 主卡：一块 240 px 的**活棋盘**，摆着「接下来最该做的那件事」的局面，按优先级：未完成的对局 → 到期的复习（谜题 / 开局书 / 看 N 步）→ 上一局没看的关键失误 → 下一课。点一下就进去。卡上写清是什么、约几分钟。
  - 旁边：今日三格进度（课 / 题 / 局）。
  - 下面一行「继续」小卡：上次的课、上次的残局、上次的名局——**写明是哪一个**（现在首页会把残局说成「上次在上课」）。
  - 「下一步建议」并进主卡；下棋侧栏里的「今天的训练」删掉。
- **验收**：首页首屏没有空白区大于一张卡；任务 a / d / f（上表）各 1 次点击。

### S2 下棋【M】

- **做什么**：
  - 新对局对话框：8 张对手卡、4 个常用棋钟（无 / 5 / 10 / 15+10）、执子；21 档、4 种风格、自定义棋钟收进「更多选项」。
  - 侧栏只留：棋谱、复盘、本局操作。侧栏「设置」页签取消（它的 12 项去设置或去新对局）。
  - 复盘只有一个「分析」按钮，精析在它的下拉里；「持续分析」进设置的「高级」。
  - 底部工具行固定 5 个位置，其余进「更多」；「导出复盘图」并进「导出」。
- **验收**：任务 b ≤ 3 次点击、不滚动；对话框一屏放下（1440×900 与 1024×768）。

### S3 训练（学习 + 谜题合一）【L】

- **依据**：谜题侧栏一屏 20 个按钮，两套分类重叠；学习目录 290 项平铺，名局和名局猜着把同样 40 局列两遍；Chess.com / Lichess 都是「一个开始按钮 + 主题在二级页」。
- **做什么**：顶部 4 个分段：
  - **课程**：120 课按 14 个单元做成卡片，显示进度。
  - **谜题**：一个主按钮「为你出一题」（混合、计分）；下面一套 6 类（杀棋 / 战术 / 残局 / 防守 / 开局 / 我的错题），内置 1,386 题和 Lichess 4 万题按类合并，不再分两套；冲刺、连胜收进「挑战」；看 N 步、盲走收进「专项」；复习是一个独立入口，写明到期几道。
  - **残局**：90 个，按 5 组。
  - **名局**：40 局，「读 / 猜」是一个开关，不再列两遍。
- **验收**：任务 e ≤ 2 次；谜题首屏按钮 ≤ 8 个；「我的」页不再有训练入口的重复。

### S4 棋谱【S–M】

- 棋谱库、开局书、对局历史（从「我的」挪来）、开局浏览器放一处。导入统一为「导入到库」，从库里再打开到棋盘；侧栏「更多 → 打开」改名为「打开到棋盘（不入库）」。筛选默认只露搜索和结果，其余在「筛选」里。

### S5 设置（唯一的一处）【M】

- **依据**：Apple HIG 的设置窗口（⌘,、分页签、即改即生效）；偏好对话框现在是一个 1,377 px 的长滚动，「清除数据」和「外观」同级，「外观」标题写了两遍。
- **做什么**：左侧分类、右侧内容的设置面板：
  - **通用**：语言（第一屏顶部）、外观（明暗）、字号
  - **棋盘**：棋盘、棋子、边框、坐标、方向、盲棋——棋子用 48 px 实物预览，旁边一块 4×4 小棋盘实时显示组合
  - **声音**
  - **对局**：默认对手、棋钟、失着提醒、自动翻转
  - **数据**：同步、导入导出、清除
  - **高级**：引擎（置换表、分析线数、持续分析）、引擎箭头、存疑标注
  - 原生菜单补上「设置…」（⌘, / Ctrl+,）和五个去处。
- **验收**：任务 h、i 各 ≤ 3 次点击、不滚动；设置只有一个入口家族（齿轮、⌘,、菜单）。

### S6 文案：把实现细节从界面上拿掉【S】

- 15 条最差的（开场白里的 UCI_Elo、「置换表」、「MultiPV」、「（120ms/步）」、「Syzygy」、「7.6 以前的合成音」、「1500?」……）逐条改写成用户的话；技术说明保留在 README 和 tooltip 的「高级」里。
- 一个东西一个名字：「不限档」一个名字；评级处处叫「等级分」；对手卡上的分数与开场白一致（用实测分，不用 UCI_Elo）。
- **验收**：静态测试加一条守卫：界面字典里不得出现 `UCI_Elo`、`MultiPV`、`Syzygy`、`ms/步` 这类词（登记册只减不增，「高级」分组例外）。

## 2 · 视觉：一套收紧的语言

### V1 设计语言 v2【M】

- **依据**：按钮 9 种、卡片 6 种、区块标题 5 种（英文全大写宽字距、中文粗体灰字两套层级）、分段控件 4 种实现、虚线框套实线卡；7 档字号都在用但没有角色。
- **做什么**（先写进 `docs/design-constraints.md`，测试守住）：
  - **按钮 4 种 × 2 尺寸**：主 / 次 / 幽灵 / 危险 × 36 / 32，单行不换行，外加图标按钮。
  - **表面 2 层**：背景与 raised，靠 1 px 发丝线 + 4% 明度差；**删掉所有虚线框**；空状态是居中图标 + 一句话 + 一个动作，不画框。
  - **标题 2 级**：区块标题 13/600 muted、不转大写，中英日同一规则；字段标签 13/400。删掉重复标题。
  - **字号 4 个角色**：30 结果数字 / 16 区块 / 14 正文 / 12 辅助（11 只给坐标和徽章）；字重只用 400 / 600。
  - **8 pt 节奏**：区块 24、组内 12、卡内 16；同一容器里网格列数不变。
  - **颜色克制**：每套主题一个强调色，只用在主按钮、当前着、选中态；状态色只表状态。木纹主题的上一手高亮改成低饱和黄铜色。
  - **数据用细线**：曲线、进度、评级趋势 = 1.5 px 线 + 8% 填充，颜色走 token。
- **验收**：组件计数守卫（按钮类、卡片类、标题类各有上限）；28 张截图前后对照。

### V2 字体【S–M】

- **依据**：没有打包字体；Windows 上 Latin 落到 YaHei 自带的拉丁字形，和 CJK 混排灰度不一致；CJK 粗体糊；11 px 标签难读。
- **做什么**：打包一款开源 Latin 可变字体（候选 Inter，OFL，含等宽数字），放在 `resources`，不进主包；排在 CJK 字体之前；CJK 粗体用 500/600；开 `text-autospace`（支持的地方），中日行高 1.6–1.75、英文 1.4–1.5；着法、时钟、分数统一等宽数字。
- **验收**：安装包体积增加 ≤ 400 KB（§8 第 3 条）；三语截图验收。

### V3 棋盘周边【M】

- **依据**：棋盘没居中；☰ 孤悬在棋盘右上角外；比分挂在棋盘右侧；学习页没有玩家栏，上面空 72 px；评估条的「+#」掉在棋盘外。
- **做什么**：棋盘上下两条**同宽的固定玩家栏**（左：头像、名字、子力；右：时钟 / 比分 / 动作），☰ 并进上栏；学习、谜题页也有这条栏（写课名 / 题目）；评估条贴着棋盘边框，标签在条内；棋盘在舞台里居中。
- **验收**：布局测试：三种模式下玩家栏与棋盘等宽、对齐；棋盘外没有孤立元素。

## 3 · 时刻：三个标志性瞬间 + 窄窗

### M1 终局一刻【M】

- **依据**：终局卡 360×190 盖在 c3–f6，将杀现场被挡；同时弹成就 toast、徽章 40 px 压住王冠。
- **做什么**：棋盘保持完整；被将死的王所在格亮一圈细环；**胜方玩家栏展开成结果条**（1–0 · 将杀 · 等级分 +305），下方滑出「再来一盘 / 复盘这局」；成就作为小徽章落在条内，不再弹 toast；徽章缩到 24 px 贴格角。
- **验收**：布局测试：终局时没有任何元素与 64 格相交（除格角徽章）。

### M2 复盘两层 + 曲线拖动【M–L】

- **依据**：Chess.com Game Review 改版：摘要在上、关键着可重试、完整报告在后；我们已有关键时刻卡（`km-card`）和重试（`review/retry.js`），但它们埋在一长串报告里；胜率曲线是整屏最亮的白色大块。
- **做什么**：
  - 第一层：一句话总结（用当前对手的口吻）+ 1–3 个关键时刻，每个「在棋盘上重试」。
  - 第二层「完整报告」：精准度、分类表、曲线。
  - 曲线改细线；**在曲线上拖动，棋盘同步走到那一步**；失误点是带 ?/?? 颜色的小菱形，悬停显示「应走 Nf3」并在棋盘上画迷你箭头。
- **验收**：任务 c 1 次点击；拖动时棋盘每帧跟随（帧间隔守卫沿用 automation 的阈值）。

### M3 窄窗【M】

- **依据**：760 宽时面板盖住棋盘三列；600 宽抽屉只露 240 px、内容被截。
- **做什么**：竖窗规则提前到 ≤ 900 宽生效：棋盘在上、抽屉在下，三档吸附（收起 / 一半 / 九成）；横向着法条和竖向棋谱只留一个；顶部图标条加当前去处的文字。
- **验收**：760、600 两档：棋盘 64 格完全可见、可下；抽屉三档内容不被截断。

## 6 · 这一版不做的

- 新内容（课程、题库、名局、残局）；
- 命令面板（⌘K）——有价值，但先把一处设置、五个去处做干净，下一版再加；
- 原来的 9.0 技术项：换引擎形态、SQLite、SDK 1.0、Chess960、第四种语言（10.0 / 以后）；
- macOS 签名、公证、自动更新（缺证书）；
- 首启定级问卷（「你会下棋吗」三档 + 导入账号）——好主意，但牵动天梯与谜题初始分，单独一版做。

## 8 · 需要你拍板的

1. **版本号 9.0**，原来的 9.0 技术项挪到 10.0 / 以后？
   - **建议**：同意。这一版用户第一眼就会看出不一样，配得上大版本；技术项没有一件是用户看得见的。
2. **先出设计稿（M0），你看过再动代码？**
   - **建议**：要。「优雅」「精致」只能看着判断；先用真实样式出 5 个画面，改起来最便宜。
3. **打包一款 Latin 字体**（候选 Inter，OFL 授权，安装包约 +300 KB）？
   - **建议**：打包。Windows 上中英混排的灰度不一致，是「不精致」最大的一个来源，系统字体解决不了。
4. **主包线**：9.0 允许主包比 8.4.0 多 20 KB（前几版是 10 KB）？
   - **建议**：20 KB。结构改动要新增模块的入口代码；新画面本身尽量放分块。
5. **训练合并**：学习和谜题合成一个「训练」，内置题与 Lichess 题按类合一？
   - **建议**：合。这是「易用」里收益最大的一条；两套重叠的分类是现在最难懂的地方。
6. **设置只留一处**：取消侧栏「设置」页签，难度 / 棋钟这类「这一局」的选择只在新对局里？
   - **建议**：同意。代价是对局中途换难度要多一步（新对局或设置里改默认），但「设置在哪」从此只有一个答案。
7. **窄窗**：≤ 900 宽统一用「棋盘在上、抽屉在下」？
   - **建议**：同意。760 现在等于不能下棋。
8. **真机**：9.0 的界面改动大，发布前能否在你的 Mac 或 Windows 上过一遍 M0 设计稿和 M4 的候选版（各约 10 分钟）？不过也照样发，但这一版尤其值得。
