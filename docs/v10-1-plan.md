# 10.1 · 精修：字体、表面、控件、棋盘细节

写于 10.0.0 发布当天（2026-10-10）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

10.0 把训练接成了闭环。这一版不加功能，只回答一句反馈：**「总感觉有些粗糙，没有 macOS 下顶级产品那种精致、细腻、清晰、优雅」**。

**已定（2026-10-10）**：按评估的建议做；字体一并评估、一并改。

## 1 · 窗口外壳（W）——**这一版不做，等 SDK**

**依据**：`hidden_inset` 让红绿灯嵌进内容、侧栏通到顶，是 Mac 应用的标准外形。但 SDK 0.10.1 的拖动区只给它自己的画布控件用（`start_window_drag_fn` 要求 `NSApp.currentEvent` 正是那次按下）；WKWebView 盖住标题栏后，网页里没有办法声明「这里可以拖窗口」，经桥异步调过去时当前事件已经不是按下。没有 Mac 可测，一个拖不动的窗口比灰标题栏糟得多。

**做什么**：不改 `app.zon`。SDK 出了网页拖动区（或 `-webkit-app-region` 一类的支持）再做，并同时让标题栏的明暗跟主题走。

## 2 · 字体（F）

### F1 · 中文、日文里的标点交给中文字体

**做什么**：新加两个只含标点的 `@font-face`（「CJK Punct SC」「CJK Punct JA」），`unicode-range` 只有 U+00B7、U+2013–2014、U+2018–201D、U+2026，`src` 用 `local()` 指向系统里的苹方 / 冬青 / 雅黑 / 游ゴシック 各字重；中文、日文的字体栈把它放在最前。英文界面不受影响。

**验收**：静态守卫——两张标点字体只含这几个码位，并排在中文、日文栈的最前；英文栈不含它们。

### F2 · Mac 用系统字体

**做什么**：字体栈在 Inter 前加 `-apple-system`。它只在 WebKit 里有效：Mac（WKWebView）落到 SF + 苹方 / 冬青，Windows（WebView2，Chromium）忽略它、照旧 Inter + 雅黑，不用按平台写分支。9.0 V2「Mac 与 Windows 同一个西文字面」的取舍改为：Mac 用系统字体，Windows 保留 Inter（它要解决的雅黑西文偏灰只在 Windows）。

**验收**：静态守卫——中、英、日三个栈都以（标点字体，）`-apple-system`、`"Inter Var"` 开头。

### F3 · 字重：两档照旧，但 600 只给标题和关键数字

**依据**：9.0 V1 定的两档（400 / 600）是对的——雅黑没有 500，Windows 上 500 会让同一个按钮里中文常规、西文中粗。问题是 600 用得太多。

**做什么**：
- `b, strong, h1–h4` 的默认粗细从浏览器的 700 收到 600。
- 600 只留给：页面标题、卡片 / 对话框标题、关键数字（等级分、精准度、比分、棋钟）、当前项标记。
- 按钮、分段控件、标签、导航、小节标题、徽章一律 400。小节标题改用字号与灰度区分。

**验收**：静态守卫——600 的规则数 ≤ 30（现在 72）；仍只有 400 / 600 两档。

### F4 · 字号补一级标题，大字收字距

**做什么**：加 `1.125rem`（18 px）一级给卡片与对话框标题；30 px 大标题 `letter-spacing: -0.02em`；中文界面不再有 11 px 的字（徽章、小标签到 12 px）。

**验收**：静态守卫——字号阶梯 12 / 13 / 14 / 16 / 18 / 30；`0.6875rem` 不再出现。

### F5 · 行高分开：界面文字与成段文字

**做什么**：中文 `--lh-body` 1.6 → 1.5，`--lh-prose` 1.75 不变，课程正文、教练解释、说明段落显式用 `--lh-prose`。

**验收**：布局测试照过；截图前后对比。

## 3 · 表面与控件（S / C）

### S1 · 三层表面拉开、边框减半

**做什么**：每个主题的「背景 / 抬起 / 卡片」三层明度拉开；卡片默认去掉 1px 边框，改靠底色区分，只有卡片与背景同色时保留一条极淡的边；卡片里再套的块（卡中卡）去掉边框与底色，改分隔线。

### S2 · 一级阴影

**做什么**：对话框、命令面板、弹出菜单用一套阴影（大而淡、两层）；卡片不用阴影。

### C1 · 分段控件照 macOS

**做什么**：轨道是一条凹下去的浅底，选中项是抬起来的一片（卡片色 + 细阴影），不再是描边块；文字 400。

### C2 · 一个强调色

**做什么**：实心强调按钮全局只用一种（主题的 accent）——查下来 10.0 已经如此（夜间主题的强调色就是那道薄荷绿）；这一版去掉的是分段控件选中态上的强调色描边，次要按钮统一成一种样子。

**验收（S / C）**：现有布局与对比度测试照过；`test-brand` 照过；截图前后对比。

## 9 · 落地记录

### F · 字体（97e41b7）

- **F1**：四个 `local()` 标点字体（中 / 日 × 400 / 600 两档），只含 U+00B7、U+2013–2014、U+2018–2019、U+201C–201D、U+2026；排在中文、日文栈最前，英文栈不用。本机（Linux，只有文泉驿）用同样的写法验证过：标点走中文字体、西文走 Inter。守卫：四个字体、码位、只用 `local()`；三个栈的开头。
- **F2**：`-apple-system` 排在 Inter 前。WebKit 之外不认这个关键字，所以不用按平台写分支；9.0 V2「两平台同一西文字面」的取舍改为 Mac 用系统字体。
- **F3**：600 的规则 72 → 29（守卫 ≤ 30）；`b, strong, h1–h4` 默认 600。中途把区块标题（`.side-h`、`.act-k`）和棋盘坐标也改成了 400，又改回 600：13 号粗体灰字正是 macOS 侧栏小节标题的画法，坐标 11/600 是 design-constraints 里写明的可读下限。
- **F4**：18 号进刻度（7 档，守卫随之改为 seven）；`.pick-tag`、`.preview-badge`、`.preview-try` 11 → 12 号。坐标、图标下的字、数字仍是 11。30 号大字没加负字距：Mac 上的 SF 自己按字号收字距，再加会过紧。
- **F5**：中文 `--lh-body` 1.6 → 1.5；布局五片与其余套件照过。

### S / C · 表面与控件（5da9c8a）

- `--card-border` 向卡片底色收 45%；`--btn-lift`（白 10% 混入）、`--btn-edge`（墨色 11%）、`--control-shadow`、`--seg-tray`、`--seg-on`、`--shadow-pop` 都在组件层声明一次，四套主题不用各自改原始色。
- 守卫改为新的形状（托盘无线有底色、选中段抬起且不用强调色、次要按钮抬起 + 细边 + 阴影）；布局测试「没有一个动作是无边框的文本链接」改为看托盘有没有自己的底色。
- 十个浏览器并行时复盘一套的「按住 600 毫秒」两条超时，单独重跑通过——是并发负载，不是这次的改动。

### B / L · 棋盘与页面

- B1：「继续」缩略图 64 → 80 px。B2：格角徽章半径 0.19 → 0.16、结果徽章 0.15 → 0.13（圆心不动，棋盘测试取样点仍在圆内）。B3：见上，不改。
- 进度圈：圈宽 20% → 13%，轨道改墨色 10%，72 → 80 px；L2：「今天」卡三行网格，圈居中。
- L3：`#lib-explorer` 从卡片下的独行挪到「我的开局书」标题右侧（`tool-txt`，和今天页「全部棋谱」同一个写法）。L4：行首的文字按钮左缩 12px，与上面的文字对齐。
- L1（下棋页右栏）：看过截图，开局前说明卡与工具行贴在一起，没有漂；不改。

### S1 补完 · F4 / F5 补完（用户要求在 10.1 里做完，不留到下一版）

第一轮交付时 S1 只把卡片边线减淡了一半、F4 留下了图标下 11 号的中文、F5 没逐个核对成段文字——用户问「规划的内容都完成了吗」时如实报了，决定补完再发。

- **S1 三级表面**：四套主题的卡片色比面板亮一步（木 #30241a → #382b20、夜 #111d1a → #16241f、日 #f8f1e4 → #fdf9f2、纸 #f4f7fe → #fbfcff）；9.0「卡片 = 面板」的守卫改为「卡片比面板亮、且只亮一步（亮度差 ≤ 16）」，design-constraints 的「表面 2 层」改为 3 级。
- **S1 卡片去边**：20 条卡片容器规则（今天、设置、棋谱、我的、谜题面板、复盘报告、对局结束……）改用 `--card-edge`（原边线的三成，几乎只在浅色主题上看得见）；分隔线、表格、输入框仍是 `--card-border`。
- **S1 卡中卡**：新对局对话框里的对手卡原来是「对话框里的深色卡片 + 边线」，改成凹下的托盘、选中的抬起（同分段控件），强调色只留在选中项的细边上。复盘条（« ‹ › »）的外框是 7.9 §1c 有意留下的（四个键要有可按的边界），不改。
- **F4**：图标下的字（「开局」「更多」……）、开局浏览器里的「书」「我的」11 → 12 号；布局测试的「11px 的字不出格子」改为 12px，并从「小于 12px」的豁免名单里去掉它们；新静态守卫：11 号只给坐标、?! 标记、图表与步骤圆点里的数字、开局浏览器的百分比条。
- **F5**：复盘关键时刻的「为什么」（`.km-why`）与失误说明（`.why-text`）改用段落行高 1.75；课程正文（`.lesson-text p`）原本就是。
- 谜题面板的「按主题细分」：L4 的规则被 `#pz-themes-row .tool-txt { margin-left: 0 }` 盖住了，第一轮截图里仍缩进——改为 -12px。

### 验收

- **截图对比**：37 张全部重拍（两倍像素，Chromium，四套主题、1440 / 1024 / 760 / 600 宽、三种语言），与 10.0.0 的同一组并排看过。
- **对比度回归**：夜主题新对局对话框里，选中的对手卡抬起后变亮，灰色的风格说明掉到 4.17:1（布局 3/5 抓到，CI 与本地一致）；选中行的字改用整行墨色。
- **测试自身的竞态**：repertoire e2e 拦住 chunk-rep.js 后 `page.reload()` 等 "load"，分块若在 load 之前被请求就互相等死（CI 一次 30 s 超时）；改为等 domcontentloaded，之后照旧等 `window.__chess.rep`。
- 本地全部浏览器套件（Chromium）通过；静态、learning、manifest-check 通过。
