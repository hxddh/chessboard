# 10.1 · 精修：字体、表面、控件、棋盘细节

写于 10.0.0 发布当天（2026-10-10）。规矩照旧：每条写**依据**、**做什么**、**验收**，发布前补**落地记录**。

10.0 把训练接成了闭环。这一版不加功能，只回答一句反馈：**「总感觉有些粗糙，没有 macOS 下顶级产品那种精致、细腻、清晰、优雅」**。

**已定（2026-10-10）**：按评估的建议做；字体一并评估、一并改。

## 依据

两次评估，2026-10-10 做：

1. **界面**：10.0.0 的 37 张截图（`OUT=… DPR=2 node scripts/shots.mjs`，Chromium，四套主题、1440 / 1024 / 760 / 600 宽、三种语言），加 `styles.css` 的用量统计。
2. **字体**：字体栈、`@font-face` 的 `unicode-range`、字号 / 字重 / 行高的用量，加一张标点对照图。

**局限**：截图是 Linux 上的 Chromium，中文落到文泉驿正黑——它没有真的半粗体，合成的粗体把「重」放大了；Mac 上的苹方 / SF 与 Windows 上的雅黑都没法在这里拍。WebKit 截图在本机缺可执行文件。Mac 上的实际观感要用户的截图来确认。

## 1 · 窗口外壳（W）——**这一版不做，等 SDK**

**依据**：`hidden_inset` 让红绿灯嵌进内容、侧栏通到顶，是 Mac 应用的标准外形。但 SDK 0.10.1 的拖动区只给它自己的画布控件用（`start_window_drag_fn` 要求 `NSApp.currentEvent` 正是那次按下）；WKWebView 盖住标题栏后，网页里没有办法声明「这里可以拖窗口」，经桥异步调过去时当前事件已经不是按下。没有 Mac 可测，一个拖不动的窗口比灰标题栏糟得多。

**做什么**：不改 `app.zon`。SDK 出了网页拖动区（或 `-webkit-app-region` 一类的支持）再做，并同时让标题栏的明暗跟主题走。

## 2 · 字体（F）

### F1 · 中文、日文里的标点交给中文字体

**做什么**：新加两个只含标点的 `@font-face`（「CJK Punct SC」「CJK Punct JA」），`unicode-range` 只有 U+00B7、U+2013–2014、U+2018–201D、U+2026，`src` 用 `local()` 指向系统里的苹方 / 冬青 / 雅黑 / 游ゴシック 各字重；中文、日文的字体栈把它放在最前。英文界面不受影响。

**验收**：静态守卫——两张标点字体只含这几个码位，并排在中文、日文栈的最前；英文栈不含它们。

### F2 · Mac 用系统字体

**做什么**：字体栈在 Inter 前加 `-apple-system`。它只在 WebKit 里有效：Mac（WKWebView）落到 SF + 苹方 / 冬青，Windows（WebView2，Chromium）忽略它、照旧 Inter + 雅黑，不用按平台写分支。9.0 V2「Mac 与 Windows 同一个西文字面」的取舍改为：Mac 用系统字体，Windows 保留 Inter（它要解决的雅黑西文偏灰只在 Windows）。

**验收**：静态守卫——中、英、日三个栈都以（标点字体，）`-apple-system`、`"Inter Var"` 开头。

### F3 · 字重：两档照旧，但 600 只给标题和关键数字

**依据**：9.0 V1 定的两档（400 / 600）是对的——雅黑没有 500，Windows 上 500 会让同一个按钮里中文常规、西文中粗。问题是 600 用得太多。

**做什么**：
- `b, strong, h1–h4` 的默认粗细从浏览器的 700 收到 600。
- 600 只留给：页面标题、卡片 / 对话框标题、关键数字（等级分、精准度、比分、棋钟）、当前项标记。
- 按钮、分段控件、标签、导航、小节标题、徽章一律 400。小节标题改用字号与灰度区分。

**验收**：静态守卫——600 的规则数 ≤ 30（现在 72）；仍只有 400 / 600 两档。

### F4 · 字号补一级标题，大字收字距

**做什么**：加 `1.125rem`（18 px）一级给卡片与对话框标题；30 px 大标题 `letter-spacing: -0.02em`；中文界面不再有 11 px 的字（徽章、小标签到 12 px）。

**验收**：静态守卫——字号阶梯 12 / 13 / 14 / 16 / 18 / 30；`0.6875rem` 不再出现。

### F5 · 行高分开：界面文字与成段文字

**做什么**：中文 `--lh-body` 1.6 → 1.5，`--lh-prose` 1.75 不变，课程正文、教练解释、说明段落显式用 `--lh-prose`。

**验收**：布局测试照过；截图前后对比。

## 3 · 表面与控件（S / C）

### S1 · 三层表面拉开、边框减半

**做什么**：每个主题的「背景 / 抬起 / 卡片」三层明度拉开；卡片默认去掉 1px 边框，改靠底色区分，只有卡片与背景同色时保留一条极淡的边；卡片里再套的块（卡中卡）去掉边框与底色，改分隔线。

### S2 · 一级阴影

**做什么**：对话框、命令面板、弹出菜单用一套阴影（大而淡、两层）；卡片不用阴影。

### C1 · 分段控件照 macOS

**做什么**：轨道是一条凹下去的浅底，选中项是抬起来的一片（卡片色 + 细阴影），不再是描边块；文字 400。

### C2 · 一个强调色

**做什么**：实心强调按钮全局只用一种（主题的 accent）；夜间主题「为你出一题」的薄荷绿大条改成普通主按钮；次要按钮是淡底无边或细边，不再三种样式混用。

**验收（S / C）**：现有布局与对比度测试照过；`test-brand` 照过；截图前后对比。

## 4 · 棋盘细节（B）

- **B1 缩略图**：今天页「继续」的小棋盘（约 64 px）只画格子与关键子——按格宽决定：每格 < 12 px 时不画子，只画最后一步与王的位置。（实现时再看：也可以把缩略图放大到 88 px。）
- **B2 复盘徽章**：「#」「1」等徽章缩到格宽的 22%，挪到格角之外一半，不压棋子。
- **B3 评估条**：左下角漏出的「+#」文字修掉（文字只在条宽够时画，或收进条里）。

---

## 5 · 留白与对齐（L）

- **L1 下棋页**：右栏开局前的空白——说明卡与「开局 / 更多」工具行贴在一起，不漂在中间。
- **L2 今天页**：hero 卡与「今天」卡等高时，「今天」卡的内容垂直居中，不留下半截空。
- **L3 棋谱页**：开局书的四个按钮成一组，不让「开局浏览器」单独折到下一行。
- **L4 谜题面板**：「按主题细分」与上下文对齐。
