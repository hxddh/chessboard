> 都实测过，都判定「不该改」，条目划掉并就地记下数字与理由（见

## 哪些条已经由构建期检查看着（P0.4）

「必须先说明理由」只有在违背它会被发现时才成立。以下几条已经不靠自律，
`scripts/test-chess.mjs` 每次 `npm test` 都在查（下面每条括号里是断言的名字）：

| 约束 | 检查 |
|---|---|
| 字号 7 档、行高 3 档、时长 3 档、圆角 token 化，**不要新增档位** | 值必须落在刻度上，且**刻度本身的档数**也被断言 —— 想加一档，得改测试里的那个数字，改动看得见（`the type scale still has seven steps`） |
| 一条缓动曲线 | `one easing curve, everywhere` |
| 格子颜色归主题 token，canvas 去读 | 四套主题各自必须定义 10 个 `--sq-*` / `--danger` / `--primary-from`；board.js 不得写死格子色 |
| **每处格子平涂必须走 `cellRect()` 取整** | `every square fill goes through cellRect()`。目前登记着 1 处例外（缺陷 10），登记数只减不增 |
| 棋子精灵只缓存一个尺寸 | `the sprite cache still holds one size` |
| 动画时长统一读 `--dur-base`，canvas 也读它 | board.js 必须 `getPropertyValue("--dur-base")`，且不得留下写死的毫秒数 |
| **每个 `var()` 都得指向真实存在的 token** | `no new var() names a missing token`。目前登记着 `--fg`（缺陷 9） |
| **主题块以外不得新增裸色值** | `no colour is written in place that was not already there`。9 个已上线的写在册子里，其中 4 个是缺陷 8 —— 册子只减不增，P2 负责清空 |
| 内容翻译表按 id 取，不以文案为键 | `no content translation table is keyed by prose` |
| 一个 i18n 键在一份字典里只能写一次 | `no key is defined twice in any dictionary`（缺陷 4 就是这条缺席的产物） |
| 每个 i18n 键都得有控件在读 | `every one of the N keys is read by some control` |

**登记册（register）这个做法**：几条检查带一份「已上线的例外」清单，断言的是
「不得新增，且册子里的每一条都还在」。后半句同样重要 —— 修好一条却忘了从册子里
划掉，测试会提醒你划掉它。册子因此既是护栏也是待办清单。

## 1 · 动效

| 约束 | 理由 |
|---|---|
| 棋盘尺寸变化**不做**动画（只过渡 background / box-shadow），面板照旧滑动 | 实测面板收起时棋盘增幅 +5% / +20% / +84%（三种窗口形状）；大幅尺寸动画会引起注意力抖动 |
| 动画只给「用户没亲手走的那一步」 | 见 `animateReply()` 注释：自己拖的子已经在手上，再补一段滑动是重复叙述 |
| 易位时王车同行 | 两个子动，视觉上必须同时发生 |
| 被拒绝的落子滑回原格，不闪回 | 「不行」是一个需要被画出来的状态 |
| 「减少动态效果」分档而非全关：停 13 条位移动画 + canvas 滑动，保留 12 条纯颜色过渡 | 颜色过渡不引起眩晕，位移会 |
| 动画时长统一读 CSS 的 `--dur-base`（3 档），canvas 也读它 | 单一来源；board.js 早期写死 150ms 已改掉，文档注释仍是旧值（需修正） |

## 2 · 棋盘绘制

| 约束 | 理由 |
|---|---|
| canvas 渲染，不改 DOM | 64 格 + 拖拽动画，canvas 正确 |
| 每处格子平涂必须走 `cellRect()` 取整 | 小数边界在某些尺寸下会糊出接缝。**当前教学成功闪烁未取整，是唯一例外，属缺陷** |
| 棋子精灵只缓存一个尺寸 `round(step)` | 换尺寸会重栅格化 12 个子 |
| 键盘光标用双线描边 | 要同时压在浅格/深格/白子/黑子上 |
| 格子颜色归主题 token（`--sq-*`），canvas 去读 | 单一来源 |

## 3 · 排版

- 字号 7 档、行高 3 档、时长 3 档、圆角已 token 化 —— **不要新增档位**。
- 侧栏 42 处文本已收敛到 11 种组合。
- 棋盘坐标 11px / 600 是可读下限，不要再小。
- 数字用 `--font-num`（tabular）：时钟、评分、着法号已在用。

## 4 · 布局

- 竖窗（`max-aspect-ratio`）改底部抽屉，不是压窄的侧栏。
- 侧栏宽 284px 是三层导航能容纳的下限。
- `flex: 1 1 30%` 会让第四个按钮长成主按钮的宽度 —— 分段控件必须等宽网格。
- `[hidden] { display: none !important }` 的 `!important` 是必需的：作者的 display 规则会盖掉它。

## 5 · 引擎与陪练

| 约束 | 值 | 理由 |
|---|---|---|
| 单 worker，`exclusive()` 串行 | — | 对局搜索与复盘分析永不交叉 |
| `gen` 计数器 + 每个 await 后重查 | — | 悔棋/新局/导入要让在飞的结果作废 |
| 每次搜索前 `isready` 排空 | — | UCI 按序处理，readyok 一定在残留 bestmove 之后 |
| 每档**全部重设** UCI 选项 | — | UCI 选项是黏的 |
| 最短思考时间 | 350ms | 深度档瞬间返回，压一下才像在思考 |
| 时间预算（四档棋力） | 500 / 700 / 900 / 1200ms | 陪练两档不走时间预算，用 depth 2 + MultiPV 抽样 |
| 新手档 `worstBias` | **0.2**，不是 0.6 | 0.6 时实测被打出 81% 得分率 —— 那是自己送棋 |
| 风格 slack | greedy 450 · attacker 320 · principled 90 厘兵 | 偏离最优的上限 |
| 已算出的杀绝不放弃 | `best ≥ 100000−50` 时风格模块返回 null | 风格不能送掉必胜 |
| 未评估局面画 `null`，不是 0.5 | — | 「引擎说均势」和「没人问过引擎」是相反的两件事 |

## 6 · 数据身份

- 开局题 id 由 **ECO + 着法 hash** 派生，不用数组位置：插入一条线会让 108 个 id 漂移。
- 旧 id 映射表必须**冻结成数据**，不能从当前棋谱推导 —— 推导只对「没跳过这个版本的人」成立。
- 复习排期按**解出次数**而非日期：这是离线、开得不规律的应用，按日期会「离开两周后一次性倒出来」。
- 连续两次干净解出才毕业；队列「最不熟的排前面」。
- 存档槽存 `mode` / `diff` 的 **id** 而非成品标签：中文存的档切英文界面要显示英文。
- 零着存档（摆好局面未走）必须保得住 —— `load_pgn` 不收「只有 FEN 头」的形状。
- 恢复存档时先把终局状态填回 `statsRecordedSig`，防止同一局记两次战绩。

## 7 · 原生层（host.js 侧）

- 能力一律问 `platform.supports` 并缓存，不靠「方法存在不存在」猜。
- 存储写入 256 KiB 截断；注意路径分隔符差异。
- 清单里声明的每个键，runner 必须真的在读（原由 `manifest-check.mjs` 守）。

## 8 · 文案

- 同一句话不在屏幕上出现两次：`statusText()` 侧栏开时只显示课名，关闭时才显示整句任务。
- 开局题走错说「违背了哪条原则」，不说「这不是谱着」—— 这是全应用最好的一处反馈设计，是其他模块该对齐的标杆。
- 建议有优先级：`recommendation()` 把「课程没上完」排在「该升难度」之前，不是把所有建议一起倒出来。
- 手写 `**加粗**` 解析必须对落单星号做保护。

### 高优先

1. ✅ **无败局音效** —— `audio.js` 只有 playWin/playStar/playDraw。被将死（app.js:447）、超时判负（:560）、**用户主动认输**（:3342）三处都播放胜利号角。需加 `playLoss`，并按「谁赢」而非「有没有将死」分派。
2. ✅ **导出复盘图在白底上几乎不可见** —— `renderReportCanvas()` 用 `--card` 作底色（木 4% / 夜 3% 白的叠加层）+ `--text` 作文字。木/夜主题导出的 PNG 贴到任何白底文档里 = 近白字在白底上。导出需要一套**不透明**的专属配色，与界面主题无关。
3. ✅ **`storageSet()` 的返回值 11 处全被丢弃** —— `host.js` 刻意返回 true/false 并自己 catch，app.js 11 处调用（存档、设置、教学进度、做题进度 ×2、统计 ×3、成就、槽位、面板状态）无一读它，且全部待在空 catch 里。写入失败时应用继续正常显示进度，直到下次启动归零。

### 一致性 / 口径

13. ✅ **统计主键是 `game.pgn()`** —— 同走法两局撞键（短杀很容易）。已靠「遍历到最后一个未标注的匹配」化解（recordAccuracy），但那是启发式。记录里已有 `t: Date.now()`，应发 id。另：`game.pgn()` 在 80 手对局上要 3.3ms，而它同时是主键、缓存钥匙和渲染路径上的比较对象。
14. ✅ **难度分档在 6 / 8 个类别里有空档位**，共 7 个空组合（一步杀的中等+较难、三步杀的简单、吃子的较难、求和的较难、防守的简单）。根因：`puzzleTier()` 主项 `(plies−1)×1.5`，而杀王三类的 plies 是写死常量（m1=1/m2=3/m3=5），贡献 0/3/6 分；其余全部变量合计最多 ±4.5，跨不过 3 分一档的门槛。**难度实际编码的就是题型。** 代码已对 `op` 和 `real` 两类做过同样诊断并单独定档（注释：「38 条线全部落在较难，难度筛选从来没起过作用」），只差最后一步没走到杀王三类。且筛选结果会被记住，一次误选让下次进入这类时看起来像题库空了。
