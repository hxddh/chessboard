## 已核实的 Bug

### B1 · 原生菜单与 ⌘/Ctrl 加速键从 1.10 起就是死的（高）

**现象：** `app.zon` 声明了完整菜单（对局 / 视图 / 帮助）与键位；README 与 v1.10 / v1.16 发布说明都把它写成已上线功能；JS 侧 `NATIVE_COMMANDS` 也接好了。但菜单栏始终是宿主默认条，⌘N / ⌘Z / ⌘⇧H 等从不触发。

**根因：** `src/main.zig` 从 v0.1.0 起一直写着：

```zig
.menus = &.{},
```

而 `runner.resolvedMenus` 是：

```zig
return self.menus orelse storage.fromManifest();
```

Zig 里 `&.{}` 是**非空、长度 0** 的切片，`orelse` 不会落到 `fromManifest()`。于是 `app.zon` 的 `.menus` 从来没被装进 Runtime。

**为什么守卫没拦住：**

| 检查 | 看到了什么 | 没看到什么 |
|------|------------|------------|
| `test-chess.mjs` | `app.zon` 有菜单项；`app.js` 有对应 handler | `main.zig` 是否把菜单交给 runner |
| `manifest-check.mjs` | runner **能**读菜单键 | 调用点是否传了 `null` 而不是空切片 |

正是本仓库反复出现的病——**声明了、管道通了、运行时被空值短路**——只是短路点从「runner 不读键」挪到了「main 传空切片盖掉清单」。

v1.10 发布说明写的是：「`app.zon` 里的菜单是空的，现在不再是空的」。它只填了清单那一头，**从来没改过 `main.zig`**。所以 ⌘⇧H 那次「修」（1.18 避开系统 ⌘H）也落在一条从未通电的线上。

**修复：** `.menus = null`（或不传该字段）+ 守卫：`app.zon` 有菜单时，`main.zig` 不得传空切片。本 PR 已修。

### B2 · 开局 C24 中文名标错（中）

`openings.js`：

```
["C24", "中心开局·比萨普变例", "e4 e5 Bc4 Nf6 …"]
```

着法是 **Bishop's Opening**（`1.e4 e5 2.Bc4`）。真正的中心对局是同文件里的 `C21`（`e4 e5 d4`）；短主教开局是 `C23`。

英/日译者都悄悄改对了：

| 语言 | 显示名 |
|------|--------|
| zh | 中心开局·比萨普变例 ← 错 |
| en | Bishop's Opening, Berlin Defence |
| ja | ビショップズ・オープニング：ベルリン・ディフェンス |

中文用户看到的名字和棋、和其他语言不一致。守卫只查合法性 / 名字唯一，不查「名字是否描述这串着法」或「三语是否指同一个开局」。

**修复：** 中文键改为 `主教开局·柏林防御`，同步 en/ja 键。本 PR 已修。

## 守卫缺口（今天没爆，但和下一个 bug 同形）

1. **`main.zig` 调用点不在 `manifest-check` 视野里** — B1 的真正缝。清单→runner→页面都查了，独缺「runWithOptions 传了什么」。
2. **日文游离拉丁词 / 假名比例扫描只盖 `lessons-ja`** — `openings-ja` 思路文、`puzzles-ja` 题名不扫。今天扫过一遍是干净的，但是潜伏面。
3. **开局名 ↔ 着法 / 跨语言一致性不验** — B2 的缝；同类还有卡罗-卡恩/卡罗-康、谢文宁根/舍维宁根、维纳韦尔/温纳瓦尔 等拼法分叉（功能无碍，质量噪声）。
4. **`test-openings.mjs` / `test-tactics.mjs` 不进默认打包流水线** — 开局线健全性、战术题唯一性依赖本机 Stockfish；CI 绿不等于这两类性质被守住。

## 产品缺口（按对本受众的重要性）

受众：零基础、觉得国际象棋难上手；离线桌面。  
近几版把「教材厚度」和「外壳正确性」做得很好；下一档价值在**学习闭环的形状**。

### P1 — 该先做的

| # | 缺口 | 为什么对本产品重要 | 侵入性 |
|---|------|-------------------|--------|
| 1 | **看不见自己在变强** | 无 rating、无正确率趋势、成就是一次性里程碑。离线单机没有天梯，自我进步感是几乎唯一的动力 | JS + 存档（可从已有对局/做题记录派生） |
| 2 | **出题仍是线性顺序** | `findIndex(!solved)`；路线图第一条「自适应出题」。SRS 已管错题，不管新题选题 | JS（复用 SRS 掌握度） |
| 3 | **课程学完不回来** | 间隔重复只盖做题；67 课没有课后复查 | content + 轻 JS |
| 4 | **提示只有「全给」** | 连错两次 → 正解箭头；没有「该动哪个子 → 方向 → 整着」台阶 | JS |
| 5 | **开局只练执白** | 一半对局执黑却没有应对库 | content + 少量 JS |
| 6 | **坐标只教不练** | 第 1 课讲完就没有「点出 f5」类反应训练 | JS（小模式） |

### P2 — 定位相关的竞品差距

- 战术题解后缺「为什么成立」的一句话讲解（开局题已有原则级 coach，战术没有）。
- 开局「体系讲解」仍薄（路线图已列「更多开局体系」）——现在是背线 + 原则纠错。
- 每日目标要按本产品哲学重做：SRS 刻意拒绝按日期调度是对的；可以做「本会话做 N 题」而不是 streak 抄袭。

### P3 / 出圈

- README「怎么玩」版本号、残局随机训练器、题目标签展示 — 锦上添花。
- **移动端**：已有 `docs/MOBILE-EVAL.md`，结论「先 spike，别发」仍然成立。
- **在线对弈 / 账号 / 云同步 / 大型开局库**：离线定位下刻意出圈，不是缺口。

## 建议的下一版切法

1. **立刻（本审计已做）**：通电原生菜单 + 守卫；改正 C24；澄清 README 数字。
2. **下一正式版核心**：自适应选题（路线图已写）+ 一个极轻的「进步感」指标（例如近 50 题正确率 / 按母题掌握度条）。这两条咬合，且都能长在现有 SRS/成就上。
3. **内容并行**：开局执黑一套最小应对；部分战术题加一句解后讲解；坐标反应小模式。
4. **工程债**：把「`main.zig` 不得用空切片盖掉清单菜单」升成 `manifest-check` 的正式条；日文扫描扩到 openings/puzzles；评估是否把 openings/tactics 引擎检放进 CI（或至少 nightly）。

## 本审计做过的红测

- 把 `main.zig` 的 `.menus = &.{}"` 留着 → 菜单不通（现状即红）。
- 改为 `null` → `resolvedMenus` 走 `fromManifest`（逻辑上通电）。
- 新守卫：`app.zon` 有 `.command =` 时，`main.zig` 不得出现 `.menus = &.{}`；删掉修复即变红。
- `node scripts/test-chess.mjs` 全绿。
