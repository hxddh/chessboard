# 7.9 · 精致：把每一处量到像素

写在 7.8.0 发布之后、动手之前。规矩照旧：

- 每条写**依据**、**做什么**、**验收**；
- 发布前补**落地记录**，做到的和没做到的都逐条写。

7.7 收拾了棋盘四周，7.8 补齐了动作。7.8.0 之后再看同一组截图，已经找不出「缺一块」的
地方。差距剩在更细的一层：**对齐、尺度、字重、留白、颜色的分寸**。这一层单独看每一处
都很小，放在一起，就是「顺手的工具」和「精致的产品」之间的那点距离。Lichess 和
Chess.com 在这一层上几乎挑不出错。

依据来自三处：

- **固定截图集**：`scripts/shots.mjs` 的 22 个状态，下文写「截图 NN」。这次另拍了一组
  两倍像素的（新增 `DPR=2`，见 §7），细处要放大才看得清。
- **量尺脚本**：在 1440×900、1024×700 下，用中、英、日三种界面加载同一盘意大利开局，
  量了这些：
  - 面板里每个可见按钮的高度；
  - 每段文字的字号；
  - 按钮文字是否折行；
  - 棋谱里回合号与着法的基线；
  - 兵种字形的高度；
  - 棋盘在它那一栏里的位置。
- **现有的度量**：
  - `docs/measured.json` 的标记色度（7.8 立的）；
  - `scripts/test-eco.mjs` 对开局变例名覆盖的统计。

局限照旧：截图用的是无头 Linux 的字体，WebKit 只在 CI 上跑。

## 0 · 结论先行

7.8.0 的画面在「有没有」上已经没有缺口，不够精致的地方集中在六类：

1. **棋盘上方那一排控件没有归属**（§1a）：
   - 「悔棋」「提示」「☰」浮在棋盘右上角外面，既不在对手那一行，也不对齐棋盘边。
   - ☰ 的右边缘比棋盘外框多出 104px。
2. **面板里的控件不成网格**（§1b–1e）：
   - 三组动作按钮定宽、靠左，右半边空着；英文界面里「Live analysis」「Offer draw」
     折成两行。
   - 翻棋谱的四个箭头是裸图标，相隔约 200px，没有按钮的样子。
   - 底部五个图标没有文字。
3. **字太小，数字像代码**（§2）：
   - 面板里所有文字只有 12px 和 13px 两个字号，棋谱也是 13px；Lichess 的棋谱约 15px。
   - 计数（「10 / 10」「已解 0/1408」「done 0/96」）和精准度大字用的是等宽字体，
     一眼看上去像终端输出。
   - 棋谱里的回合号装在一个个小方块里，基线比着法高 3px。
4. **选中的格子比上一步还艳**（§3）：
   - 木纹浅格上，选中标记的色度 C* 是 56.9，上一步是 43.9。7.8 给上一步定的上限是 47，
     Lichess 默认棋盘的上一步是 52.4。
   - 日间主题选中 57.2；纸面主题的提示标记 68，是整个应用里最艳的一块颜色。
5. **空状态和文案各说各的**（§4）：
   - 记录页一页里有三种空状态：实底卡片、虚线卡片、卡片外的裸按钮。
   - 英文文案有病句（「twenty analysed buy a diagnosis」）。
   - 「今天的训练」出现在教学和做题页顶上：正在上第一课，卡片还在说「学一节新课」。
6. **开局名还有一半中文一半英文**（§5）：
   - 本应用自己的数据里一共出现 137 个变例段，7.8 译了最常见的 60 个，覆盖 80% 的出现
     次数。
   - 剩下的 77 个照旧是英文，例如截图 07 的「意大利开局：古典变例，Center Attack」。

这一版**不加功能**，只把现有的每一处做对。

## 1 · 控件的归属与网格

### 1a 棋盘上方的控件归到对手那一行（截图 01、07、11、15、20）

**依据**：

- 1440 宽时，棋盘外框是 x 112–896。「悔棋」「提示」在 y 2–30、x 800–966，☰ 在
  x 972–1000。
- 对手那一行（头像、名字）在 y 36–66。两排之间差了半行，右边缘也不对齐：☰ 比外框多出
  104px。
- 教学模式（截图 05）上方只剩一个孤零零的 ☰。
- Lichess 把这类控件放在棋盘右侧那一栏；Chess.com 放在棋盘下方的工具条里。两家都不会
  让按钮悬在棋盘角上。

**做什么**：

- 「悔棋」「提示」（做题时是「答案」）并进对手那一行的右端。这一行已经有吃子和比分，
  控件排在它们左边。
- ☰ 本来就是开合面板用的，移到面板那一侧的边缘。面板关着时，它贴在窗口右上角。
- 竖窗（600 宽）下同一规则：对手那一行右端。

**验收**：

- 三种宽度（1440、1024、600）下，控件的垂直中线与对手那一行的中线相差 ≤ 1px。
- 最右一个控件的右边缘与棋盘外框右边缘相差 ≤ 1px。
- 新增 `test-layout-e2e` 断言。

### 1b 动作按钮排成等宽网格，任何语言都不折行（截图 07、08）

**依据**：

- 「复盘」「本局」两组，每组三个按钮，定宽 72px，靠左排。右边 400px 的面板里，右半边
  是空的。
- 量尺脚本：英文界面「Live analysis」「Offer draw」折成两行（截图 08）。中文、日文不折。

**做什么**：

- 每组按钮用三列等宽网格铺满面板宽度。
- 文字放不下时，按钮换成两列、下一行再排，不让文字折行。
- 「认输」保持红色描边，其余照旧。

**验收**：

- 中、英、日三种界面，在 1440、1024、600 三种宽度下，面板里任何按钮的文字都只有一行
  （新增断言：用文本的矩形行数判断）。
- 同一组按钮的宽度相差 ≤ 1px。

### 1c 翻棋谱的四个箭头做成一条按钮栏（截图 07、11）

**依据**：

- 「« ‹ › »」是四个 20px 的裸图标，均分面板宽度，彼此相隔约 200px。
- 可点的地方看不出边界；禁用时只是颜色变淡。
- Lichess 的是同一个位置，但做成一整条分成四格的按钮，每格有底色和悬停态。

**做什么**：

- 四格等宽、36px 高、共用一个圆角容器。
- 悬停和按下有底色，禁用的格子去掉悬停，焦点环用全局那一套。

**验收**：

- 四格同宽同高。
- 键盘 Tab 能依次到达，焦点环可见。
- 截图前后对比贴进 PR。

### 1d 底部图标工具条加上文字（截图 07、08、11）

**依据**：

- 「复制 PGN」「下载」「存档」「编辑注释」「更多」五个 20px 图标排成一行，只靠悬停
  说明。
- 第一次用的人认不出其中三个。

**做什么**：

- 面板宽度 ≥ 360px 时，图标下面加一行 11px 的文字。
- 更窄时照旧只显示图标，悬停说明照旧。

**验收**：

- 三种语言下，文字不溢出各自的格子。
- 截图 07、11、19 对比。

### 1e 控件只有两种高度（量尺脚本）

**依据**：

- 面板里可见按钮有 36px 18 个、28px 3 个。28px 的是：
  - 棋盘上方的「悔棋」「提示」；
  - 教学页的「重来」「下一课」；
  - 做题页的「重做」「下一题」。
- 做题页上，上面的题型按钮是 36px，下面紧跟的「重做」「下一题」是 28px，一眼就是两套
  东西。

**做什么**：

- 定两个高度 token：`--ctl-h: 36px`（面板里的一切按钮）、`--ctl-h-sm: 32px`（§1a 并进
  对手那一行的控件、§1c 的按钮栏以外的工具按钮）。
- 其余的 28px 都改成这两个之一。

**验收**：

- 静态检查：`styles.css` 里按钮的高度只能来自这两个 token（与 7.7 的字号、缓动曲线守卫
  同一个做法）。
- 量尺断言：面板里可见按钮的高度只有两种。

## 2 · 文字：大一号，数字用正文字体

### 2a 面板正文与棋谱大一号（量尺脚本）

**依据**：

- 「标准」字号下，面板里所有文字只有 12px（11 处）和 13px（12 处）。
- 棋谱着法 13px。
- 在 1440 宽的屏幕上，这比 Lichess（棋谱约 15px、正文约 14px）和 Chess.com 都小一号。
  面板显得挤、灰，读起来费劲。

**做什么**：

- 「标准」档整体上移一级：正文 13 → 14px，辅助文字 12 → 13px，棋谱 13 → 15px。
- 「小」「大」两档跟着各移一级。
- 7 级字号阶梯不加级，只挪用哪一级。

**验收**：

- 7 级阶梯守卫照旧通过。
- 量尺：「标准」下棋谱着法 15px，正文 14px。
- 截图 07、12、19 在三种宽度下不出现新的横向滚动，面板内容不溢出。

### 2b 数字不用等宽字体（截图 01、06、07、12）

**依据**：

- `--font-num` 是 SF Mono / Menlo / Consolas。这些地方都在用它：
  - 棋谱计数「10 / 10」；
  - 做题的「已解 0/1408」、教学的「done 0/96」；
  - 精准度的「100%」大字；
  - 棋钟。
- 等宽字体的 0 带斜杠或点，字形窄高，和旁边的正文不是一个家族，看起来像终端输出。
- Lichess 的棋钟也不用等宽字体，用正文字体加等宽数字。

**做什么**：

- `.num` 改为正文字体加 `font-variant-numeric: tabular-nums`。数字照样等宽对齐，字形和
  正文一致。
- 棋钟照同样处理，保留加粗。

**验收**：

- 静态检查：`--font-num` 不再出现等宽字体族名。
- 棋钟走字时宽度不跳：新增断言，量 10 秒内棋钟元素的宽度，最大减最小 ≤ 0.5px。

### 2c 棋谱的回合号：去掉方块，与着法同一条基线（2× 截图 07）

**依据**：

- 每个回合号装在一个圆角深色方块里。
- 量尺：回合号文字的下缘在 y 134，着法在 y 137，差 3px。
- 方块和选中着法的高亮块在视觉上是同一种东西，棋谱读起来像一格一格的表格，而不是一行
  一行的棋步。

**做什么**：

- 回合号去掉方块，右对齐，用辅助文字色。
- 回合号与同一行两个着法共用一条基线。
- 当前着法的高亮块照旧。

**验收**：

- 量尺断言：每一行回合号与着法文字下缘相差 ≤ 1px。
- 2× 截图前后对比。

### 2d 对局者一侧的比分不像棋钟（截图 11、12、20）

**依据**：

- 终局后，对局者那一行右端出现一个方框，里面写「0」或「1」。
- 它的尺寸、底色、字体和棋钟一模一样。
- 在人机对局里，看起来像「还剩 1 秒」。

**做什么**：

- 比分改成不带方框的加粗数字。和局时写「½」。
- 胜方的数字用强调色。

**验收**：截图 11、12、20 对比，比分与棋钟在同一局面里可以一眼分开。

## 3 · 颜色的分寸：选中不比上一步艳

**依据**：`docs/measured.json` 的 `markChroma`（浅格上的 C*）：

| 主题 | 上一步 | 选中 | 将军 | 提示 |
|---|---|---|---|---|
| 木 | 43.9 | **56.9** | 47.2 | 26.3 |
| 夜 | 45.2 | 34.7 | 46.5 | 42.6 |
| 日 | 46.5 | **57.2** | **53.7** | 33.2 |
| 纸 | 26.4 | 30.0 | 49.7 | **68.0** |

- 7.8 只给「上一步」定了上限（47，Lichess 参照值 52.4 的九成）。
- 木、日两个主题里，选中的格子比上一步艳得多。截图 07 里 c3 是整盘棋最抢眼的一块。
- 纸面主题的提示标记 68 是全应用最艳的颜色。

**做什么**：

- 四种标记全部定上限，都以同一个参照为准：上一步、选中 ≤ 47，将军、提示 ≤ 52。
- 选中在明度上与上一步拉开，不靠加艳来区分。这是 7.8 `markHue` 的做法：色相差小，
  色差大。
- 调整后重录 `measured.json`。

**验收**：

- `measure-marks.mjs` 对四种标记都断言上限。
- `markHue` 里同一格上两种标记的最小 ΔE00 不低于 7.8 的值：分寸收了，区分度不能丢。

## 4 · 空状态与文案

### 4a 记录页只用一种空状态（截图 03、16、19）

**依据**：同一页里有三种空状态。

- 「这一页记下……」是实底卡片，内含三个带图标的入口。
- 「统计」「棋谱库」「我的开局库」「对局历史」是虚线卡片。
- 「导入 PGN」「按白方导入」「按黑方导入」是卡片外面的裸按钮，左对齐，大小不一。

**做什么**：

- 统一成一种空状态：虚线卡片里放图标、一句话、一个主按钮。按钮在卡片里面。
- 「我的开局库」的两个导入按钮在卡片里并排、等宽。

**验收**：截图 03、16、19 对比；新增断言：记录页的空状态卡片内每张至多一个主按钮，
卡片外没有按钮。

### 4b 教学和做题页不显示「今天的训练」（截图 05、06、21）

**依据**：

- 在教学模式里，第一课正在进行，面板最上面仍是「今天的训练：学一节新课」，把课文往下
  推了 140px。做题页同理。
- 这张卡片是给「不知道做什么」的人看的。已经在做的人不需要它。

**做什么**：卡片只在人机和双人两种模式、且当前没有对局在进行时显示（与 7.8 §1b 的规则
合并）。

**验收**：`test-layout-e2e`：教学、做题模式下卡片隐藏；课文标题的纵坐标比 7.8.0 上移。

### 4c 英文与日文文案过一遍（截图 03、05、19）

**依据**：

- 英文有病句，例如「Import the games you played elsewhere; twenty analysed buy a
  diagnosis.」。
- 有些地方大小写不一致：「Take lesson 1」「Solve a tactics puzzle」是句首大写，
  「the next lesson」「no game played today」却是全小写。

**做什么**：

- 把记录页、教学页、今天的训练、结果卡、设置页的可见文案通读一遍，逐条修。
- 定一条规则写进 i18n 注释：英文按钮与标题用句首大写，说明文字是完整的句子。

**验收**：

- 修改清单写进落地记录，逐条列出原文与改后。
- i18n 键数与 README 计数守卫照旧通过。

### 4d 做题页的纵向节奏（截图 06）

**依据**：

- 「为你出一题」按钮下缘到「题型」标题只有 9px。其余段落之间是 20px 左右。
- 十个题型按钮排成 4 行，是整页最重的一块。

**做什么**：

- 段落之间只用两种间距：同一组内 8px，组与组之间 20px。
- 题型按钮改为和设置页一样的分段控件（每行三格），选中的那一格高亮。

**验收**：量尺断言：做题页各段之间的间距只有 8px 和 20px 两种。

## 5 · 开局变例名译全（`test-eco.mjs`）

**依据**：

- 本应用自己的数据（开局书 195 条线的每一步、十盘经典对局、课程与题库里的局面）一共
  出现 137 个不同的变例段，出现 387 次。
- 7.8 译了最常见的 60 段，覆盖 310 次（80%）。
- 剩下 77 段照旧显示英文，例如截图 07 的「Center Attack」。一个开局名一半中文一半英文，
  比全英文更显得没做完。

**做什么**：

- 137 段全部给出中文、日文名。
- 中文棋界没有通行叫法的，登记在 `NO_ESTABLISHED_NAME` 里。此时整段显示英文，不能出现
  前半中文、后半英文。
- 取名规则照 7.8：沿用开局书已有的写法。

**验收**：

- `test-eco.mjs` 的门槛从「前 60 段」改为「全部出现过的段」。
- 新增断言：任何开局名要么整句是中文（日文），要么整句是英文，不出现半中半英。

## 6 · 这一版不做的

- **新功能**：在线对弈、账号、更多棋子与棋盘纹理，都不在这一版。
- **拖动调整棋盘大小**：理由同 7.8。
- **动效重做**：这次没有找到动效上的具体问题，不为改而改。§1c 的按钮栏只用现有的
  `--dur-quick` 与唯一的缓动曲线。
- **签名、公证与自动更新**：仍然缺证书。

## 7 · 让「精致」可以验收

- **量尺断言进 `test-layout-e2e`**：
  - §1a 的对齐、§1b 的不折行、§1e 的两种高度；
  - §2c 的基线、§4d 的两种间距。
  - 三种语言 × 三种宽度，WebKit 和 Chromium 都跑。
- **2× 截图**：`shots.mjs` 新增 `DPR` 环境变量（已随本计划提交）。CI 的截图任务改为
  拍两倍像素，PR 里放大对比细处。
- **颜色**：`measure-marks.mjs` 对四种标记都断言上限（§3）。

## 8 · 顺序

1. §1 控件的归属与网格，加 §7 的量尺断言：一个 PR。它改动的面最大，其余几条都在它之上
   量。
2. §2 文字与数字。
3. §3 颜色，加 §4 空状态与文案。
4. §5 开局变例名。

每一步两个浏览器引擎的 CI 全绿，PR 里贴 2× 截图的前后对比。
