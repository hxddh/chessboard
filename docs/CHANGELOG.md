## 4.0.0 改了什么

**教练接管:今天的训练 + 看得见的进步。** 工具到 3.0 已经齐了,但「今天该干什么」一直是用户自己的功课,而最老的 P0「进步看不见」始终没动。对局页新增一键日课(planner.js 纯模块):先清复习 → 你的错题 → 弱项两道 → 下一课/背谱 → 来一盘,步骤只在来源有货时存在,完成按计数器差值判定(复习步按答题数计——SRS 一次不毕业,欠账不动≠没练;这条规则是 E2E 抓出、修正后单测钉住的),点一步跳一步,绝无自动跳转。记录页新增「进步」节(progress.js):准确率走势(数据从 1.x 就躺在 stats.games 里,从没被画过)、周对周错误率(ISO 周桶与总账同一落笔点,从 4.0 起记,不伪造历史)、错题收/找回、连续天数。界面键 670 → 690。

## 2.3.0 改了什么

一处能从菜单栏删掉对局的缺陷，一张终于提到菜单快捷键的表，三个交给系统去问的不可逆确认，以及一条抬了八个月没抬的测试固定版本。规则、引擎、题库、课程未动。

起点是一个问题：依赖有没有新版本，有哪些能力还没用起来。**答案里最有价值的一条不是新能力，是查的路上撞见的旧缺陷。**

**一、菜单栏能删掉一盘棋，键盘上的同一个动作不能。** keydown 处理器在碰到任何动作之前先过两道闸 —— 前面有没有对话框、你在哪个模式里 —— 而 `shortcut` 事件直接调进 `NATIVE_COMMANDS`，两道闸一道都没过。量到的：在做题或教学里，⌘N 会在训练界面上弹出「开始新局将清空当前对局」，按下确定，**主对局没了**（字母 N 在那里是「下一题」，从不碰主对局）；⌘F 会翻动课程摆好的方向（F 不会）；快捷键表开着时 ⌘F 照样翻后面的棋盘（每个字母键都停在 `dialogOpen()`）。修法不是加一堆 if：模式本来就写在 `KEY_HELP` 里，给每行标上对应的菜单命令，两扇门从此读同一张表。

**二、那张表叫「快捷键」，却从没提过菜单里的八个快捷键。** `app.zon` 声明了 ⌘N、⌘Z、⌘⇧H、⌘F、⌘\、⌘[、⌘]、⌘/，全应用搜「⌘」是零处。现在每行字母后面多一个虚线框的加速键，`primary` 按这台机器是 ⌘ 还是 Ctrl 来写。表在 `app.js` 里是 `app.zon` 的副本（页面读不到 `app.zon`），所以静态检查双向卡死这两份。

**三、清除全部存档，改由系统来问。** `dialogs.showMessage` 在 SDK 里从 0.4 就有，这个应用从来没调过。只给三个答案收不回来的问题用：清除全部存档、清除统计与历史、重置课程进度。其余确认仍是页内那个框。没有这种对话框的构建照样问得出来 —— `null` 的意思是「这台机器上没有」，不是「用户说不」，这一条单独有断言。

**四、playwright 固定版本 1.49.1 → 1.62.1。** 钉住是对的，但钉住不等于冻住，而它冻了八个月。对 Chromium 无所谓，对 WebKit 不是：macOS 那一半跑用户系统里的 WKWebView，1.49.1 带的 WebKit 落后将近两年 —— 只在真实 WebKit 里出现的回归，这道双引擎门禁看不见。

**没抬的**：`@native-sdk/cli` 0.8.1 → 0.8.4 新增的能力只有录音，而 0.8.4 的 `appkit_host.m` 无条件用了 ScreenCaptureKit / CoreMedia，我们手抄的 `build.zig` 两个都没链 —— 只改 pin 会在 macOS 链接期断掉，和 2.1.9 同一个形状。`esbuild` 0.28.2 装上重跑，产物 sha256 一模一样。

**两条我提错的**：`commands.list()` 只返回 `{id, title, enabled, checked}`，没有键也没有修饰键，而且这个应用没有顶层 `.commands`，它返回空数组；富剪贴板一次只能写一种 flavour、每次 `clearContents`、且只接受三种文本 MIME，没有图片 —— 「复制棋谱的同时挂一张棋盘 PNG」写不出来。都在发布说明里留着。

**测试**：`test-layout-e2e` 新增 4h（两扇门一道闸）与 4i（三个不可逆的问题走系统对话框），`test-chess.mjs` 新增一组静态断言。注入验证五处、五次红、各自点名。

**补记 —— 第一次发布跑失败了，红在 Windows。** 上面那组静态断言里，「两道闸确实写在命令前面」的正则把换行写成了 `\n`：LF 检出读得到，Windows 检出里躺着的是 `\r\n`，读不到。于是 CI 六个作业全绿（都在 ubuntu 上），发布流水线前十步全绿、标签打了、草稿建了、macOS 的 zip 也传上去了，**然后 Windows 构建里的同一套单元测试红了一条**，第 11 步把整条停住 —— 没有发出一个只有一半下载的版本。和 2.0.0 那次同一个形状。修法不只是把 `\n` 改成 `\s*`：这条检查现在跑两遍，一遍读这份检出、一遍读它的 CRLF 副本，只读得懂一种的正则会在手边这台机器上红。整个仓库 126 个文件转成 CRLF 跑过全量静态套件，没有第二处同类问题。

## 2.2.1 改了什么

两处「界面说了、应用没做」，都是先量出来的。规则、引擎、题库、课程未动。

这一轮的起点不是猜：把 `index.html` 里 59 个可交互控件和全部测试文件对了一遍，**23 个从来没有被任何测试点过名**，整个做题模式的界面是其中最大的一块（`test-tactics` 验的是题目立不立得住，不是这个模式的界面）。

**一、做题解出之后，「答案」还画在那里，按下去什么都不做。** `showPuzzleAnswer()` 头一行就写着「已解出就返回」，只是没人停止画那颗按钮 —— 实测按下去画布差 0 像素、不出提示条，`H` 快捷键同样。这正是 P3 有明文的那条：不能用的控件不是变灰，是不画；它旁边的「接实战」从第一天起就是这么做的。量这件事的过程本身值得记：第一次量出来是「画面变了 3384 像素」，那 3384 像素是画布失焦时被擦掉的键盘光标，点「设置」页签能得到一模一样的 3384；第二次按下去才是真正的 0。

**二、复盘的时候棋盘跟着自转。** 自动翻转的说明是「每步走完后棋盘转向走子方」，但翻页函数也无条件调它 —— 每按一次 ‹ 棋盘就整个掉个头。两边交替，所以这是 100% 的步数：复盘 40 回合等于 80 次翻转，外加 80 次写设置文件。改在翻转函数自己里面，13 个调用点一起修好：不在实战位置就不翻；实战期间照翻、● 回到最新照样朝走子方，这两条一起断言了。

**测试**：`test-layout-e2e` 652 → 664 条。新的 3d2 是既有 3d 的另一半 —— 3d 问「可见控件里有没有被禁用的」，3d2 问「画出来的控件按下去有没有做事」，做法是每个控件在各自全新的页面里按一次，看 DOM / 画布 / 本地存储 / 提示条四样有没有动；七个状态量下来只有「答案」一处。注入验证时仪器错了两次（提示条过期只掉一个 class，快照撞上它消失就一定「有变化」，于是每个控件都显得活着 —— 假阴性），第三版改成「提示条连续 2 秒不显示才开始量」才立得住。全量十三套 2163 条断言全绿。

## 2.2 改了什么

界面四刀，规则、引擎、题库、课程未动。每一刀都是先量出来的。

**一、面板只说一种控件语言。** 实测 2.1.9：设置页是有边框的分段控件，对局页是 12px 无边框的文本链接 —— 十六个你真正在用的动作被渲染成小字说明，而一年只去两次的设置页看着像个应用。同屏按钮样式 3 种、字号×字重组合 6 种。现在 `.theme-row button` 和 `.act-btn` 共用同一段声明，22 处 `text-link` 全部改掉，这个类不复存在；三档权重，`.primary` 同屏最多一个，且只在应用自己已经在催的那一刻花在「分析」上。

**二、主题延伸到外壳。** 木色外壳是 `#14100e` / `#241c18`（明度 5% 和 8%），旁边棋盘是 `#f0d9b5` / `#b58863` —— 不是一个木色的界面，是一个黑色的界面里放了一张木头的图片；和夜色的外壳在 442 长的空间里只差 21，换主题换掉的只有格子，日 / 本 那一对同样是 21。面板从来没接错线（它读的就是 `--panel`），值本身才是缺陷。现在木是胡桃木，夜的三通道首尾从 8 拉到 12，日和本只动色相不动明度 —— 后两者的次要文字离 AA 只有十分之一。顺带还债：本的次要文字与「清除全部存档」被推到 4.39 / 4.37，先把墨色调深才让对比度那一节重新全绿。

**三、顶栏真的用起来，棋盘下方那条脊删掉。** 1280×820 面板打开时棋盘 822 宽、面板 284，而上方那条 32px 里是一个状态条、两个按钮和 640px 空白；与此同时两个对手、两个棋钟、吃掉的子四行深地堆在最窄的那一列，面板一关全部消失。vs 条整条搬进顶栏，一行、居中、开关面板都在；脊说的四件事各自有了更准的位置，连带 30px 预留一起没了 —— 面板一关，棋盘直接落到窗口底。三档密度：1100 以下收对手名字，820 以下收吃子和中间格，820 以下面板是盖上来的、盖上来时比赛条不画。面板少了 `.side-head`，最窄那一列还回来 60px。

## 2.1.7 改了什么

两处修复，都在同一个键上：**棋盘一拿到焦点，Esc 就不再是「取消」了。**

**Esc 被棋盘吞掉。** `canvas` 的 keydown 无条件吞下每一个 Escape，只在「有选中的棋子」时才真的做事，于是窗口那条 Esc 链（关对话框 → 关掉不会自己走的 fault 提示条 → 退出编辑器 → 收面板）一层都够不着。而焦点几乎总在棋盘上——点一下棋子就聚焦了。实测 2.1.6：提示条挂着、焦点在棋盘上，连按三次 Esc 毫无反应；把焦点挪开，一次就关掉了。fault 档提示条是全应用唯一「不说走就不走」的那一条，2.1.6 之后它还扛着「重试」：引擎掉线时你最想按的那个 Esc，正好是按不动的那个。同一个错误此前修过两次（1.10 的 FEN 输入框、后来的升变对话框），这是第三处。现在的规则一句话：Escape 只在棋盘真的有东西可取消时才归棋盘。

## 2.1.2 改了什么

四轮复查，十四处。最重的一处不是版式：**导出的复盘图把两位对手的名字对调了**。

**导出的复盘图，两个人的名字调了个。** `renderReviewImage` 里两处写反：装着白方精准度、疑问手、失误、大失误的那一列，标题写的是「黑方」；关键一步也把走出那步棋的人报成了对手。而四百行外的面板里，同一份报告的同一批数字，名字是对的。这是全 app 唯一一件做出来就是要交给别人的东西。根因是「说出一方」和「说出另一方」写全了只差一个字，而全文有八处写全了 —— 六处指本方，两处有意指对手（「白方超时，黑方胜」）。收成 `sideName` / `otherSideName` 各一处。

**编辑局面那一行四个按钮，三种语言都装不下自己的字。** `.tool-btn` 高 32px 不换行、自带 24px 内边距，`flex: 1` 缩不到自己最长的词以下：英文实测那行要 271px 而只有 239px，主操作整个越出面板；中日文靠把标签折进一个没有第二行余地的药丸，文字从按钮里漏出来 ——「开始对局」两行、「キャンセル」三行，最后一个字挂在边框下面。改 2×2，分行处正是语义分界。

**题型段：样式表写着「五项以上退回三列」，代码从没实现。** `auto-fit` 配 64px 下限在 335px 面板里解析成四列，而四列时「Win material」要 79px、格子 78px —— `grid-auto-rows: 1fr` 把它折行后的高度发给全部十个按钮，一个宽了一像素的标签让整个控件高出一半，只在英文下。

**快捷键表在四个模式里显示同一份十三行**，而 keydown 处理器一直是分模式的。做题模式下它给出「Z 悔棋」「F 翻转棋盘」和两行回放 —— 在那里全都没有作用；还把 N 说成「新局」，而做题里 N 是下一题。改成按模式渲染。

**十五个成就是一份清单，行却是五种形状。** 两列不够装「一个名字 + 走到哪儿了」：名字要么折行，要么把计数器挤下去。实测中文 33 与 55，英文 33/54/55/76/90，日文 33/54/55/68/76；十一个带计数的徽章里只有「圆满」把计数器留在同一行，仅因名字够短。改成整幅面板宽的一列，十五行一个高度 —— 正是它上方「统计」已经在用的那一行；最坏的英文列反而变短了（673 → 656px）。

**对局历史对话框两处。** 行「日期 · N 回合 · 精准度 X%」要一行装下，380px 的框只给 262px，而英文里昨天下的那局要 263 —— 相对写法「yesterday 12:55 AM」比更早对局的「7/31/2026」长；一个像素，40 行里 12 行 67px。全 app 只有这一个对话框装的是一列句子，却用着只装一个问题的框的宽度。另一处：两个筛选段并排 `flex: 0 1 auto`，而 flex 的 auto 基准是内容宽度，内容是 `minmax(0, 1fr)` 网格 —— 最小内容宽度是 0，它们从来没长大过。中文下四个结果按钮分 60px、三个执子按钮分 94px，而那行有 418px、空着 264px；26px 一列时「执白」折成三行，执子段 79px 高挨着 35px 高的结果段。

**七个对话框，读屏听到的名字就是屏幕上那个标题。** 每个都把标题存了两份（`aria-label` 加可见的 `<h3>`，来自不同的键），两对已经走岔；确认框更甚 —— 标题每次现写，`aria-label` 却是固定的「确认」：点「清除全部存档」，屏幕上写着「清除存档」，读屏念的是「确认」。

**两处「为什么不行」读屏一个字都听不到**：编辑器的非法局面原因（也是「开始对局」变灰的原因）、FEN 对话框的拒绝理由，都写进普通 `<p>`；FEN 输入框只变红，从未标记 `aria-invalid`。

**另外几处**：导出成功但说不清文件去了哪（`saveFile` 对「没有对话框 API」和「用户取消了」返回同一个 `null`，于是没有桥接时报的是「已取消导出」）；故障提示没有关闭键，只能等；统计行在英文下 42px 对其余 23px；回放条的键会因为被按而缩小跳走；四个内联 `margin-top`（14 和 10，两个刻度上都没有的值）—— 内联样式是全部 token 守卫唯一看不见的地方，现在有守卫禁止它。

## 2.1.1 改了什么

**设置页的顺序就是它的说法。** 三个不可撤销的删除、全页唯一的红色，此前夹在你每天都会调的两组之间 —— 挪到最后。「外观」改名「界面」（它装着语言和音效，两项都不是外观），组内从最看得见排到最看不见：主题 → 棋盘方向 → 语言 → 音效。「棋盘方向」从一个写着「翻转」的按钮改成**白方视角 / 黑方视角**两段：这一页每一行都显示它现在是什么，只有它显示按下去会怎样。

**另外三处**：「三项都不可撤销」在空档案下只有两项（文案改成不点数）；13 个分组标题有 3 个是 `<span class="side-h">`，按标题导航看不见；「翻转」三个入口各带一份实现，而 `NATIVE_COMMANDS` 上的注释正写着「只有一份实现，两者绝不会走岔」—— 已经走岔了（按钮 toast，键和菜单默默改），收成 `setFlipped` 一处。

## 2.1 改了什么

只改了一个东西：棋盘正上方那条 44px 的横栏。它不是没对齐 —— 是**里面没有任何两件东西共享一个单位**，所以对不齐：模式行（一次会话切 0–2 次）、状态药丸（每一步都变）、四个动作加 ☰（随时点），三种更新频率、三套视觉语汇、三种高度（36 / 27.4 / 32）、两条基线，并排在 44px 里。

而这 44px 是**从棋盘的边长里扣的** —— 棋盘是正方形、在这个 app 跑得到的每一种窗口里都是高度受限的，上下各只剩 6px 留白。实测把 `--chrome-h` 调到 0：棋盘边长 1400×900 下 +5.2%、640×560 下 **+8.7%**，换成面积是 **+10.7% 到 +18.2%**。而这条栏上 **66% 是空的**。

现在顶栏 = 一句话 + 这一步棋要用的两个动作 + ☰，**32px 高、一种控件高度（28px）、一条基线、左右各 8px**。模式进设置页第一节（和难度/风格/主题同一种段控件），翻转进设置页·界面，新局进对局页·本局（它此前是全 app 唯一一个渐变实心按钮 —— 这个 UI 里「该按的就是这个」的说法，花在了对弈中最不该按的那一个上）。五个动作本来就都有快捷键（H Z F N P），搬走的丢的是重复的按钮不是唯一的路；☰ 留下，面板关着时它是唯一的指针入口。

一并删掉 `.mode-nav` —— 只为一行存在的第二套段控件语汇。它带的 `margin-top: 12px` 是面板时代的，在顶栏里把整组压到中线下 6px、越出栏底 2.5px，组边框和选中下划线在**栏外面**叠成一条 3px 双色横杠；样式表里没有一条规则能发现，因为它每一条声明都只有它自己在用。
