## 新发现

### D1 · README 仍把菜单「死掉的区间」写错（文档诚信，中）

关窗那一行有完整更正：「1.18/1.19 写了但没生效 … 1.19.1 起才真」。

菜单那一行（README「怎么玩」快捷键速查）却写成：

> 提示是 ⌘⇧H 而不是 ⌘H … **1.10–1.17 这一项一直是死的**

这等于告诉读者：1.18 改键之后就好了。  
事实（见 v1.21.1 发布说明）：**整条原生菜单 + 全部 ⌘/Ctrl 从 1.10 到 1.21.0 全哑**；1.18 的 ⌘⇧H「修」落在从未通电的线上；**从 1.21.1 起才为真**。

正确区间是 **1.10–1.21.0**，且应像 close_policy 那样写明「写了但没生效」。数字/标题守卫钉不住这段散文。

### D2 · 菜单通电之后：原生菜单文案锁死中文（产品/i18n，中）

`app.zon` 里菜单 title/label 全是中文硬编码（「对局」「新局」「引擎提示」…）。界面本身三语齐备，首次启动还会跟系统语言。

菜单死着的时候谁也看不见；**1.21.1 通电之后**，英文/日文用户会看到：网页 UI 是母语，**菜单栏全是中文**。  
README「英文模式下各视图可见中文串数为 0」只量了 Web 视图，不覆盖原生菜单栏。

静态清单做不到跟 `langId` 热切换——这是架构债，不是笔误；但发布说明与 README 都没承认这个新露出来的面。

### D3 · 原生菜单动作与页内字母键在教学/做题下分叉（低，待真机确认观感）

页内 `h`/`z`/`n` 在 learn/puzzle 模式走 `learnHint` / `learnUndo` / `nextPuzzle` 等。  
`NATIVE_COMMANDS` 一律打到主对局（`requestHint` / `undo` / `requestNewGame`）。

菜单刚通电，两条路第一次会同时存在；教学/做题时按 ⌘Z/⌘⇧H/⌘N 可能动到背后那盘惰性主棋。严重度低，但是「通电后才需要验」的一类。

### D4 · 菜单仍无真机/端到端实证（残留风险，中）

构建绿 ≠ 菜单栏出现且加速键命中。仓库没有按原生菜单的 e2e。  
在某条流水线或本机实包上确认 ⌘N/⌘Z/⌘⇧H 之前，不宜再写成「已证实上线」。

## 建议切法（仍不改代码，只排序）

1. **文档与实证**：README 菜单行按 close_policy 同级更正；真机或流水线实按一次菜单/加速键；承认菜单文案暂锁中文（或列进后续）。
2. **下一正式版产品核**：极轻「进步感」指标（近 N 题正确率 / 母题掌握条）+ 自适应选题；两者共用同一套掌握度信号。
3. **便宜高价值**：`recommendation()` 接上 `review.js` 的弱项；提示加一级「先高亮起子」。
4. **内容并行**：开局最小执黑应对；日文抽检母语校对。
