# 真机走查清单

自动化能覆盖的，都已经在 `checks.yml` 和发布门禁里跑了：规则、纯函数、源码守卫、六个浏览器 E2E（Chromium 与 WebKit 两个引擎，含侧栏版式量测与 2.0 新增的「任一时刻可见禁用控件数为 0」「题型 × 难度每个组合非空」）、Stockfish 的开局与战术检查、`zig build test`。

**这份清单是剩下的那一半 —— 没有任何自动化碰得到的部分。**

为什么值得照着念一遍：这一层历史上出过的问题，没有一个是小问题。

| 版本 | 问题 | 潜伏了多久 |
|---|---|---|
| 1.10–1.21.0 | 原生菜单栏其实是画上去的，⌘N / ⌘Z 一次都没触发过 | 十一个版本 |
| 1.18–1.19.0 | macOS 关窗直接退出（`close_policy` 声明了没人读） | 两个版本 |
| ≤1.21.1 | 大于 256 KiB 的 PGN 被静默截断成前 256 KiB | 未知 |
| ≤1.21.1 | Windows 路径的每个 `\` 都被送成 `\\` | 未知 |

它们都不会让任何测试变红，因为测试根本够不到那一层。

**怎么用**：照顺序做，每条对照「应该看到」。任何一条对不上就停下来记录 —— 写清楚你做了什么、看到了什么、期望是什么。不必自己判断严重程度。

标注说明：**[M]** 仅 macOS · **[W]** 仅 Windows · 无标注 = 两个平台都要做。

## 8.2 真机路线（30 分钟）—— v8-2-plan V1 第 3 步、§8 第 8 条

8.2 起，下面「8.1 真机清单」R1–R19 里凡是「打包后能不能用」的条目，改由 CI 驱动打包后的应用来走：`build-macos.yml` / `build-windows.yml` 的 **automation** 作业（同一提交、同一清单、同一打包命令的第二份构建，打开 SDK 的 automation server，**这份构建从不发布**），经 `scripts/automation-scenarios.mjs` 跑页面里的场景（`src/web/js/selftest-scenarios.js`），同步对着 runner 上的假服务器（`scripts/fake-sync-server.mjs`）。每条现在标了「CI 已覆盖（作业名）」或「只能人看」。

**CI 那一半的现状要照实说**：这两个作业写好时还没有在 macOS / Windows runner 上跑过（开发环境只有 Linux）。本机验证过的是 null 平台上的 automation 构建（测试缝）、同一批场景在 Chromium 里的页面一半（`scripts/test-selftest-e2e.mjs`）和 Zig 测试；Windows 的 WebView2 + automation 没有先例，那个作业暂时不挡发布。第一次运行的结果记在 v8-2-plan §9 M4。

**剩下只能人看的，就是这一条路线**：图标、原生对话框本身（含中文路径）、动画手感、Windows 顶部拖动区实验、用真账号连真站同步，外加 8.2 照上游改的两处原生行为（窗口位置、Windows 高缩放下的清晰度；v8-2-plan §9 M4 · `docs/sdk-fork-notes.md` R15 / B09）。两个平台各约 17 分钟。按顺序走，每步对照「应该看到」，结果记在每步后面（格式同「记录格式」）；对不上就照实记下，不用判断严重程度。**没人走过的步骤不挡发布，照实写进发布说明**（§8 第 8 条）。

**准备（两个平台都要）**：8.2.0 的 Release 产物；一个有对局的 Lichess 账号和一个 Chess.com 账号（公开的就行）；一个文件名带中文、几局以上的 .pgn（如 `王者对局.pgn`）。

### macOS（约 17 分钟）

1. **图标（R1、R2，2 分钟）**：从 dmg 装好、打开。看 Dock（默认大小）、启动台、Finder 图标视图与列表视图（16 px）；应用开着时再看一眼 Dock。
   - 应该看到：琥珀色圆角方块里一匹深色的马，两只耳朵、有眼睛，和邻居一样大；运行时不会换成旧图标或 SDK 默认的。
   - 截图：Dock 一张、Finder 列表视图一张（放大到能看清 16 px）。
2. **打开 PGN（R12，3 分钟）**：「更多」→「打开」，选 `王者对局.pgn`；再打开一次，按「取消」。
   - 应该看到：系统「打开」面板，标题「打开 PGN」；选中后棋谱装进来，选局窗口列出全部对局；取消时局面不动、没有提示；Dock 图标右键 →「最近使用」里有这个文件。
3. **导出 PGN（R13，3 分钟）**：走两步，「导出 PGN」，存到 `~/我的 棋谱/`（先建好这个带空格的中文目录）；再导出一次，按「取消」。
   - 应该看到：系统「存储」面板，文件名预填 `chess-日期时间.pgn`；存下后 Finder 打开并选中这个文件，提示「已导出 …」；取消时提示「已取消导出」，不生成文件。
4. **动画手感（R19，5 分钟）**：60 Hz 显示器，QuickTime「新建屏幕录制」录下：拖一个棋子走一步、引擎应着的滑动、将军的脉冲、打开新对局对话框、切换导航栏的两页。用 QuickTime 按 ← → 逐帧看。再在系统设置里打开「减少动态效果」，录一次走子。
   - 应该看到：滑动每一帧都在前进，没有连续两帧以上停在同一位置；对话框和切页没有一帧空白或跳位；减少动态效果时滑动与脉冲都不出现，着法照常完成。
   - 记下：最长停顿几帧。
5. **真账号同步（R6、R7 的真站那一半，3 分钟）**：棋谱库 →「从网站同步」，打开「允许联网同步」，填你的 Lichess 名字，「最多取」选 100，同步；「已取到 k 局」还在数时拖一下窗口、在棋盘上走一步。完了换 Chess.com 的名字再同步一次。
   - 应该看到：k 往上数；窗口跟手，棋子立刻落下；棋谱库多出这些对局；Chess.com 只进标准国际象棋。
   - 记下：从点「同步」到进库几秒；有没有哪一下停住。
6. **窗口位置记得住（X1，R15 · 8.2 修正，2 分钟）**：把窗口拖到屏幕右下角附近、拉成和默认不同的大小，⌘Q 退出再打开；有第二块显示器的话，再拖到第二块上退出、打开一次。
   - 应该看到：两次都回到退出前的位置和大小，不居中、不跳回主屏、不每次长高一个标题栏。全新安装（删掉存档目录）第一次打开仍然居中（L4）。
   - 为什么要人看：Zig 测试只证明交给主机的是 `.restored`，屏幕上落在哪只有真机看得到。

### Windows（约 17 分钟）

1. **图标（R3，2 分钟）**：解压后在资源管理器里**双击** `Chessboard\bin\chessboard.exe`（8.2.1 修的就是这一步：8.2.0 这样启动时页面读不到）。先看窗口里棋盘和侧栏都出来了，再看图标。看任务栏、Alt+Tab、资源管理器「小图标」（16 px）和「中等图标」（32 / 48 px）、开始菜单；另看 `chessboard.exe` 本身在资源管理器里是不是这个图标。
   - 应该看到：同一个图标；16 px 是按像素画的那张（两耳之间一个像素的缝，眼睛一个亮点）。
   - 截图：任务栏一张、小图标一张。
2. **打开 PGN（R14，2 分钟）**：R12 在 Windows 上做一次（含「取消」）。
   - 应该看到：系统打开对话框；选中后装进来；任务栏跳转列表里有这个文件（没有就记下：Windows 的最近文档要先运行一次 `register-pgn.cmd`）。
3. **导出 PGN（R15，3 分钟）**：存到 `C:\Users\<你>\Desktop\`；再导出一次，把文件名的 `.pgn` 删掉再存。
   - 应该看到：另存为对话框，文件名预填、类型为 pgn；存下后资源管理器打开并选中它；删掉扩展名时存成 `.pgn`。
4. **真账号同步（R10，以及 R6 在 Windows 上，3 分钟）**：同 macOS 第 5 步，Lichess 和 Chess.com 各一次。
   - 应该看到：同上。HTTPS 走 Zig 标准库的客户端、证书来自系统证书库，这一步是 R10 唯一的证明。
5. **动画手感（R19，3 分钟）**：同 macOS 第 4 步，用 Xbox Game Bar 录屏（设置里把帧率调到 60），录走子和切页两段就够。
6. **缩放 150% 时不发虚（X2，B09 · 8.2 修正，2 分钟）**：设置 → 屏幕 → 缩放改成 150%（不用注销），打开应用；任务管理器 →「详细信息」→ 右键表头「选择列」勾上「DPI 感知」，看 `chessboard.exe` 那一行。有两块缩放不同的显示器的话，把窗口从一块拖到另一块。
   - 应该看到：文字、棋子、棋盘边缘和 100% 时一样锐利（8.1 在 150% 下是糊的）；「DPI 感知」一列是「每个显示器(v2)」/ Per-Monitor (v2)；跨显示器拖过去后不糊、内容按新缩放重排，不留一半大一半小。
   - 为什么要人看：交叉编译只证明 exe 里嵌了清单；PerMonitorV2 下 WebView2 主机自己处理 DPI 变化，这条路这个应用以前没走过。
7. **顶部拖动区实验（R4w，2 分钟，可选）**：需要一份只改了 Windows 清单、原生侧给 `main` 视图设了顶部拖动区的实验构建（开发侧提供；没有就跳过，记「未做」）。按住窗口内顶部那条拖。
   - 记下：能不能拖动窗口；那条上的页面按钮还点不点得到。做不做都不影响 8.2.0。

8. **解压到不可写的目录（2 分钟，可选，v8-3-plan V2）**：把 `Chessboard` 文件夹放进 `C:\Program Files\` 再双击 `bin\chessboard.exe`。
  - 应该看到：页面照常出来。8.4 起（v8-4-plan V1）exe 旁边写不进去时，WebView2 的用户数据改放 `%LOCALAPPDATA%\Chessboard\WebView2`：走完这一步，那个文件夹里应该有东西，`bin\` 旁边没有 `chessboard.exe.WebView2`。
  - 如果窗口空白或报错，或者数据还是想往 `bin\` 旁边写，记下来。放在可写目录里的副本不受影响，数据照旧在 exe 旁边。

## P. 8.0 B2：「妙着」「仅此一着」人工核对

复盘在 v8-0-plan B2 里加了着法分级（`src/web/js/review-grade.js`，每一档的定义和门槛都写在那个文件的注释里）。其中「妙着」和「仅此一着」没有任何自动化能判断对不对 —— 引擎只能说「这步最好、别的都差很多」，这算不算一个人会叫好的着法，要人来看。

两档的规则，简述（胜率都从走子方看，review.js `winPct`）：

- **仅此一着**：走的是引擎首选；更深一遍的 MultiPV 3 搜索确认，次佳比它差 ≥ 10 个百分点，并且这一差跨过了结果线（首选 ≥ 70 而次佳 < 70，或首选 ≥ 30 而次佳 < 30）；只有一步合法着法、或在对方刚吃子的格子上吃回的，不算。
- **妙着**：同样是引擎首选、加深确认、次佳差 ≥ 10、不是吃回或唯一合法着；并且沿引擎给的应着线，走子方在对方应着后、以及再下一个应着后，都少了 ≥ 2 个兵的子力（至少一个轻子换一个兵）；走后胜率 ≥ 50。不要求跨结果线（莫菲 16.Qb8+ 是两步杀，次佳只是「仍然 +3.6」）。

**怎么核对**：把 FEN 摆上（本应用「局面编辑」或任意棋盘），看「着法」一栏那一步和右边的引擎线，在最后一栏勾「同意 / 不同意」判定。不同意的，在「记录格式」下写一行原因。「妙着」表的后半是**引擎首选、确实弃了子、但没有判成妙着**的着法，用来查漏判：如果你觉得其中哪一步该是妙着，勾「不同意」。

**数据来源**：28 局测量语料（`scripts/fixtures/corpus.mjs`）加上读棋课里另外的名局（`classics.js`），按「分析」（预算 200，定节点）跑一遍 B2 流程。胜率三列依次是：走之前的局面（即引擎首选）、次佳线、走之后。1300 多手里判出的妙着只有 2 处 —— 规则是刻意严的，漏判比错判好查。
